## Что изменилось (по заявке)

1. **Буква «Я» в дне недели** (ПЯТНИЦА): добавлена левая диагональная
   ножка (глиф стал зеркальным отражением латинской «R»). Раньше «Я»
   рисовалась чашей без ножки.
2. **День недели и дата смещены правее, погода больше не примыкает к
   дате**: слово дня недели сидит ближе к дате (зона сдвинута на 8
   колонок; ПОНЕДЕЛЬНИК — длинное слово — остался на месте, чтобы не
   наезжать на дату), а блок погоды теперь прижимается к ПРАВОМУ краю
   ЕДИНЫМ ЦЕЛЫМ (иконка + температура вплотную): при короткой
   температуре («-1°», «+5°») зазор между датой и иконкой вырос
   с 2 до 7 колонок; при длинной «-12°» компоновка прежняя (зимой
   ничего не ухудшилось).
3. **Календарь — «выравни по высоте все кнопки года и месяца»**:
   селекты года/месяца теперь той же высоты, что стрелки и «Сегодня»
   (ровно 30px, разброс 0.0px — проверено замером DOM в обеих темах).
4. **Светлая тема — «стрелки и „Сегодня“ поярче»**: тёмный
   контрастный текст (#141413 на белой подложке) вместо бледного
   светло-голубого, который почти исчезал на светлом фоне.
5. **Сервер `authorizeWeather()`** (по вашему логу «FAIL … Требуемые
   разрешения: https://w»): сообщение больше НЕ обрезается — виден
   полный URL области; при ошибке разрешения к результату
   добавляется готовое «лекарство» (см. ниже).

## ЧТО НУЖНО СДЕЛАТЬ ВАМ

### Клиент (обязательная часть — 10 секунд)

Ничего не нужно: новое SW `kipia-test-v748` подхватится само при
следующем открытии приложения. Если хотите увидеть изменения сразу —
**Ctrl+Shift+R** (жёсткое обновление) на странице Табеля.

### Сервер (НЕобязательно — только если хотите задействовать серверный резерв погоды)

Погода у вас УЖЕ работает напрямую из браузера (wttr.in), поэтому
серверный резерв можно не чинить. Если хотите, чтобы и он работал:

1. Обновите `WorkSchedule.gs` в проекте Apps Script (скопировать из
   этого репозитория — файл `scripts/WorkSchedule.gs`).
2. **Почему у вас authorizeWeather выдал FAIL**: судя по логу, диалог
   авторизации НЕ появился, а ошибка сохранилась — значит, в манифесте
   `appsscript.json` проекта ЯВНО перечислены `oauthScopes` БЕЗ области
   `script.external_request` (при явном списке Google не запрашивает
   недостающие области — сразу отказ в `UrlFetchApp.fetch`).
   Лечение (один раз):
   - Настройки проекта (⚙ Settings) → галка **«Show "appsscript.json"
     manifest file in editor»**;
   - открыть `appsscript.json`, в массив `"oauthScopes"` добавить
     строку `"https://www.googleapis.com/auth/script.external_request"`
     (или удалить массив `oauthScopes` целиком — тогда области
     определятся автоматически);
   - Сохранить → снова выбрать `authorizeWeather` → **Выполнить** →
     подтвердить доступ → Deploy → Manage deployments → ✏ →
     Version: **New version** → Deploy.
3. Проверка: Табель → шестерёнка → «Обновить сейчас» — статус должен
   показать источник (резерв — «meteoinfo.ru (через Apps Script)»;
   при живом прямом канале wttr.in он остаётся основным).

Новая `authorizeWeather()` сама подскажет это лекарство в журнале
выполнения: сообщение об ошибке печатается ПОЛНОСТЬЮ (была обрезка
на 90 символах — вы видели лишь «https://w»), а к строке FAIL
добавляется «ЛЕЧЕНИЕ: область … + oauthScopes манифеста …».
