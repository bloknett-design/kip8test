# Task 407 — блок «Повторные инструктажи…» по шаблону «Список_И_и_ПЗ»

**Заявка**: «Необходимо переделать блок Повторные инструктажи и
периодическая проверка знаний, информация в этом блоке будет
формироваться из двух таблиц в файле табель_КИП_ИОС. Первая таблица,
новая, "Список_И_и_ПЗ" содержит шаблонный список инструктажей и
проверки знаний, вторая таблица "Инструктажи" заполняется
пользователем, и по столбцу "название" берёт нужную информацию из
первой таблицы».

**Репозиторий**: kip8test (тестовый сайт)
<https://bloknett-design.github.io/kip8test/>

**Версия SW**: kipia-test-v633 → **v634**
**Тесты**: 3896 passed / 0 failed (было 3857/0; +39 в
test-task407.js; guard-бамп 93 файла)
**Браузер-чек**: 37/37 ×3 контекста (тёмная view / светлая edit /
мобайл 375), 0 JS-ошибок; VLM ×3 (glm-5v-turbo) — подтверждено
визуально (карточка с группами, попап, мобильный блок).

## Что изменилось

### Сервер (WorkSchedule.gs)

- **Новый лист «Список_И_и_ПЗ»** (константа `INSTR_LIST_SHEET`) —
  шаблонный список инструктажей и проверок знаний. Столбцы — ПО
  ЗАГОЛОВКАМ строки 1 (позиция любая, приём Task 402/403):
  `название` (ключ соответствия: текст = «тема» записи таблицы
  «Инструктажи»; сравнение нормализованное — регистр/лишние
  пробелы/«ё» не важны, считает клиент), `вид`
  (инструктаж/проверка_знаний — толерантно), `периодичность`
  (число месяцев; пусто/0 = разовый — «следующий срок» не
  считается), `основание` (приказ/правила — справочно).
- **`listTrainings`** — ответ дополнен двумя полями:
  `instrList` (шаблон «Список_И_и_ПЗ»; листа нет — пустой массив,
  блок живёт прежним плоским списком) и `instrAll` (ВСЕ записи
  «Инструктажей» БЕЗ фильтра года — «последний» инструктаж ищется
  по всем годам: контроль годовых/трёхлетних циклов; `trainings`
  остаётся годовым срезом — бейджи/окно месяца/печать/сводная не
  меняются).
- **`_readInstrListSheet`** — чтение листа по заголовкам
  (`_headerColIndex`); нет листа/ключевого столбца «название» —
  пустой список (не ошибка).
- **`instrListInit` + топ-левел функция** — РАЗОВОЕ создание листа
  с заголовками и типовым наполнением (4 пункта; идемпотентно —
  существующий лист не трогает).

### Карточка работника — блок «Повторные инструктажи…»

- **`_renderInstrSection`** (новый) — тело блока по шаблону:
  - **группа на каждый пункт шаблона** (порядок = порядок строк
    листа): шапка `.ws-il-head` (свотч + код И|ПЗ по «виду» пункта +
    название + «раз в N месяцев»), строки-записи ГОДА `.ws-il-row`
    (код записи — ФАКТ записи + дата + ✎/✕ редакторам),
    строка следующего срока от ПОСЛЕДНЕЙ записи любого года:
    `след. срок: … ✓` (актуально) / `⚠ просрочено с …`
    (периодичность 0 = разовый — срок не считается);
  - карточка (страница «Работники») дополнительно показывает
    `— не проводился` (записей нет ни в одном году) и `— в этом
    году не проводился` (последняя запись — прошлый год);
    попап шахматки — компактный: без этих строк, пункты без
    записей вообще скрыты;
  - записи года, чьих названий нет в шаблоне — секция
    **«вне списка»** (плоские строки, как прежде; опечатки видны);
  - дубли названий шаблона — первый пункт; вид записи ≠ вид пункта
    — показываем факт записи, периодичность из шаблона.
- **Деградация** (лист не создан / сервер старый / кэш прежней
  версии): `_INSTR_LIST` пуст → прежний ПЛОСКИЙ список записей
  года (Task 405/406) — обратная совместимость.
- **CSS**: `.ws-il-head/.ws-il-name/.ws-il-per/.ws-il-row/
  .ws-il-due(-ok/-bad)/.ws-il-off` + светлые темы + размеры окна
  `.ws-wcard` (14px, компактные строки-«пилюли» групп).

### Форма «Новое мероприятие» — подсказки «Темы»

- Поле «Тема» получило **datalist** `#wsTrTitleList`: при типе
  инструктаж/проверка знаний предлагаются названия из шаблона
  соответствующего «вида» (инструктаж → «инструктаж», проверка
  знаний → «проверка_знаний»); прочие типы — без подсказок.
  Пересбор при открытии шторки и смене типа (`onchange`);
  **свободный ввод остаётся** (внеплановые темы).

### Кэш (Task 314)

  как СИЗ) и восстанавливаются с guard'ами — кэш прежней версии

## Серверные шаги (⚠ выполняет пользователь ПОСЛЕ merge)

1. Обновить `WorkSchedule.gs` в проекте Apps Script таблицы
   табель_КИП_ИОС (файл из этого репозитория).
2. В редакторе Apps Script выбрать функцию **`instrListInit`** →
   ▶ Run — будет создан лист «Список_И_и_ПЗ» с заголовками и
   типовым списком из 4 пунктов.
3. **Отредактировать лист под свою номенклатуру**: строки можно
   добавлять/удалять прямо в листе; «название» должно совпадать с
   «темой» записей таблицы «Инструктажи» (регистр/пробелы/«ё» не
   важны); «вид» — `инструктаж` или `проверка_знаний`;
   «периодичность» — число месяцев (пусто = разовый); «основание»
   — справочно (приказ/правила).

До шагов 1–3 приложение работает как раньше: блок показывает
плоский список записей года (данные «Инструктажей» уже читаются).
