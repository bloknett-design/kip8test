# DEPLOY — Task 538: клиентская синхронизация избранного/примечаний телефонного справочника

**Заявка:** «готов, сделай клиентскую интеграцию — синхронизацию
избранного/примечаний из localStorage в архив (данные будут
переноситься между устройствами по email)».

**Что сделано (КЛИЕНТ — index.html + sw.js, сервер НЕ менялся):**
модуль **PbSync** — двусторонняя синхронизация избранного и
примечаний раздела «Телефонный справочник» с серверным архивом
(Task 537: PhonebookArchive.gs, Google Таблица «Телефонный
справочник — Архив пользователей», данные привязаны к email).

- **3-way merge по base-снимку** (`*_phonebook_sync_base`):
  последнее согласованное с сервером состояние — база слияния.
  Добавление на любой стороне подхватывается; удаление на стороне
  выигрывает у «бездействия» другой; конфликт правок примечания на
  двух устройствах — остаётся локальный вариант (тост + счётчик).
- **Очередь исходящих** (`*_phonebook_sync_queue`): коалесценция по
  (тип+контакт) — поздняя правка затирает раннюю, дублей на сервер
  не уходит; переживает офлайн/перезагрузку; ретраи по событию
  `online`, следующей правке и открытию раздела; дебаунс 1.5 с.
- **Бейдж статуса в тулбаре** (`pbSyncBadge`): «Синхронизировано» /
  «Ожидает: N» / «Синхронизация…» / «Локально» / «Нет связи»;
  тап — детали (email, время последней синхронизации, очередь).
- **Деградация на localStorage**: нет входа / нет сети / старый
  Apps Script (без PhonebookArchive.gs — «Unknown action») /
  истёкшая сессия — приложение работает как раньше, правки копятся
  в очереди и уходят при появлении связи. Серверные id, которых
  нет в текущем phonebook.json, не поднимаются — в архив уходит
  мягкое удаление (снимки в контакт_json сохраняются).
- Устаревшие записи, успевшие синхронизироваться, удаляются и на
  сервере (pbSyncDropStale из pbCleanupStaleFavorites) — иначе pull
  снова поднял бы их из архива.
- SW: `kipia-test-v749 → kipia-test-v750` (в kip8 — `v546 → v547`).

## КЛИЕНТ (GitHub Pages) — делать НЕЧего

PWA обновится само через Service Worker (v750/v547): при следующем
открытии — фоново, для мгновенного — **Ctrl+Shift+R**. Права/вход —
как раньше: раздел «Телефонный справочник» для ролей с секретными
кнопками (КИП8 и выше); синхронизируются данные вошедшего email.

## СЕРВЕР (Apps Script) — опционально, если Task 537 ещё не развёрнут

Синхронизация работает только при задеплоенном архиве. Если бейдж
показывает «Локально» с пояснением «Сервер не поддерживает архив
справочника» — выполните DEPLOY-Task537-phonebook-archive-storage.md
(≈5 минут: + PhonebookArchive.gs → заменить Code.gs →
phonebookArchiveInit ▶ Run → Deploy → New version). Ничего
дополнительно для Task 538 на сервере делать НЕ нужно: клиент сам
начнёт синхронизироваться при следующем открытии раздела.

## Проверка после деплоя

1. Открыть «Телефонный справочник» — в тулбаре рядом с «Только
   избранные» появляется бейдж: «Синхронизировано» (зелёный).
2. Тап по бейджу — тост «Справочник — аккаунт: <email> ·
   синхронизировано в ЧЧ:ММ:СС · очередь: 0».
3. Поставить звезду/добавить примечание → открыть справочник на
   другом устройстве (тот же email) → данные на месте.
4. Погасить сеть → правки вносятся как обычно, бейдж «Ожидает: N»
   → сеть вернулась → очередь уезжает сама, бейдж снова зелёный.

## Откат
