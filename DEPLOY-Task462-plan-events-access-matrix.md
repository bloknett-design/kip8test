# DEPLOY — Task 462: доступ к «Плановым мероприятиям» — отдельное право plan.events в матрице KIP8_Access

**Дата:** 02.10.2026. **Что менялось:** клиент (index.html — уже в репозитории,
деплой GitHub Pages автоматически) + матрица KIP8_Access (по этой инструкции).
**Серверный код Apps Script НЕ меняется** — RoleMatrix.gs читает колонки
матрицы динамично, RoleMatrixGate.gs отдаёт все права как есть.

## Суть

Раздел «Плановые мероприятия» (создан Task 460 в «Документации ИОС») до сих
пор не имел своего права: страница следовала за хабом «Документация ИОС»
(права `kipios.view` / `kipios.restricted` / `flowmeter.view`). Task 462
выделяет разделу ОТДЕЛЬНЫЙ столбец матрицы:

| Право | Что даёт |
|-------|----------|
| `plan.events` | Видимость раздела «Плановые мероприятия»: кнопка на хабе «Документация ИОС», пункт в сайдбаре, страница |

Галочка снимлена → раздел полностью скрыт у роли (кнопка, сайдбар, прямой
переход — экран «Нет доступа»); хаб «Документация ИОС» и расходомеры при
этом НЕ трогаются. Право самодостаточно: роль без КИП ИОС и расходомеров,
но с `plan.events`, раздел видит.

**Переходный период (важно):** клиент kipia-test-v686 различает «колонки
plan.events в матрице ещё нет» (скрипт ниже не запущен — работает прежнее
поведение Task 460: раздел следует за хабом) и «колонка есть, галка снята»
(раздел скрыт). Благодаря этому деплой в ЛЮБОМ порядке ничего не ломает:
между обновлением клиента и запуском скрипта никто не теряет доступ.

## Шаги деплоя

### 1. Матрица: добавить столбец plan.events (одноразовый скрипт)

Открыть Apps Script (script.google.com, проект развёртывания AKfycbyt… —
ОДИН проект на kip8 и kip8test), вставить файл
`scripts/RoleMatrixTask462Init.gs` (из репозитория kip8test), выполнить
функцию `task462AddPlanEventsPermission`. Скрипт идемпотентен:

- добавит колонку `plan.events` в лист matrix (r4 = perm_id, r5 =
  «Плановые мероприятия», чекбоксы; последней правой колонкой);
- проставит галочки ПО УМОЛЧАНИЮ = текущий доступ (Task 460): отметить
  роли с `kipios.view` ИЛИ `kipios.restricted` ИЛИ `flowmeter.view`
  (ИТР ТОКЕМ, КИП8 pro, КИП ИОС, КИП ИОС pro, КИП ИОС дежурный, ИТР8,
  ИТР8 pro, ИТР ИОС) + «Админ» — чтобы при переходе на новое право НИКТО
  не потерял раздел;
- добавит строку-справочник в лист permissions;
- допишет метку версии в matrix!A3;
- сбросит кэш матрицы (roleMatrixInvalidateCache).

Если колонка УЖЕ есть — скрипт ничего не меняет (галочки не трогает).

Можно и руками: колонка после последнего права, строка 4 = `plan.events`,
строка 5 = `Плановые мероприятия`, формат ячеек ролей — чекбокс, галочки
по списку выше.

### 2. Клиент (kip8test)

Уже в репозитории (SW kipia-test-v686), GitHub Pages деплоится автоматически
CI. Пользователям: Ctrl+Shift+R ×1–2.

### 3. Галочки в таблице (KIP8_Access → лист matrix)

После запуска скрипта доступ к разделу определяется ТОЛЬКО колонкой
`plan.events` — снимите/поставьте галочки ролям по усмотрению. Изменения
подхватываются БЕЗ релиза приложения: при входе, загрузке страницы,
heartbeat (кэш матрицы ≤ 5 минут; для мгновенного эффекта —
`roleMatrixInvalidateCache()` в редакторе Apps Script или из админ-панели).

## Что НЕ менялось

- Серверный код (Code.gs / WorkSchedule.gs / RoleMatrix.gs /
  RoleMatrixGate.gs) — не тронут: страница статичная, серверных запросов
  не делает, гейт не нужен; чтение матрицы динамическое.
- Таблица KIP8_Access общая для kip8 и kip8test — колонка появится у
  обоих, но клиент kip8 (v498) раздела ещё не имеет (Task 460/462 ждут
  переноса) и новую колонку игнорирует.

## Проверка после деплоя

1. Войти под ролью с галочкой `plan.events` → «Документация ИОС» →
   кнопка «Плановые мероприятия» видна, страница открывается.
2. Снять галочку у роли → Ctrl+Shift+R → раздел скрыт (кнопка, сайдбар),
   прямой URL — «Нет доступа»; хаб «Документация ИОС» работает.
3. Диагностика: `roleMatrixDebug()` в редакторе Apps Script — в списке
   прав должен появиться `plan.events`.
