# DEPLOY — Task 536: серверная погода УДАЛЕНА (WorkSchedule.gs без getWeather/парсеров/authorizeWeather); клиент — только прямые каналы open-meteo → wttr.in

Дата: 2026-10-16 · Репозиторий: kip8test · SW: `kipia-test-v749`

## Что изменилось (по заявке)

Заявка: «Через сервер погода не загружается, работает только через
wttr.in (напрямую из браузера), поэтому убери из кода WorkSchedule.gs
не рабочие строки кода связанные с погодой».

1. **WorkSchedule.gs — минус 290 строк нерабочего кода**: удалены
   эндпоинт `getWeather` (meteoinfo.ru + резерв open-meteo.com через
   `UrlFetchApp`), парсеры `_parseMeteoinfo`/`_parseOpenMeteo` и
   топ-уровневая функция `authorizeWeather()` — серверным запросам не
   хватало области `script.external_request`, и авторизация так и не
   была выдана. На местах удаления остались заметки «Task 536» с
   объяснением причины.
2. **Code.gs**: роутинг `workSchedule.getWeather` удалён (клиент больше
   не обращается к этому эндпоинту).
3. **Клиент (index.html)**: цепочка погоды — только ДВА прямых канала
   `open-meteo.com → wttr.in` (оба — из браузера, без Apps Script).
   Серверный резерв и все подсказки про `authorizeWeather()` /
   манифест `appsscript.json` / `oauthScopes` убраны. При сбое обоих
   каналов панель настроек честно пишет: «Прямые запросы
   open-meteo/wttr.in не прошли (…) Повтор — по расписанию или
   кнопкой ниже».
4. **НЕ тронуто**: производственный календарь `_getProdCal` (legalic)
   — это НЕ погода, `UrlFetchApp` там остаётся законным (у него свой
   тихий фолбэк).

## ЧТО НУЖНО СДЕЛАТЬ ВАМ

### Клиент (обязательная часть — 10 секунд)

Ничего не нужно: новое SW `kipia-test-v749` подхватится само при
следующем открытии приложения. Хотите сразу — **Ctrl+Shift+R**
(жёсткое обновление) на странице Табеля. Погода продолжит работать
через wttr.in, как работала.

### Сервер (по желанию — чистка мёртвого кода)

Старое развёртывание продолжит работать и БЕЗ обновления: клиент
просто больше не вызывает `workSchedule.getWeather`. Но чтобы в
проекте Apps Script не оставалось нерабочего кода (и FUNCTIONS
`authorizeWeather()` в списке редактора):

1. Скопировать из репозитория свежие файлы: `scripts/WorkSchedule.gs`
   и `scripts/Code.gs` — в соответствующие файлы проекта Apps Script
   (заменить содержимое целиком).
2. Deploy → Manage deployments → ✏ → Version: **New version** →
   Deploy.
3. Больше никаких `authorizeWeather()` запускать НЕ нужно — серверных
   запросов погоды больше нет в принципе.
