# DEPLOY — Task 489: «Сотрудники» табель_КИП_ИОС — ФИО → фамилия/имя/отчество + дата_рождения

**Тип: КЛИЕНТ + СЕРВЕР (Apps Script) + РАЗОВЫЙ ПЕРЕНОС ДАННЫХ.**

Заявка: «В файле табель_КИП_ИОС, в таблице "Сотрудники" столбец
"ФИО" раздели на три столбца для указания полных данных работников
фамилии, имени и отчества, и эти данные полного ФИО должны
отражаться только в приложении в карте работника в блоке профиле
и в сохранённом файле excel в скаченном архиве на листе
"Работники", в других местах как и прежде сокращённо (Иванов
И. И.). Так же добавь новый столбец "дата_рождения" перед
столбцом "комментарий", и эту информацию так же необходимо
отображать в карте работника в блоке профиле в конце списка. Не
забудь учесть при написании кода для скриптов, что столбцы в
таблице "Сотрудники" сместятся и поменяют своё наименование по
расположению.»

## Что сделано (код — kip8test @v713)

### Клиент `index.html` (v712 → v713)

1. **Карта работника · блок профиля** — шапка показывает
   **ПОЛНОЕ** ФИО («Хадасевич Александр Сергеевич · таб. №2741»;
   легаси-кэш без `ФИО_полное` — как прежде краткое). В списке
   профиля новая строка **«Дата рождения»** — В КОНЦЕ (после
   «Комментария», дд.мм.гггг; пусто/нет — не показывается).
2. **Форма добавления/правки работника** — единое поле «ФИО»
   заменено ТРЕМЯ (Фамилия/Имя/Отчество) + поле «Дата рождения»;
   префилл правки — из частей записи (легаси — раскладка краткого
   ФИО по словам); валидация — «Введите фамилию»; payload
   `addEmployee`/`updateEmployee` несёт части + дату рождения +
   легаси-поле `ФИО` (КРАТКАЯ композиция — не обновлённый Apps
   Script пишет его в единый столбец как прежде).
3. **Архив Excel (лист «Работники»)** — колонка ФИО теперь
   **ПОЛНОЕ** имя (легаси-запись — краткое); листы «Отпуска»/
   «Инструктажи»/«СИЗ» — как прежде кратко.
4. **Прочие места** (шахматка, попапы, сводка «Общая», СИЗ) —
   КАК ПРЕЖДЕ КРАТКОЕ ФИО («Хадасевич А. С.») — композиция
   из частей на сервере.

### Сервер `scripts/WorkSchedule.gs`

1. **`_employeesColMap`** — ВСЕ столбцы «Сотрудников» читаются/
   пишутся **по ЗАГОЛОВКАМ строки 1** (нормализация: регистр/
   пробелы/подчёркивания), фолбэк — канон РАСКЛАДКИ:
   - **НОВАЯ (Task 489):** A таб_№ / B фамилия / C имя /
     D отчество / E тип / F смена / G шаблон_ротации /
     H старт_цикла / I дата_приёма / J дата_увольнения /
     K в_архиве / L должность / (M группа_допуска — позиция
     любая) / N дата_рождения / O комментарий;
   - **ЛЕГАСИ:** A таб_номер / B ФИО / … / J должность /
     K комментарий.
   Раскладка определяется по наличию заголовков
   «фамилия»+«имя»+«отчество» (уроки Task 402/403: позиции
   столбцов в файле пользователя меняются — жёсткие индексы
   запрещены).
2. **`listEmployees`** — ответ несёт: `ФИО` — КАК ПРЕЖДЕ КРАТКОЕ
   (композиция «Хадасевич А. С.» из частей), `ФИО_полное` —
   ПОЛНОЕ («Хадасевич Александр Сергеевич»), сырые `фамилия`/
   `имя`/`отчество`, `дата_рождения` (ISO/null).
3. **`addEmployee`/`updateEmployee`** — части отдельными
   столбцами по карте; легаси-поле ФИО (старый фронтенд без
   частей) пишется КАК ЕСТЬ; `дата_рождения` — с guard по
   payload (старый фронтенд не затирает лист).
   **`dismissEmployee`** — увольнение/архив по карте (новая
   раскладка J/K, легаси H/I — жёсткие индексы удалены).
   **`_ppeLookupEmployee`** (СИЗ, колонки C/D) — краткое ФИО
   по карте (разделение сместило прежние индексы B/J).
4. **`employeesSplitInit` + `function employeesSplitInit()`** —
   РАЗОВЫЙ перенос (запуск в редакторе, как trainingsSplitInit).
