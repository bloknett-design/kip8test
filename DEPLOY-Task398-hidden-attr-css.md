# Task 398 — кнопка «Работники» у роли без доступа: атрибут `hidden` против CSS (фикс)

**Дата:** 23.09.2026. **Заявка:** «Почему в роли КИП ИОС видна кнопка
"Работники" в разделе Табель учёта рабочего времени, хотя доступа и
перехода по ней нет?»

## Что это

Клиентский фикс ОДНИМ CSS-правилом (index.html): у роли «КИП ИОС» с
`workschedule.view.min` (ограниченный просмотр табеля) кнопка
«Работники» ОСТАВАЛАСЬ на экране, хотя клик по ней ничего не делал.

## Причина (воспроизведена диагностикой)

1. **Логика была верной.** JS-гейт Task 395 честно ставил кнопке
   `#wsWorkersBtn` атрибут `hidden` (уровень `min` — карточки
   недоступны), `openWorkersPage()` молча отсекал клик (min ≠
   edit/view). Именно поэтому «доступа и перехода нет», а экран
   «Нет доступа» не показывался (гейт уровня — не navigateTo).
2. **Но атрибут не работал.** CSS-правило тулбара
   `.ws-refresh-btn { display: inline-flex }` (класс кнопки)
   ПЕРЕБИВАЕТ браузерный UA-стиль `[hidden] { display: none }`:
   авторский CSS ВСЕГДА сильнее стилей браузера по умолчанию.
   Замер (Chromium, роль КИП ИОС, уровень min): `hidden=true`,
   но rect кнопки **107×30** — она рендерилась и кликалась.
3. Полный DOM-скан (дашборд + табель): протекала ТОЛЬКО эта
   кнопка — у «Итогов учёта»/«Сформировать»/«Сохранить»/«Отменить»/
   вкладок «Месяц»/«Год» авторских display-правил нет, `hidden`
   работал. «Печать»/«Вид» того же класса протекали бы только в
   недостижимом состоянии (null — сам раздел скрыт).

## Фикс

Одно универсальное правило в начале `<style>` (index.html):

```css
[hidden] { display: none !important; }
```

Восстанавливает семантику атрибута `hidden` по ВСЕМУ приложению:
элемент с атрибутом не отображается, какой бы `display` ни задавал
авторский CSS. Показ — всегда снятием атрибута (`el.hidden=false`),
как и делает весь JS приложения. JS-гейты Task 395/397 не тронуты.
