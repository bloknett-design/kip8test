# Task 421 — DEPLOY: 9-ОГЭ — зависимый пункт (отметка без автосоздания)

Заявка: «Нужно подправить логику автоматического формирования новых
записей инструктажей. При выполнении общего инструктажа должно
формироваться две записи, общий через 6 месяцев и 9-ОГЭ через три
месяца от даты выполненного общего инструктажа. При выполнении 9-ОГЭ
не должна формироваться новая запись, а только фиксация его
выполнения. Получается, что 9-ОГЭ зависимый от общего».

## Диагноз

Правило (0) ЦИКЛ Task 420 при отметке выполнения 9-ОГЭ создавало
запись ОБЩЕГО инструктажа на дату +3 мес (замысел «по кругу»).
По новой заявке 9-ОГЭ — ЗАВИСИМЫЙ пункт: его выполнение ничего
создавать не должно, только фиксацию; цикл держится исключительно
на выполнении общего (общий создаёт ОБЕ записи: 9-ОГЭ +3 мес и
общий +6 мес — поведение Task 420 сохранено).

## Что сделано (SW kipia-test-v648)

### Сервер `scripts/WorkSchedule.gs`

1. **Правило (0) ЦИКЛ УДАЛЕНО** (`_autoCreateNextTrainings`):
   отметка РЕБЁНКА («в составе», 9-ОГЭ) больше не создаёт запись
   РОДИТЕЛЯ. Выполнение 9-ОГЭ = только фиксация (F=1, пересчёт
   «просрочен»).
2. **Правило (1) — только для независимых пунктов**: собственный
   новый срок (дата + N мес) создаётся у пункта БЕЗ «в составе»
   (`per > 0 && !parentItem`). Пункт-ребёнок собственного
   автосоздания НЕ имеет — его новые записи появляются при
   выполнении РОДИТЕЛЯ (правило 2). Неразрешающаяся связь
   (опечатка в столбце у не-9-ОГЭ пункта) → пункт считается
   независимым, срок создаётся.
3. **Правила (2)/(3) не менялись** (регресс 419/420): выполнение
   ОБЩЕГО создаёт ОБЕ записи — 9-ОГЭ +3 мес И общий +6 мес
   (чередование «по кругу из года в год»); незавершённые записи
   детей с датой <= даты родителя покрываются (`updated`).
4. **Аудит** `WORKSCHEDULE_SET_TRAINING_DONE`: разбор
   соответствия дополнен причиной — `[пункт=… родитель=… дети=…;
   Task 421: зависимый пункт — автосоздания нет]` (журнал Apps
   Script, Ctrl+Enter).

## ⚠ СЕРВЕРНЫЙ ШАГ (обязательно)

Новая логика работает только после обновления сервера:

1. Открыть проект Apps Script табель_КИП_ИОС;
2. заменить содержимое `WorkSchedule.gs` на новый
   `scripts/WorkSchedule.gs` из репозитория (main, коммит Task 421);
3. **Создать НОВУЮ ВЕРСИЮ развёртывания** (Deploy → Manage
   deployments → Edit → New version), старую версию не трогать;
4. Code.gs и маршрут не менялись; `instrListInit` запускать НЕ нужно.

До обновления сервера отметка 9-ОГЭ по-прежнему создаёт запись
общего (старый сервер); клиентская часть (тосты, «след. срок»)
работает при обеих версиях.
