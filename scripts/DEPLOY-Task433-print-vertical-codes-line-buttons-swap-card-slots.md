# Task 433 — печать (вертикальная секция, записи до конца листа, коды строкой) + кнопки ✎↔✕ + слоты названий в картах

**Заявка (kip8test):** «Расположение кодов в печати верни обратно,
я имел в виду, что бы правая часть блока растянулась вправо до
конца листа, и если текст не будет вмещаться в одну строку, тогда
переносить его на следующую строку. Кнопки редактировать и
удалить в блоке инструктажей поменяй местами. В картах
работников, в блоках профиля и отпуска, расстояние между
названием строчки и содержанием в этой строчке должно быть по
примеру как в блоке мероприятия обозначением кода и содержанием
в строке».

## Что изменилось

**Клиент `index.html` (сервер Apps Script НЕ тронут — srvVer 427,
WorkSchedule.gs/Code.gs без изменений):**

1. **Печать — нижняя секция снова ВЕРТИКАЛЬНАЯ (заявка:
   «расположение кодов верни обратно»).** Флоат Task 432 и
   flex-ряд Task 364/431 СНЯТЫ:
   - **КАЖДАЯ запись-«блок» списка мероприятий — гибкий ряд
     [точка][дата][текст]** (`.wsp-mev-item`: `display: flex`,
     `align-items: baseline`, `gap: 1mm`, `page-break-inside:
     avoid`): дата — слот `min-width: 66px` (худший диапазон
     «29.09–02.10», короткие «20.09» выравниваются по нему),
     **ТЕКСТ `.wsp-mev-text` — `flex: 1` — ПРАВАЯ ЧАСТЬ БЛОКА
     РАСТЯНУТА ВПРАВО ДО КОНЦА ЛИСТА**; перенос — ТОЛЬКО когда
     текст не вмещается в одну строку (замер предпросмотра:
     первая строка длинной записи 1070 из 1092; короткие записи —
     одна строка);
   - **КОДЫ — ВЕРНУЛИ ИСХОДНОЕ РАСПОЛОЖЕНИЕ «в одну строку»**
     (как до Task 360; столбик Task 360–431 и флоат Task 432
     сняты): единая строка-абзац «Коды: …» ПОД списком
     мероприятий (`.wsp-legend`: `margin-top: 2.5mm`, БЕЗ float и
     max-width), коды идут В СТРОКУ (`.wsp-lg`: `display: inline`,
     `margin-right: 3mm`, `white-space: nowrap` — код не рвётся
     внутри): строка ЗАПОЛНЯЕТСЯ вправо до конца листа (замер:
     крайний код 1027 из 1092), перенос на следующую строку —
     только когда текст не вмещается; «Коды:» и первый код — на
     одной строке; сноска `wsp-foot` — ниже обеих секций;
   - **порядок DOM**: обёртка → мероприятия → коды → два
     последовательных закрытия → сноска (в `_buildPrintHtml`
     мероприятия строятся ПЕРВЫМИ — флоат Task 432 строил коды
     первыми). Работает и в диалоге предпросмотра (Task 430), и
     при прямой печати, и в сохранённом HTML (тот же CSS через
     `_printCssText`).

2. **Блок инструктажей: кнопки ✎ и ✕ ПОМЕНЯНЫ МЕСТАМИ** (Task
   432 было «✕ ✎»). В разметке b5 ряд строится как
   `iActEdit + iActDel` — карандаш правки ПЕРВЫМ, крестик
   удаления ПОСЛЕ. Колонка `.ws-act-col` (галочка НАД рядом) и
   зазоры 5px (Task 431/432) НЕ тронуты. Попап ячейки шахматки —
   прежний горизонтальный порядок ✎/✕ (гейт asBlocks жив).

3. **Карты работников — плотные слоты названий «по примеру блока
   мероприятий»** (слот кода 26px + gap 8px):
   - профиль: `.ws-wcard .ws-emp-field .ws-emp-k` — `min-width`
     128 → **110px** (плотный по самой длинной строке «Группа
     допуска» ≈ 109px при 14px): расстояние название→содержание —
     как код→содержание (зазор после «Группы допуска» 8px,
     значения выровнены в одну колонку 118px от края строки);
   - отпуска: строки несут класс `ws-emp-vac` + СВОЙ плотный слот
     **56px** в картах («Часть N» короче названий профиля — зазор
     8px вместо прежних ~76px);
   - базовый вид 12px (попапы/совместимость): 108 → 94px,
     отпуск — 48px. СИЗ/мероприятия/инструктажи и попапы НЕ
     тронуты.
