# Task 426 — День шахтёра: НЕ государственный праздник

**Заявка (kip8test):** «И ещё учти, при подсчёте отпускных дней и
учёте праздничных выходных, что день шахтера (отмечается каждый год
в последнее воскресенье августа) не входит в перечень
государственных праздников, дающих право на дополнительный
выходной».

## Что изменилось

**Сервер `scripts/WorkSchedule.gs`** — календарь без Дня шахтёра:

1. **Наложение удалено из `_getProdCal`** (обе ветки):
   - legalic-ветка: больше НЕ добавляет последнее воскресенье
     августа в нерабочую карту как региональный праздник — дни
     берутся из федерального календаря как есть. Если календарь
     объявит этот воскресенье рабочим переносом
     (TRANSFERRED_WORKING) — он будет РАБОЧИМ (раньше оверлей
     принудительно возвращал выходной);
   - фолбэк без сети: 30.08 НЕ добавляется в карту праздников —
     воскресенье остаётся обычным выходным по дню недели
     (`_isNonWorkingDay` для дневного персонала работает как для
     любого воскресенья);
   - функция `_minersDayMmdd` (расчёт даты) удалена.
   На график дневного персонала 5/2 это НЕ влияет (воскресенье и
   так нерабочий) — меняется только СТАТУС дня: не «праздник», а
   «обычный выходной».

2. `srvVer` '425' → **'426'** (маркер нового сервера в ответе
   `setTrainingDone` — проверяется отметкой любого инструктажа;
   предупреждение «старый сервер» остаётся только для < 423).

**Клиент `index.html` (ProdCalendar)** — то же правило на клиенте:

1. **Оверлей `_applyRegionalOverlay` удалён** вместе с
   `_minersDayMmdd` и константой `_MINERS_DAY_TITLE` («День
   шахтёра») — данные legalic/isDayOff используются как есть;
2. **Фолбэк `dayInfo`** больше не вычисляет День шахтёра: последнее
   воскресенье августа — обычный выходной, `holiday: false`,
   без названия (День города Кемерово 12.06 остаётся — это только
   название федерального праздника);
3. **Отпускные дни (Task 310, ст. 120 ТК РФ)** — ГЛАВНОЕ:
   праздник в периоде отпуска не вычитается из календарных дней
   → отпуск, захватывающий последнее воскресенье августа,
   больше НЕ продлевается на этот день (тест: 24.08–06.09.2026 →
   14 календарных = 14 «чистых», раньше было 13; праздники
   ст. 112 — 01.05, 09.05 и т.д. — вычитаются как раньше);
4. **Внешний вид**: у ячейки этого воскресенья нет розовой
   праздничной подсветки и названия «День шахтёра» в тултипе/
   попапе — обычный выходной в красной рамке-группе выходных;
   месяц августа в окошке «Мероприятия/нормы» — без «30 августа —
   региональный праздник»;
5. **Кэш поднят v2 → v3** (`ws_pcal_year3_`): в старом кэше День
   шахтёра лежит как праздник — после обновления первый запуск
   скачает свежие данные и старые ключи v1/v2 вычистятся
   автоматически (ничего нажимать не нужно);
6. **SW v652 → v653** — пользователи получат новый index.html.

## О «легаси-строках обучение/прогул/примечание»

Фраза из Task 425 обозначала: старые записи мероприятий, которые
была внесены в лист «Инструктажи» ещё СТАРОЙ версией приложения
(до разделения таблиц Task 405 — тогда мероприятия и инструктажи
писались в один лист). Текущий код их НЕ создаёт: новые
мероприятия идут только в «Мероприятия». Стоп-правило Task 425 —
защита на случай, если такая старая строка ещё лежит в живом
листе: отметка её выполнения не запускает автосоздание
инструктажных сроков. Если в листе «Инструктажи» (таблица
табель_КИП_ИОС, столбец C «тип») таких строк нет — делать ничего
не нужно. Если есть и их нужно перенести в архив «Мероприятия» —
в редакторе Apps Script запустить `trainingsSplitInit` (переносит
обучение/прогул/примечание в «Мероприятия», id сохраняются;
повторный запуск безопасен).
