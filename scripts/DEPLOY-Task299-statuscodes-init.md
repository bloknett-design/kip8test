# DEPLOY Task 299 — скрипт автоматической замены листа «Коды_статусов»

**Дата:** 2026-09-03 · **Репозиторий:** kip8test · **SW:** v540 (не менялся) · **Тесты:** 1345/0 + мок-тест 76/0

## Что это

`scripts/StatusCodesInit.gs` — разовый инструмент для Google Apps Script,
автоматизирующий ШАГИ 1–3 деплоя Task 298 (DEPLOY-Task298-status-codes.md):

| Шаг Task 298 | Было вручную | Стало |
|---|---|---|
| 1. Лист «Коды_статусов» — 16 строк | вбить руками, «?» в цветах | `statusCodesReplace()` |
| 2. Миграция «О»→«ОТ» в «Записи_графика» | Ctrl+H по колонке C | `migrateVacationStatus()` |
| 3. (опция) «Дни_цикла» шаблон 2 → Д8/Д7,2 | руками | `updateCycleDaysTemplate2()` |

Всё сразу (Шаги 1–2): **`statusCodesDeployAll()`** — рекомендованный запуск.

## Запуск

1. Открыть редактор Apps Script проекта развёртывания (AKfycbyt… —
   тот же, где лежит `WorkSchedule.gs`).
2. «+» → **Создать файл** → имя `StatusCodesInit.gs` → вставить содержимое
   файла ЦЕЛИКОМ (копия: `download/kip8test/scripts/StatusCodesInit.gs`).
3. Выбрать в выпадающем списке функций `statusCodesDeployAll` → **▶ Run**
   (первый запуск попросит авторизацию — разрешить).
4. Журнал (Ctrl+Enter): скрипт открывает таблицу 1MQtW… по ID, пишет её
   адрес, сохраняет прежний лист в резерв, пишет новый, перечитывает и
   подтверждает построчно.
5. Проверить приложение (см. ниже), затем при желании запустить
   `statusCodesStatus()` (диагностика) и `statusCodesCleanupBackups()`
   (удалить резервы, когда откат точно не нужен).
6. Файл из проекта можно удалить — код приложения его не использует.

**Редеплой Web App НЕ нужен** (сервер не менялся), Ctrl+Shift+R НЕ нужен
(SW v540 уже у пользователя): приложение читает «Коды_статусов» динамически
без кэша — состав подхватывается после обновления страницы.

## Функции

- `statusCodesDeployAll()` — Шаг 1 + Шаг 2 одним запуском (рекомендация).
- `statusCodesReplace([force])` — Шаг 1: старый лист сохраняется как
  «Коды_статусов_резерв_<дата_время>», новый создаётся на его позиции;
  повторный запуск при уже эталонном составе — no-op; `force=true` —
  перестроить оформление.
- `migrateVacationStatus()` — Шаг 2: ТОЧНОЕ «О» (кириллица) в колонке C,
  с учётом регистра; «ОТ»/«ОБ»/«д»/латинская «O» не затрагиваются; перед
  правкой лист копируется в «Записи_графика_резерв_<дата_время>».
- `updateCycleDaysTemplate2()` — Шаг 3 (опция): шаблон 2, дни 1–4
  «Д»→«Д8», день 5 «Д»→«Д7,2»; резерв «Дни_цикла_резерв_<дата_время>».
- `statusCodesStatus()` — диагностика без изменений: текущий лист,
  отличия от эталона, остаток «О», состояние шаблона 2, список резервов.
- `statusCodesCleanupBackups()` — удалить все резервные листы трёх
  семейств (⚠ только когда откат не нужен).

## Что запишется (16 кодов, Т-12/Т-13)

Порядок = порядок строк в попапе шахматки. Полная таблица — в самом
`StatusCodesInit.gs` (массив `SC_STATUS_CODES`, легко поправить названия/
цвета перед запуском). Отличия от ручной правки пользователя (xlsx от
03.09.2026):

1. **«Д8» и «Д7,2» — ДВА кода, раздельные строки.** В ручной правке они
   были склеены в одну строку «Д8, Д7,2» — так не работает: колонка A —
   первичный ключ, код сверяется точным совпадением (сервер:
   `_validateStatusCode` → `unknown_статус`; клиент: попап/select из
   листа). Деплой Task 298 (v540) рассчитан именно на 16 отдельных кодов.
2. **Цвета заполнены** там, где в ручной правке стояло «?»:
   Д8 `#FFF9C4`, Д7,2 `#FFF176`, д `#FFD54F`, н `#78909C`, У `#80CBC4`,
   И `#B3E5FC`, `*` `#FFAB91`, `.` `#CFD8DC` (согласованный набор Q2).
3. Название «.» — вариант пользователя: «Выходной, плановый выходной
   день». ПЗ — без точки в конце (единообразно с остальными).
4. Длинные формулировки д/н — из DEPLOY-Task298 (с «—» и «в комментарии»).

## Безопасность

- Прежний лист НИКОГДА не удаляется: резерв с датой-временем в имени.
  Полный откат Шага 1 = переименовать резерв обратно в «Коды_статусов».
- Миграция и Дни_цикла правятся только после копии листа (copyTo).
- Валидация данных ДО записи: дубль кода/кривой цвет останавливает
  скрипт до любых изменений в таблице.
- Самопроверка после записи: лист перечитывается и сверяется построчно
  («Д7,2», «*», «.» посимвольно; формат «@» не даёт Google ничего
  переинтерпретировать).
- Идемпотентность: повторные запуски — no-op, резервы не плодятся.
- Никаких объединений ячеек и закреплений столбцов (урок RoleMatrixInit
  v3/v4 про неотображаемые листы); закреплена только строка 1.

## Проверка после запуска

1. В журнале: «✓ ЗАМЕНА ВЫПОЛНЕНА: 16 кодов записаны и подтверждены
   чтением» + «✓ МИГРАЦИЯ: N записей „О“ → „ОТ“».
2. Таблица: лист «Коды_статусов» — тёмная шапка, 16 строк, каждая строка
   залита своим цветом; резервные листы рядом.
3. Приложение «График работы» (обновить страницу): тап по пустой ячейке —
   попап = 16 кодов + «— выходной» + «Дополнительно…», у кодов цветные
   свотчи; «Дополнительно…» → select «Статус» = 16 кодов.
4. Месяц с отпуском: пустые ячейки плана показывают «ОТ» (пунктир);
   «Сформировать» создаёт записи «ОТ» без дублей и без «зависших» «О».
