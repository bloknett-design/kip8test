# DEPLOY — Task 309: карточка сотрудника у колонки ФИО, правка/удаление мероприятий, рамка ручных д/н

**Дата:** 2026-09-04 · **Репо:** kip8test · **SW:** kipia-test-v547 → **v548**
**Заявка пользователя:** «при наведении указателя мыши или при нажатии
на поле с сотрудником (слева от шахматки), должно появляться окно с
данными сотрудника, которые раньше были в убранных вкладках
(сотрудники, отпуска, инструктажи). Так же сделай возможность
редактирования и удаления добавляемых мероприятий в ячейки. Коды "д"
и "н", добавляемые в шахматку пользователем вручную, должны
отображаться с обрамлением по краям, по примеру как в их миниатюрах».

## Что изменилось (только фронтенд)

1. **Карточка сотрудника** — попап у колонки ФИО (наведение курсора
   с задержкой 350 мс или клик; на таче — только клик). Данные из
   удалённых вкладок (Task 307/308):
   - секция **«Сотрудник»** — тип/смена, должность, шаблон ротации
     (имя из «Шаблонов_ротации»), старт цикла, дата приёма, комментарий;
   - секция **«Отпуска · \<год шахматки\>»** — периоды по частям
     (фильтр `_vacDaysInYear`), «Итого в году: N дней»;
   - секция **«Мероприятия · \<месяц\>»** — события месяца с темой,
     датами и кодом (свотч цвета из справочника).
   Два режима: **hover** (закрывается при уходе курсора через 400 мс;
   вход курсора в попап отменяет закрытие — кнопки кликабельны) и
   **pinned** по клику (закрытие — клик по фону или Esc). Взаимная
   блокировка со статусным попапом ячейки. Элементы: `#wsEmpPopup`
   (`.ws-cell-popup.ws-emp-popup`) + `#wsEmpPopupCloser`.
   Колонка ФИО: `cursor: pointer`, сплошная hover-подсветка
   (sticky-колонка — прозрачный фон просвечивал бы), `data-tab` для
   hover-делегата (mouseover/mouseout на `#wsGridWrap` — слушатели
   переживают перерисовки innerHTML).
2. **Правка и удаление мероприятий** (кнопки только у ролей с правом
   записи; зрители видят справку):
   - в попапе ячейки — секция «Мероприятия в этот день» получила
     кнопки **✎** (правка) и **✕** (удаление) в каждой строке;
   - в карточке сотрудника — те же кнопки у каждого мероприятия;
   - **правка** — шторка `#wsTrSheet` в режиме «Правка мероприятия»
     (заголовок `#wsTrSheetTitle`, кнопка «Сохранить» `#wsTrSubmitBtn`,
     форма заполнена значениями записи). Сохранение = **addTraining
     (новые значения) + deleteTraining (старый id)** — серверного
     `updateTraining` не существует, Apps Script НЕ менялся. Порядок
     add→delete выбран из отказа от потери данных: сбой добавления не
     трогает старую запись; сбой удаления после успешного добавления
     оставляет видимый дубль (перезагрузка сетки + тост ошибки).
     Старые авто-строки Записи_графика с FK удалённого id снимет
     «Сформировать» (шаг 4.6), новые создаст с новым id — регенерация
     сходится. Тост «Мероприятие обновлено».
   - **удаление** — прежний `deleteTraining` (kipConfirm), попапы
     закрываются до диалога.
3. **Ручные коды «д»/«н»** — класс `ws-manual-dn` (только источник
   «руч» + строчные д/н): рамка по краям ячейки
   `box-shadow: inset 0 0 0 2px` — как у миниатюры-свотча попапа
   выбора статуса (тёмная тема — светлая рамка, светлая — тёмная).
   Видна и ДО сохранения (локальная правка уже даёт «руч»). Плановые
   Д/Н и другие ручные коды — прежний вид (тонкая рамка
   `ws-source-manual`).
4. **Регресс-фиксы Task 308** (баг: после добавления/удаления
   мероприятия — ложный тост «Ошибка: … loadTrainings is not a
   function», сетка не перезагружалась): вызовы удалённых вместе со
   страницами методов `loadTrainings()` / `loadVacations()` заменены
   на `loadGrid()` (перезагружает всё, включая `_loadTrainings` /
   `_loadVacations`).

## Чего НЕ менялось

- **Сервер `WorkSchedule.gs` — БЕЗ изменений** (Apps Script НЕ трогать!).
  Правка мероприятия — композиция живых эндпоинтов
  `workSchedule.addTraining` + `workSchedule.deleteTraining`.
- Листы Google-таблицы — без изменений; миграции не нужны.
- Все эндпоинты `workSchedule.*` — прежние; id мероприятий при правке
  меняется (новая запись), на работу сетки это не влияет.
