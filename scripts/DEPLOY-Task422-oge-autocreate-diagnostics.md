# Task 422 — 9-ОГЭ +3 мес не создаётся: диагностика и фикс

**Заявка (kip8test):** «Проверь, при выполнении общего инструктажа, 9-ОГЭ +3 мес не создаётся».

## Диагноз (воспроизведён на GAS-VM до правок)

Код Task 421 на чистых данных создаёт ОБЕ записи. Симптом возникает при
одном из трёх условий:

1. **«Хвостовая» запись общего в окне (дата; дата+3]** — например, созданная
   снятым правилом (0) Task 420 (отметка 9-ОГЭ → общий +3) или вручную.
   Проверка `!hasInWindow(tema, provDate, chDate)` в правиле (2) считала её
   «цикл уже продолжается» и НЕ создавала 9-ОГЭ — навсегда, пока хвост не
   удалить. На сценарии «хвост 15.11 при отметке общего 01.09» не создавалось
   ВООБЩЕ НИЧЕГО (хвост блокировал и 9-ОГЭ, и общий +6).
2. **Дубль 9-ОГЭ в окне** — молчаливая защита от дубликатов: пользователь
   не видел НИ записи, НИ объяснения.
3. **Старый Apps Script** (419: строгая связь по эталонным названиям) — на
   живом листе пользователя давал «только общий +6», тот же симптом.
   Клиент не мог отличить старый сервер от нового.

## Реализация

**Сервер `WorkSchedule.gs`** (клиент — только диагностика):

1. **Правило (2) — ГЛАВНЫЙ ФИКС:** окно (дата; дата+N] проверяется ТОЛЬКО по
   записям САМОГО ребёнка (настоящий дубль). Запись РОДИТЕЛЯ в окне ребёнка
   больше НЕ подавляет создание — заявка: «при выполнении общего ДВЕ записи
   безусловно». «Хвостовой» общий не оставляет 9-ОГЭ без нового срока; цикл
   продолжится его выполнением. Антидубль родителя в правиле (1) сохранён
   (хвост в окне (X; X+6] → общий +6 не создаётся).
2. **`skipped[]` с ПРИЧИНОЙ** для детей без новой записи: «уже запланирован
   на ДД.ММ.ГГГГ» (hasInWindow теперь возвращает дату записи, занявшей окно) /
   «периодичность не задана» / «ошибка создания (…)». Per-child try/catch —
   сбой одного ребёнка не роняет остальных и уже созданный общий.
3. **Ответ `setTrainingDone`** дополнен: `srvVer: '422'` (версия серверного
   кода автосоздания), `autoNote` (полный разбор пункт/родитель/дети/решения
   — раньше только в аудит-логе Apps Script), `skipped`. Ошибка автосоздания
   больше НЕ молчит: catch пишет `autoNote = 'ОШИБКА автосоздания: …'` в
   ответ (отметка по-прежнему не ломается).
4. `note` аудита дополнен решениями по детям: «9-ОГЭ → 01.12.2026» /
   «9-ОГЭ: не создан — уже запланирован на 20.11.2026».

**Клиент `index.html`** (`toggleTrainingDone`):

5. Тост при отметке: новые сроки (как раньше) + **пропущенные дети с
   причиной** («…; 9-ОГЭ — уже запланирован на 20.11.2026») + **⚠ «Сервер
   Apps Script старой версии — замените WorkSchedule.gs и создайте новую
   версию развёртывания»**, если в ответе нет `srvVer` (главная причина
   «создался только общий» на живых данных) + ⚠ «Автосоздание не завершено»
   при ошибке.
6. `autoNote` — в консоль (`[инструктажи] автосоздание: …`, F12 → Console)
   для точечной диагностики живого листа.
