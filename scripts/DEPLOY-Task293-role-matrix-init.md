# DEPLOY-Task293 — Инициализация матрицы доступа в KIP8_Access

**Версия скрипта: v4** (устранена ПРИЧИНА «пустых листов» после v3:
объединение заголовков на всю ширину при закреплённых столбцах
создаёт состояние, которое Google Sheets не может отобразить — лист
существует, но выглядит пустым; закрепление столбцов полностью убрано —
стиль существующих листов users/sessions; добавлены самопроверка чтением
и функция `roleMatrixStatus()`).
История: v3 — закрепление до объединений; v2 — `setFontStyle('italic')`
+ `roleMatrixCleanup()`; v1 — первый выпуск.

**Что это**: одноразовый запуск скрипта `RoleMatrixInit.gs`, который создаёт
в таблице **KIP8_Access** 3 новых листа системы доступа (matrix, permissions,
roles). Приложение (PWA / Apps Script Web App) на этом этапе **не меняется и
не передеплоивается** — новая таблица станет источником истины для системы
доступа на следующих этапах (Task 294+: RoleMatrix.gs чтение, клиент,
вкладка админ-панели).

**Безопасность**: существующие листы (users, sessions, otp_codes, audit_log,
config) не затрагиваются. Повторный запуск ничего не изменяет (идемпотентно).
Расширение Web App (деплой AKfycbyt…) трогать НЕ нужно.

## Шаги запуска (5 минут)

1. Открыть таблицу **KIP8_Access**
   (docs.google.com/spreadsheets/d/1TmmNZLUArWH38F6NX0gMGar8LMNMQomm_FaGZv9osyk).
2. Меню: **Расширения → Apps Script** — откроется редактор проекта,
   привязанного к этой таблице (тот же, что развёрнут как Web App).
3. На панели файлов слева: **+ → Скрипт (Файл)** → назвать
   `RoleMatrixInit` → в открывшийся файл вставить всё содержимое
   `RoleMatrixInit.gs` (из download/kip8test/).
4. **Ctrl+S** (сохранить).
5. Сверху в выпадающем списке функций выбрать **roleMatrixInit** →
   **Выполнить** (Run).
   - Первый запуск попросит авторизацию (Review permissions → выбрать
     аккаунт → Разрешить) — это доступ скрипта к вашей же таблице,
     безопасно.
6. Дождаться завершения. В журнале выполнения (Execution log) должно быть:
   `Готово. Созданы листы: matrix, permissions, roles. Прав: 13, ролей: 12.`
7. Перейти в таблицу и проверить 3 новых листа (вкладки внизу):
   - **matrix** — «роль × право», чекбоксы-галочки;
   - **permissions** — справочник 13 прав с описаниями;
   - **roles** — справочник 12 ролей.
8. Файл `RoleMatrixInit.gs` в проекте Apps Script можно оставить (он не
   участвует в обработке запросов) или удалить — на работу Web App не влияет.

## Если уже запускали v1/v2/v3 (любая из этих версий)

- v1 упал на `setItalic` — частично создан matrix.
- v2 упал на «Невозможно закрепить столбцы…» — создан matrix (битый).
- v3 завершился «Готово», но листы ПУСТЫЕ (повреждены объединением
  через границу закрепления; подтверждено скачиванием таблицы:
  листы есть, закрепления 5×2/4×2 есть, непустых ячеек — 0).

Восстановление одинаковое:

1. Обновить содержимое файла RoleMatrixInit в Apps Script на код **v4**
   (Ctrl+A → вставить новый код → Ctrl+S).
2. В выпадающем списке функций выбрать **roleMatrixCleanup** → Выполнить —
   удалит старые (в т.ч. повреждённые) листы. Ожидаемый лог:
   `Удалены листы: matrix, permissions, roles. Теперь запустите roleMatrixInit().`
3. Выбрать **roleMatrixInit** → Выполнить. Ожидаемый лог (без всяких
   предупреждений):
   `Целевая таблица: «KIP8_Access» — https://docs.google.com/…`
   `Готово. Созданы листы: matrix, permissions, roles. Прав: 13, ролей: 12. Самопроверка чтения: matrix 17×15 (A6='zapret'), permissions 17×8, roles 16×5 — ОК. …`
4. Перейти в таблицу → вкладки matrix / permissions / roles (последние
   в списке вкладок) — теперь с содержимым.

Если что-то выглядит не так — выбрать **roleMatrixStatus** → Выполнить
и прислать журнал: функция ничего не меняет и показывает точное
состояние листов (размеры, закрепления, «повреждён/пустой/ОК»).

## Проверка результата

- В листе **matrix**: заголовок и инструкция в строках 1–2 (объединены
  на всю ширину), 12 ролей-строк, 13 колонок-прав с галочками, роли
  «Запрет / Общий доступ / Админ» обведены золотой рамкой
  (системные — защищены от удаления), закреплены строки 1–5.
- Названия ролей в колонке B листа matrix и в листе roles **точно**
  совпадают со значениями role в листе users (связка по названию).
- Технические строки (1–5) и колонки A–B при попытке редактирования
  показывают предупреждение (мягкая защита warning-only).
- Диагностика в любой момент: функция **roleMatrixStatus**.

## Что изменилось по сравнению со старой картой (применено ПО таблице)

  `kipios.view` / `kipios.restricted` (взаимоисключающие),
  `workschedule.view` / `workschedule.edit`.
