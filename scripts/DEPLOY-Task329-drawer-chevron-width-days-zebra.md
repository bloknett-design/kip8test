# Task 329 — ШТОРКА «ИТОГИ УЧЁТА»: ШЕВРОН НА ЛЕВОМ КРАЮ, БОРТИК, ШИРИНА ПО СТОЛБЦАМ, ПЕРЕРАБОТКА В ДНЯХ, ЗЕБРА ФИО

**Дата:** 2026-09-06
**Заявка пользователя:** «В шторке итогов учёта убери кнопку "Ещё", на внутренней стороне левого края шторки по середине размести кнопку-значок со стрелкой шеврона и сделай на нём функционал кнопки "Ещё", а по левому краю шторки сделай небольшой декоративный бортик. Теперь шторка итогов учёта должна выдвигаться ровно по размеру столбцов таблицы, поэтому ширину столбцов сделай уже, по размеру их заглавий в две строки. Данные столбца переработки показывай не в часах а в днях. В столбце сотрудников сделай фон зебру, как в шторке итогов учёта.»

**Затронуто:** только `index.html` (клиент) + `sw.js` (версия кэша) + тесты.
**НЕ тронуто:** сервер/Apps Script/листы Google (эндпоинты и данные без изменений).

## Что сделано

1. **Кнопка «Ещё» УДАЛЕНА из шапки** (`#wsTtMore`, CSS `.ws-tt-more` удалены).
   Шапка шторки — снова только ⚠ + «Обновить» (Task 325); на месяце —
   пустой 16px-филлер (`_updateTtHead` без «Ещё»).

2. **Кнопка-значок-ШЕВРОН `#wsTtChv`** на внутренней стороне ЛЕВОГО края
   шторки, по середине высоты (`top: 50%` + `translateY(-50%)`,
   `left: 0`, z 6, 22×48, примыкает к бортику, полупрозрачная заливка):
   svg-стрелка «‹» — «раскрыть столбцы влево»; активное состояние —
   разворот на 180° (`.on svg { rotate(180deg) }`, transform 0,18s),
   синий тинт; `aria-pressed`/`aria-label` (видимой подсказки нет —
   как у значка подсветки Task 328). Функционал — прежний
   `toggleTotalsExtra()` (доп. столбцы месяца, состояние переживает
   смены месяца/вкладок). `_updateTtMoreBtn` → `_updateTtChv`
   (видимость: открытая шторка + вкладка «Месяц»).

3. **Декоративный БОРТИК `.ws-tt-edge`** по левому краю шторки: тонкая
   вертикальная полоса 5px во всю высоту края — вертикальный
   «родственник» нижней полосы `.ws-tt-foot` (стальной bevel
   #35648f + блик #85b7dc; светлая #b3c2ce + белый), `pointer-events:
   none`, z 5.

4. **Шторка выдвигается РОВНО ПО СТОЛБЦАМ таблицы:**
   - геометрией владеет JS: `_fitTtDrawer()` после каждого рендера
     ставит `width = фактическая ширина таблицы` (месяц — сумма
     явных узких ширин; год — max-content; пусто — 240);
   - парковка за правым краем и анимация — ИНЛАЙНОВАЯ маржа в px
     (проценты не умеют «минус собственная ширина», прежние
     `width: 50%`/`margin-right: -50%`/правило `ws-tt-open → 0`
     удалены): открытие — `margin-right: −ширина` → reflow → `0`
     (transition 0.28s; сетка сжимается плавно, коробка не
     сплющивается), закрытие — маржа `−ширина` (шторка уезжает
     С КОНТЕНТОМ, панель прячется уборкой `_ttCloseCleanup` через
     320 мс);
   - кап `max-width: 60%` — длинные таблицы (год) прокручиваются
     ползунком шторки;
   - пересечение брейкпоинта desktop↔mobile: инлайновые размеры
     сбрасываются (иначе px перебили бы 86vw оверлея); возврат на
     десктоп с открытой шторкой — полный перерендер (`onMqTT`
     в `_attachFitResize`).

5. **Столбцы УЗКИЕ — по заголовкам в 2 строки** (десктоп): месячная
   таблица — `table-layout: fixed` + ЯВНЫЕ ширины каждого th
   (классы `ws-tt-c-*` в CSS + дубль-инлайн из JS-карты `TT_COL_W`):
   Явки 36 · Часы 38 · Переработка 56 · Отгул 42 · Больничный 64 ·
   Отпуск 50 · Уч. отпуск 52 · Прогул 50 · День 38 · Ночь 38 ·
   Прочие 50 (значения подобраны замером 11px bold — все заголовки
   ≤ 2 строк). Свернуто 130px, развёрнуто 514px. JS дополнительно
   ставит ЯВНУЮ ширину таблицы = сумме (fixed-раскладка с
   `width:auto` в контейнере нулевой ширины даёт КРУГОВУЮ
   зависимость — столбцы сжимались в мин-контент; явный px
   детерминирован). Годовая таблица — `width: max-content`.
   Мобайл — прежняя модель (100% оверлея, ФИО 42%, равные остатки;
   разворот «Ещё» — мин-ширина 64px/столбец + прокрутка).

6. **ПЕРЕРАБОТКА — В ДНЯХ, не в часах** (месяц И год): значение —
   `overDays` (количество записей д/н), целое; ЧАСЫ — в тултипе
   ячейки («часов переработки: 12 (коды д/н)», с запятой). Заголовок
   годовой колонки — «дни переработки за год».

7. **ЗЕБРА колонки сотрудников шахматки** — как строки шторки
   (Task 322: тёмная 9% / светлая 7%): чётные строки
   `td.ws-emp-col` — градиент ПОВЕРХ непрозрачного фона (колонка
   sticky; тот же приём, что подсветка «сегодня» Task 313), включая
   ШИРОКИЙ режим (шторка открыта — правило продублировано со
   специфичностью выше gridwide-шортката); hover ФИО — сплошная
   подсветка без зебры (одинаково на чётных/нечётных). Строки
   выровнены со шторкой — полосы «продолжают» зебру итогов.
