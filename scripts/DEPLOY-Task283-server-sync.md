# DEPLOY Task 283 — сервер Apps Script не знает отпускные действия
# («Ошибка: Unknown action: workSchedule.addVacation»)

## Симптом (заявка пользователя 2026-09-01)

> В приложении (v530, тосты включены) при добавлении отпуска:
> **«Ошибка: Unknown action: workSchedule.addVacation»**.
> Отпуска в списке не отображаются (там «Ошибка: Unknown action:
> workSchedule.listVacations»).

Хорошая новость: фронтенд Task 282 работает — тост показал
настоящую причину вместо молчания. Запрос **доходит до сервера**,
авторизация проходит — но сервер отвечает «не знаю такого действия».

## Причина

В Apps Script-проекте табели стоит **старый `Code.gs` без
роутинга отпусков**. Маршруты `workSchedule.listVacations /
addVacation / deleteVacation` появились в Task 274 (DEPLOY-Task274,
шаг 2.3 и шаг 2.4 «Новая версия»). Судя по ошибке, в проекте эти
маршруты не внесены (или не была создана новая версия развёртывания) —
тогда любой отпускной запрос попадает в ветку `default` роутинга и
возвращает `Unknown action: …`.

Раньше (до v530) эта ошибка **молча глоталась** фантомным KipToast —
отсюда и «нажимаю добавить — ничего не происходит», и «отпуска не
отображаются» без объяснений.

## Фикс

Код менять не нужно — **актуальные файлы уже готовы** в
`download/kip8test/`. Нужно синхронизировать сервер Apps Script
с репозиторием (2 файла) и пересобрать версию.

## Шаги деплоя (3 шага, ~5 минут)

1. Открыть проект Apps Script табели (из Google Таблицы:
   **Расширения → Apps Script**, тот же проект, где `Code.gs`,
   `WorkSchedule.gs`).
2. **Заменить `Code.gs`**: открыть файл `Code.gs` → выделить всё
   (Ctrl+A) → удалить → вставить содержимое файла
   `download/kip8test/Code.gs` → сохранить (Ctrl+S).
3. **Заменить `WorkSchedule.gs`**: так же — Ctrl+A → удалить →
   вставить содержимое `download/kip8test/WorkSchedule.gs` → Ctrl+S.
4. **Новая версия**: Deploy → **Управление развертываниями** →
   ✏️ (карандаш) → Версия: **Новая версия** → Описание
   (например «Отпуска: сервер») → **Развернуть**.
   URL веб-приложения НЕ меняется.

Фронтенд уже на v530 (Ctrl+Shift+R вы уже сделали) — больше на
стороне сайта ничего делать не нужно.

### Если Task 281 не выполнялся

Если в проекте ещё **не** заменён `VacationsInit.gs` (инструкция
DEPLOY-Task281) — заменить его тоже
(`download/kip8test/VacationsInit.gs` → Ctrl+S) и запустить:
редактор → выбрать функцию `vacationsInitSheet` → ▶ Run
(БЕЗ force). Скрипт идемпотентен: данные в «Отпуска» не трогает,
только чинит шапку/форматы/валидации.

## Проверка после деплоя

1. Приложение → «График работы → Отпуска» — список сотрудников
   загружается, у заданных периодов — части с датами и итогом
   («28 дн. · 3 части»), сводка «N из M сотрудников».
2. «+ Добавить отпуск» → сотрудник, даты → «Добавить»:
   - успех: диалог закрывается, тост «Отпуск добавлен…», строка
     в списке;
   - при ошибке — виден тост с пояснением (например «Период
     пересекается…», если период уже введён вручную в таблице).
3. «Сформировать» в шахматке — «О» на днях отпуска.

Если после деплоя появится другая «Ошибка: …» — пришлите её текст
в чат: теперь любая ошибка видна и диагностируется точно.

## Откат

Вернуть прежние `Code.gs` / `WorkSchedule.gs` в редакторе и снова
«Новая версия». Замена файлов не меняет данные в Google Таблице —
лист «Отпуска» и все строки остаются как есть.
