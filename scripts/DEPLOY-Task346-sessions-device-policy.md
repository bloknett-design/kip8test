# DEPLOY Task 346 — Политика сессий «1 моб + 1 десктоп» на почту

**Заявка (2026-09-08):** «у пользователей должна быть возможность с одной
почты заходить и параллельно работать в двух приложениях, в мобильном и
десктопном. Чтобы при входе, допустим, в мобильное приложение, затем он мог
с этой же почтой войти в десктопное приложение и при этом не было запрета
с формулировкой, что пользователь уже вошел. Но не больше двух входов с
одной почты, и только один вход в мобильное приложение, а другой вход с
этой же почтой в десктопное приложение.»

**Состав активации — 3 правки в Apps Script (~15 минут):**
1. новый файл `SessionsDevicePolicy.gs`;
2. `Auth.gs` — 4 правки (или замена целиком готовым патченным файлом);
3. `Code.gs` — 1 строка в роутере.
Плюс разовый запуск `sdpInit` и публикация «Новая версия».

**⚠️ Главное открытие при сверке с живым кодом (08.09.2026):** в живом
`Auth.gs` оказались ДВЕ блокировки «С этого аккаунта уже выполнен вход.
Обратитесь к администратору…» — в `sendOTP` (при запросе кода) и в
`verifyOTP` (при верификации). Это ровно тот запрет «пользователь уже
вошел» из заявки: клиент Task 346 и SessionsDevicePolicy сами по себе его
НЕ снимали — без правки Auth.gs вход во второе приложение по-прежнему
отваливался бы на запросе OTP. Патч убирает обе блокировки (лимит входов
теперь обеспечивает политика вытеснения), сохраняя полезную
самосинхронизацию `login_status` при отсутствии активных сессий.

**Что уже сделано на клиенте (PWA kip8test/kip8, Task 346):**
`KipAuth.verifyOTP` шлёт в payload поле `device` (`'mobile'` — мобильный
UA, `'desktop'` — Electron-десктоп или браузер на ПК); при `evicted > 0`
показывает тост «Вход выполнен. Прежний вход в … приложении с этой почтой
завершён.»; в админ-панели у сессий бейдж «моб»/«десктоп». Старый сервер
(без этого деплоя) поле игнорирует — всё работает как раньше.

## Шаг 1. Добавить файл SessionsDevicePolicy.gs

1. Открыть **Apps Script Editor** проекта KIP8_Access
   (script.google.com — тот же проект, где `Code.gs`/`RoleMatrix.gs`;
   развёртывание AKfycbyt…/exec).
2. Слева «Файлы» → **+** → «Скрипт» → назвать `SessionsDevicePolicy`.
3. Вставить код из репозитория `scripts/SessionsDevicePolicy.gs`
   (kip8test и kip8 идентичны). Сохранить (Ctrl+S).
4. В выпадающем списке функций вверху выбрать **`sdpInit`** → **Run** (▶).
   Один раз: добавит заголовок `device` в r4 колонку G листа `sessions`.
   Повторный запуск безвреден («уже есть»).

## Шаг 2. Обновить Auth.gs (4 правки или замена целиком)

**Вариант А (рекомендую):** открыть файл `Auth` в редакторе и заменить его
содержимое целиком готовым патченным `scripts/Auth.gs` из репозитория —
это ваш живой код + все 4 правки разом (синтаксис проверен; письмо с
OTP-кодом не тронуто). Перед заменой сверьте, что ваш текущий `Auth.gs` совпадает с
тем, из которого делался патч (сигнатуры: `sendOTP: function(rawEmail)`,
`verifyOTP: function(rawEmail, code)`).

**Вариант Б — точечные правки:**

**2.1. Сигнатура verifyOTP (3-й аргумент payload):**
```js
// БЫЛО:
  verifyOTP: function(rawEmail, code) {
// СТАЛО:
  verifyOTP: function(rawEmail, code, payload) {
```

**2.2. sendOTP — УБРАТЬ блок «уже выполнен вход»** (заявка прямо
запрещает этот отказ). Блок вида:
```js
// БЫЛО (удалить ветку с throw):
    if (user.login_status === 'вход выполнен') {
      // … комментарий про рассинхронизацию …
      const hasActive = Utils.userHasActiveSession(user.ID);
      if (hasActive) {
        Utils.audit(email, 'LOGIN_BLOCKED_DUPLICATE', ip, ua, 'Already logged in (active session exists)');
        throw new Error('С этого аккаунта уже выполнен вход. Обратитесь к администратору для сброса.');
      } else { /* сброс login_status */ }
    }
// СТАЛО (только самосинхронизация; активная сессия — НЕ блок, это
// параллельный вход в другое приложение, лимит применит политика):
    if (user.login_status === 'вход выполнен'
        && !Utils.userHasActiveSession(user.ID)) {
      Utils.updateUserStatus(user.row, 'вход не выполнен', user.last_login);
      Utils.audit(email, 'LOGIN_STATUS_AUTO_RESET', ip, ua,
        'login_status was "вход выполнен" but no active session found — auto-reset');
      user = Utils.findUserByEmail(email);
    }
```

**2.3. verifyOTP — УБРАТЬ такой же блок** после `Utils.markOtpUsed(otp.row);`
(«Ещё раз проверить login_status…», throw `LOGIN_BLOCKED_DUPLICATE`) —
заменить на аналогичную конструкцию без throw:
```js
    let freshUser = Utils.findUserByEmail(email);
    if (freshUser.login_status === 'вход выполнен'
        && !Utils.userHasActiveSession(freshUser.ID)) {
      Utils.updateUserStatus(freshUser.row, 'вход не выполнен', freshUser.last_login);
      Utils.audit(email, 'LOGIN_STATUS_AUTO_RESET', ip, ua,
        'login_status was "вход выполнен" but no active session — auto-reset (during verify)');
      freshUser = Utils.findUserByEmail(email);
    }
```

**2.4. Политика после создания сессии + evicted в ответе:**
```js
    // Создать сессию
    const session = Sessions.createSession(freshUser);

    // Task 346: политика «1 моб + 1 десктоп» (SessionsDevicePolicy.gs).
    const t346device = (payload && payload.device) ? String(payload.device).toLowerCase() : '';
    let t346evicted = 0;
    if (typeof sdpApplyDevicePolicy === 'function') {
      const t346policy = sdpApplyDevicePolicy(email, t346device, session.token);
      if (t346policy && t346policy.evicted) {
        t346evicted = t346policy.evicted;
      }
    } else {
      console.warn('Task 346: sdpApplyDevicePolicy не найдена — SessionsDevicePolicy.gs не подключён?');
    }
```
и в `return` (в конце verifyOTP) добавить поле:
```js
    return {
      token: session.token,
      role: freshUser.role,
      userId: freshUser.ID,
      email: email,
      evicted: t346evicted   // Task 346: >0 — вытеснен прежний вход того же типа
    };
```
Guard `typeof sdpApplyDevicePolicy === 'function'` — страховка от
порядка шагов: если Шаг 1 пропущен, вход работает как раньше (без лимитов),
а не падает. `evicted` в audit `LOGIN_SUCCESS` — по желанию (есть в
готовом патче).

**2.5. Админ-панель:** если `Admin.listSessions` строит объекты сессий
вручную по списку полей — добавить `device` (колонка G), чтобы появились
бейджи «моб»/«десктоп». Если объекты строятся по заголовкам листа — ничего
делать не нужно.

## Шаг 3. Code.gs — роутер, передать payload (1 строка)

**Зачем:** все запросы приложений приходят в функцию `doPost` в файле
**Code.gs**. Она разбирает JSON запроса в переменную `payload` и по полю
`action` вызывает нужный модуль. Сейчас для входа (`verifyOTP`) она
передаёт только email и код — поле `device`, которое присылает приложение,
**выбрасывается**. Новый Auth.gs читает `payload.device`; без этой правки
он видит `undefined` → политика молча пропускается: входы без лимита,
device в лист не пишется, вытеснения/тостов/бейджей нет.

**Порядок действий:**
1. Открыть редактор: script.google.com → проект KIP8_Access (тот же, где
   правили Auth.gs и добавляли SessionsDevicePolicy.gs).
2. Слева в списке «Файлы» выбрать **Code.gs** — файл с функцией `doPost`.
3. Ctrl+F → искать `verifyOTP` — первое вхождение внутри большого
   `switch (action)`, рядом кейсы `sendOTP`/`getCurrentUser`/`heartbeat`.
4. В кейсе `verifyOTP` добавить третий аргумент `payload` (и больше НИЧЕГО
   в файле не менять):
```js
// БЫЛО:
      case 'verifyOTP':
        result = Auth.verifyOTP(payload.email, payload.code);
        break;
// СТАЛО:
      case 'verifyOTP':
        result = Auth.verifyOTP(payload.email, payload.code, payload);
        break;
```
5. Сохранить: Ctrl+S (функции запускать не нужно — код компилируется
   при публикации).
6. **Опубликовать ЕЩЁ ОДНУ версию** — код изменился, та версия, что уже
   опубликована, роутер без правки: Развернуть → Управление
   развёртываниями → то же развёртывание (AKfycbyt…) → карандаш
   «Изменить» → Версия: «Новая версия» → Развернуть. URL не меняется.

**Частые ошибки:**
- править `case 'verifyOTP'`, а не `sendOTP` и не что-то ещё;
- запятая между `payload.code` и `payload`, закрывающая скобка после;
- забыть про п.6 — без новой публикации приложения продолжат получать
  старую версию (развертывание привязано к номеру версии);
- если живой Code.gs выглядит иначе (другие кейсы рядом) — ориентир один:
  строка `result = Auth.verifyOTP(...)` внутри `case 'verifyOTP':`.

**Признак «не применилось»:** после входа в приложении у новой строки
листа `sessions` колонка device (G) пустая — значит роутер не передал
payload или версия не опубликована.

## Шаг 4. Опубликовать новую ВЕРСИЮ (не развёртывание!)

⚠️ **Только «Управление версиями» → «Новая версия»** — как в Task 284:
«Новое развёртывание» сменит URL `/exec`, и приложения пойдут мимо
сервера. Текущее развёртывание AKfycbyt…/exec остаётся тем же.

## Шаг 5. Проверка

1. В Apps Script Editor: выбрать `sdpDebug` → Run — в `deviceColumn`
   не должно быть «ОТСУТСТВУЕТ».
2. Войти в **мобильной** PWA → лист `sessions`: у новой строки
   `device` = `mobile`.
3. Войти с той же почтой в **десктопном** приложении → **ошибки
   «С этого аккаунта уже выполнен вход» быть НЕ должно**; новая строка
   `device` = `desktop`, мобильная строка на месте (параллельная работа).
4. Войти с той же почтой **ещё раз в мобильном** (другой телефон/
   переустановка) → прежняя мобильная строка исчезает (вытеснение),
   в приложении тост «Прежний вход в мобильном приложении … завершён»,
   десктопная сессия не тронута. На старом устройстве через ≤5 минут
   (heartbeat) — штатное «Сессия истекла».
5. Админ-панель → Сессии: бейджи «моб»/«десктоп» у строк с device.

---

**Как это работает / отказоустойчивость:**

| Ситуация | Поведение |
|---|---|
| Вход моб → вход десктоп (та же почта) | ✅ всегда разрешено (блок «уже вошел» удалён из Auth.gs), обе сессии живут параллельно |
| Вход моб → вход моб (второй телефон) | старая моб-сессия закрывается (evicted=1), новая работает |
| Инвариант | ≤1 активная `mobile` + ≤1 активная `desktop` на почту = не больше двух входов |
| Запрос кода (sendOTP) при активной сессии | ✅ код отправляется как обычно (раньше — отказ «уже выполнен вход») |
| Старый клиент (без поля device) | политика пропускается, вход как раньше; строка без device уйдёт со штатной очисткой (hourlyCleanup) |
| Ошибка (нет листа/колонки, сбой) | fail-open: вход НЕ блокируется, ошибка — в лог Executions |
| Шаг 1 пропущен (нет SessionsDevicePolicy.gs) | guard `typeof` в Auth.gs — вход работает без лимитов, warning в лог |
| Смена device-колонок/заголовков | индексы ищутся по заголовку r4 динамически (как RoleMatrix) |

**Откат:** в `Code.gs` вернуть вызов без `payload`; в `Auth.gs` удалить
вызов `sdpApplyDevicePolicy` и поле `evicted` (клиентские поля безвредны);
при необходимости вернуть блокировки `LOGIN_BLOCKED_DUPLICATE` (но это
снова запрет параллельного входа из заявки). Файл
SessionsDevicePolicy.gs можно удалить целиком; колонку `device` оставить.
