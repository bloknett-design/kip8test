# DEPLOY Task 346 — Политика сессий «1 моб + 1 десктоп» на почту

**Заявка (2026-09-08):** «у пользователей должна быть возможность с одной
почты заходить и параллельно работать в двух приложениях, в мобильном и
десктопном. Чтобы при входе, допустим, в мобильное приложение, затем он мог
с этой же почтой войти в десктопное приложение и при этом не было запрета
с формулировкой, что пользователь уже вошел. Но не больше двух входов с
одной почты, и только один вход в мобильное приложение, а другой вход с
этой же почты в десктопное приложение.»

**Что уже сделано на клиенте (PWA kip8test/kip8, Task 346):**
`KipAuth.verifyOTP` теперь отправляет в payload поле `device`
(`'mobile'` — мобильный User-Agent, `'desktop'` — Electron-десктоп или
браузер на ПК); при ответе сервера с `evicted > 0` показывает тост
«Вход выполнен. Прежний вход в … приложении с этой почтой завершён.»;
в админ-панели у сессий появился бейдж «моб»/«десктоп». Старый сервер
(без этого деплоя) поле игнорирует — всё продолжает работать как раньше.

**Серверная часть — ДВА шага в Apps Script (10 минут):**

---

## Шаг 1. Добавить файл SessionsDevicePolicy.gs

1. Открыть **Apps Script Editor** проекта KIP8_Access
   (script.google.com — тот же проект, где `Code.gs`/`RoleMatrix.gs`;
   развёртывание AKfycbyt…/exec).
2. Слева «Файлы» → **+** → «Скрипт» → назвать `SessionsDevicePolicy`.
3. Вставить код из репозитория `scripts/SessionsDevicePolicy.gs`
   (kip8test и kip8 идентичны). Сохранить (Ctrl+S).
4. В выпадающем списке функций вверху выбрать **`sdpInit`** → **Run** (▶).
   Один раз: добавит заголовок `device` в r4 колонку G листа `sessions`.
   Повторный запуск безвреден («уже есть»).

## Шаг 2. Вызвать политику в Auth.verifyOTP (2 строки)

В файле, где живёт объект `Auth` (ввод OTP/создание сессии):

1. Найти в **`Auth.verifyOTP`** место, где после успешной проверки кода
   **создаётся новая сессия** (запись строки в лист `sessions` — токен,
   user_id, email, role, created_at, last_heartbeat) и готовится
   успешный ответ клиенту (`token, role, userId, email`).
2. Сразу ПОСЛЕ создания сессии (перед `return` успешного результата)
   добавить (имена `email`/`token` подставьте те, что используются в
   вашем коде в этом месте; `payload` — аргумент с полями запроса):

   ```js
   // Task 346: политика «1 моб + 1 десктоп» (SessionsDevicePolicy.gs).
   var _t346device = (payload && payload.device) ? String(payload.device).toLowerCase() : '';
   var _t346policy = sdpApplyDevicePolicy(email, _t346device, token);
   ```

3. В `data` успешного ответа добавить поле (для тоста в приложении):

   ```js
   evicted: _t346policy.evicted || 0
   ```

4. Если `Admin.listSessions` формирует объекты сессий вручную по списку
   полей (token/email/role/created_at/last_heartbeat) — добавить туда
   `device` (значение колонки G), чтобы в админ-панели появился бейдж
   «моб»/«десктоп». Если объекты строятся по заголовкам листа — ничего
   делать не нужно, поле подтянется само.

## Шаг 3. Опубликовать новую ВЕРСИЮ (не развёртывание!)

⚠️ **Только «Управление версиями» → «Новая версия»** — как в Task 284:
«Новое развёртывание» сменит URL `/exec`, и приложения пойдут мимо
сервера. Текущее развёртывание AKfycbyt…/exec остаётся тем же.

## Шаг 4. Проверка

1. В Apps Script Editor: выбрать `sdpDebug` → Run — в колонке
   `deviceColumn` не должно быть «ОТСУТСТВУЕТ».
2. Войти в **мобильной** PWA → в таблице KIP8_Access лист `sessions`:
   у новой строки в колонке `device` = `mobile`.
3. Войти с той же почтой в **десктопном** приложении → новая строка
   `device` = `desktop`, мобильная строка на месте (параллельная работа).
4. Войти с той же почтой **ещё раз в мобильном** (другой телефон/пере
   установка) → прежняя мобильная строка исчезает (вытеснение),
   в приложении тост «Прежний вход в мобильном приложении … завершён»,
   десктопная сессия не тронута. На старом устройстве через ≤5 минут
   (heartbeat) — штатное «Сессия истекла».
5. Админ-панель → Сессии: бейджи «моб»/«десктоп» у строк с device.

---

**Как это работает / отказоустойчивость:**

| Ситуация | Поведение |
|---|---|
| Вход моб → вход десктоп (та же почта) | ✅ всегда разрешено, обе сессии живут параллельно |
| Вход моб → вход моб (второй телефон) | старая моб-сессия закрывается (evicted=1), новая работает; запретов «уже вошли» нет |
| Инвариант | ≤1 активная `mobile` + ≤1 активная `desktop` на почту = не больше двух входов |
| Старый клиент (без поля device) | политика пропускается, вход как раньше; строка без device уйдёт со штатной очисткой expired-сессий (hourlyCleanup) |
| Ошибка (нет листа/колонки, сбой) | fail-open: вход НЕ блокируется, ошибка — в лог Executions |
| Смена device-колонок/заголовков | индексы ищутся по заголовку r4 динамически (как RoleMatrix) |

**Откат:** удалить вызов `sdpApplyDevicePolicy` из `Auth.verifyOTP`
(клиентские поля безвредны) — или весь файл SessionsDevicePolicy.gs.
Колонку `device` можно оставить.
