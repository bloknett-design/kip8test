## Что менялось (ТОЛЬКО фронтенд — index.html, sw.js, tests/, scripts/)

**Заявка пользователя:**
«В баре над шахматкой добавь второе окно с данными всех мероприятий на
открытый месяц, расположи это окно между кнопками и окном времени и
праздников, раздели бар на три равных части, для кнопок и двух окон.
Если текст в окнах не будет помещаться в одну строку, он должен
переноситься на строку ниже. При добавлении нового кода или мероприятия
в ячейки шахматки, помимо кнопки "Сохранить" должна появляться кнопка
"Отменить", для отмены ввода изменений. Кнопки "Сохранить" и "Отменить"
расположи под кнопками выбора месяца и года, кнопку "Сформировать"
ещё ниже, в третьей строке.»

### 1) Бар из ТРЁХ РАВНЫХ частей + окно мероприятий месяца
- `.ws-toolbar` → три строки:
  - **строка 1** — `.ws-bar-row` (новая): десктоп ≥1024px —
    `grid-template-columns: 1fr 1fr 1fr` (ТРИ РАВНЫЕ части):
    [кнопки (селекты + «Обновить» + штамп)] | [#wsEventsPanel —
    окно мероприятий месяца] | [#wsCalPanel — окно времени и
    праздников]. Ниже 1024px — колонка (кнопки сверху, оба окна под
    ними), окно мероприятий — во всю ширину.
  - **строка 2** — `.ws-actions-row` (#wsActionsRow): «Сохранить» +
    «Отменить» (появляются при вводе изменений);
  - **строка 3** — `.ws-generate-row` (#wsGenerateRow): «Сформировать».
- **#wsEventsPanel** (`.ws-events-panel`, 95px, скролл внутри,
  overscroll-behavior: contain): заголовок-плашка «Мероприятия ·
  {месяц} {год} · {N}» (зелёная) + строки «точка-цвет · диапазон дат ·
  код · тема · ФИО». Источник — лист «Инструктажи» (_TRAININGS):
  попадают записи, ПЕРЕСЕКАЮЩИЕ месяц (диапазоны «02.09», «02–05.09»,
  «29.09–02.10»); сортировка по дате начала, затем таб. номеру; пустой
  месяц — «нет мероприятий в этом месяце». Цвет точки — из
  «Коды_статусов» (как у бейджей ячеек). Заполняет
  `_renderMonthEventsPanel` (вызов из `_renderGrid` — смена месяца,
  загрузка данных, «Обновить», мутации).
- **ПЕРЕНОС текста** (заявка): `.ws-ep-item` — `white-space: normal` +
  `overflow-wrap: break-word` (дата «02–05.09» — nowrap, не рвётся);
  `.ws-cp-day` (чипы праздников) и `.ws-cp-item` (счётчики норм) —
  тоже normal. Горизонтального переполнения нет; при большом объёме —
  вертикальный скролл внутри окон.
- Прежняя компоновка Task 269/272 (кнопки слева, окошко справа на
  fit-content, order/align-self/margin-right: auto, nowrap) — удалена.
  `margin-left: auto` у «Сформировать» удалён (своя строка).
- Стиль окон — единый с календарём (Task 270): bg-tertiary, прямые
  углы, 95px; светлая тема — #e9e7de.

### 2) Кнопка «Отменить» (отмена ввода изменений)
- **#wsCancelBtn** (`.ws-cancel-btn`, приглушённо-красная, 34px) —
  в строке 2 рядом с «Сохранить». Появляется ВМЕСТЕ с «Сохранить»
  (при наличии локальных правок _PENDING и праве записи) —
  `_updateSaveBtn` показывает/скрывает обе кнопки и всю строку 2.
- **cancelAll()**: подтверждение kipConfirm (danger, «Отменить
  правки») → сброс ВСЕХ несохранённых правок (`_PENDING = {}`) →
  `_updateSaveBtn()` + `_renderGrid()` (ячейки возвращаются к
  серверным данным) → тост «Изменения отменены (N)». Блокируется во
  время пакетного сохранения (_saving).
- Мероприятия НЕ копятся локально (шторка отправляет их на сервер
  сразу при подтверждении) — несохранённого ввода мероприятий не
  бывает; отменить до подтверждения — кнопка «Отмена» шторки.
- init(): wsGenerateRow скрыта/показана по праву записи синхронно с
  wsGenerateBtn.
