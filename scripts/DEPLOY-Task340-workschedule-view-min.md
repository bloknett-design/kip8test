# DEPLOY — Task 340: трёхуровневый доступ к «Графику работы» (workschedule.view.min)

**Дата:** 07.09.2026. **Что менялось:** клиент (kip8test/kip8 — уже в index.html)
+ сервер Apps Script (по этой инструкции) + матрица KIP8_Access.

## Суть

В матрице KIP8_Access (лист matrix) у раздела «График работы» теперь ТРИ
столбца вместо двух:

| Право | Уровень | Поведение в приложении |
|-------|---------|------------------------|
| `workschedule.edit` | полный | Просмотр + внесение: окно выбора кодов, карточки с кнопками правки, «Сформировать», «Итоги учёта», «Вид» |
| `workschedule.view` | просмотр | Клик по ячейке → окно «Мероприятия в этот день» (окно кодов НЕ открывается). Клик по ФИО → карточка сотрудника БЕЗ элементов правки («Уволить…», «+ Отпуск…», ✎/✕ скрыты). Все кнопки доступны, кроме «Сформировать» |
| `workschedule.view.min` | ограниченный просмотр | Как view, но: карточка по ФИО НЕ открывается; скрыты «Сформировать» и «Итоги учёта»; в шахматке скрыты работники «Мастер КИПиА» |

Приоритет при нескольких галочках: `edit` сильнее всех; без edit флаг `min`
СИЛЬНЕЕ `view` («ограничение»: отмечены обе — действует ограниченный
уровень). Роль без трёх прав раздел не видит.

## Шаги деплоя (ПО РЯДУ — важно!)

### 1. Матрица: добавить столбец workschedule.view.min

Открыть Apps Script (script.google.com, проект развёртывания AKfycbyt…),
вставить файл `scripts/RoleMatrixTask340Init.gs` (из репозитория), выполнить
функцию `task340AddViewMinPermission`. Скрипт идемпотентен:

- добавит колонку `workschedule.view.min` в лист matrix (r4 = perm_id,
  r5 = название, чекбоксы; все галочки сняты, «Админ» отмечен);
- добавит строку-справочник в лист permissions;
- допишет метку версии в matrix!A3;
- сбросит кэш матрицы (если RoleMatrix.gs в том же проекте).

Можно и руками: колонка после `workschedule.edit`, строка 4 =
`workschedule.view.min`, строка 5 = `График работы — ограниченный просмотр`,
формат ячеек ролей — чекбокс.

### 2. Сервер: новая версия WorkSchedule.gs

В том же проекте Apps Script заменить функцию `_requireRead` в
`WorkSchedule.gs` на версию из `scripts/WorkSchedule.gs` репозитория
(маркер: комментарий `Task 340 (трёхуровневый доступ)`). Суть: чтение
пускают ЛЮБОЕ из трёх прав (view / view.min / edit) — иначе роль с одним
`workschedule.view.min` получит `access_denied` и раздел не откроется.

Опционально: обновить `RoleMatrixGate.gs` (rmGateStatus теперь показывает
колонку M = workschedule.view.min — диагностика).

Затем: **«Осуществить развёртывание» → «Новое развёртывание»** (тип
«Веб-приложение», как обычно; один деплой на kip8 и kip8test).

### 3. Галочки в таблице (KIP8_Access → лист matrix)

- «КИП ИОС дежурный» (ограниченный просмотр): отметить
  `workschedule.view.min`. Если стоит `workschedule.view` — можно снять
  (не обязательно: min сильнее, но чище одна галочка).
- Роли с обычным просмотром: `workschedule.view`.
- Роли с полным доступом: `workschedule.edit`.
- «Админ»: все права (выдаются сервером автоматически).

Проверка: `rmGateStatus()` в редакторе — колонка M = workschedule.view.min.

## Когда что подхватится

- Серверные гейты — сразу после нового развёртывания (+ сброс кэша
  скриптом или ≤5 мин TTL).
- Клиент (kip8test kipia-test-v578 / kip8 kipia-v425) — после
  Ctrl+Shift+R ×1–2; уровень пересчитывается при входе/загрузке/heartbeat
  (≤ ~10 мин).

## Если что-то пошло не так

- Раздел «молчит»/пустой у роли с `workschedule.view.min` → шаг 2 не
  выполнен (старый `_requireRead` пускает только по view) — проверьте,
  что развёртывание создано ПОСЛЕ правки WorkSchedule.gs.
- Роль видит карточки, хотя должна быть «min» → у роли отмечены ОБЕ
  галочки? Нет — min сильнее; проверьте, что клиент обновился
  (v578/v425), и что в getMyAccess приходит `workschedule.view.min`.
