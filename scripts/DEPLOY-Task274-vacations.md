## 1. Лист «Отпуска» в Google Таблице — АВТОМАТИЧЕСКИ (Task 275)

Таблица: табель_КИП_ИОС (SPREADSHEET_ID `1MQtW-CWCmjlu-SAeVBllKDP6NRkiOkmW-7xgOjHskWY`).
Лист создаётся скриптом `scripts/VacationsInit.gs` — вручную ничего
строить не нужно:

1. Скопировать `scripts/VacationsInit.gs` в проект Apps Script табели
   (тот же проект, где `Code.gs`, `Utils.gs`, `WorkSchedule.gs`).
2. В редакторе выбрать функцию `vacationsInitSheet` → ▶ Run
   (первый запуск попросит авторизацию — разрешить).
3. В логе (Ctrl+Enter) должно быть «Лист «Отпуска» готов».

Скрипт идемпотентен и безопасен: создаёт лист «Отпуска» с шапкой
A1–F1, форматированием (синяя шапка, закрепление строки 1, ширины
столбцов, формат дат `dd.mm.yyyy`), валидациями (C — целое 1..3,
B — выпадающий список табельных номеров из «Сотрудники») и
подсветкой красным пересекающихся периодов одного сотрудника.
Повторный запуск данные НЕ трогает (только чинит шапку/формат).
`vacationsInitSheet(true)` — полная перестройка (данные удаляются).

Для быстрой проверки после деплоя: `vacationsSeedDemo()` —
демо-периоды 017 (3 части, 28 дн.) и 023 (1 часть) на пустой лист.

Структура листа (строка 1 — шапка, данные со строки 2):

| Ячейка | Заголовок | Формат данных |
|--------|-----------|---------------|
| A1 | `id` | число (присваивает приложение, auto-increment) |
| B1 | `таб_номер` | текст, FK на «Сотрудники» |
| C1 | `часть` | число 1–3 (отпуска делятся на 2–3 части в год) |
| D1 | `дата_начала` | дата |
| E1 | `дата_окончания` | дата |
| F1 | `комментарий` | текст (до 500 символов) |

Данные со строки 2, по одной строке на ЧАСТЬ отпуска. Пример
(сотрудник делит отпуск на 3 части — 14+10+4 = 28 дн.):

| id | таб_номер | часть | дата_начала | дата_окончания | комментарий |
|----|-----------|-------|-------------|----------------|-------------|
| 1 | 017 | 1 | 01.06.2026 | 14.06.2026 | основная часть |
| 2 | 017 | 2 | 03.08.2026 | 12.08.2026 | |
| 3 | 017 | 3 | 19.10.2026 | 22.10.2026 | |
| 4 | 023 | 1 | 15.06.2026 | 28.06.2026 | |

Важно:
- **id можно не заполнять** — приложение присвоит его при добавлении
  через форму (max id + 1). Task 279: строки и с ПУСТЫМ id корректно
  читаются (id: null, кнопка «Удалить» скрыта); перезапуск
  `vacationsInitSheet()` дозаполнит id автоматически.
- Даты: Task 279 — WorkSchedule.gs парсит и ТЕКСТОВЫЕ даты
  («10.08.2026», «2026-08-10», «10.08.26»); перезапуск
  `vacationsInitSheet()` конвертирует текстовые даты в настоящие
  даты Google Таблиц (самолечение данных).
- Пересечения периодов одного сотрудника и дубли «части» в одном
  году не допускаются (сервер отклонит; при ручном редактировании
  пересечения подсвечиваются красным — настройка VacationsInit.gs).
- См. также scripts/DEPLOY-Task279-vacations-fix.md (hotfix чтения
  отпусков: пустой id / текстовые даты / счётчики в тосте).

## 2. Apps Script

1. Открыть проект Apps Script табели (там же, где `Code.gs`,

2. `WorkSchedule.gs` — заменить содержимое на `scripts/WorkSchedule.gs`

   `generateMonth` (отпуска — высший приоритет среди авто-источников),
   удаление устаревших авто-«О», поле `removed` в ответе.

4. Деплой: Deploy → Manage deployments → ✏️ Edit → Version: New

## 3. Проверка (в приложении, роль «Админ»)

1. График работы → субнавигация «Отпуска» → страница «Отпуска»:
   список сотрудников, у заданных — части с датами и итогом дней
   (например «28 дн. · 3 части»), сводка «N из M сотрудников».
2. «+ Добавить отпуск»: выбрать сотрудника → «часть» подставится
   первым свободным номером; даты → «Период: N кал. дн.»; Добавить →
   тост «Отпуск добавлен. Нажмите «Сформировать»…», строка в списке.
   Пересекающийся период отклоняется (клиент + сервер).
3. Шахматка: пустые ячейки внутри периодов показывают «О» с
   пунктирной рамкой (план, tooltip «ОТПУСК (план…)»).
4. «Сформировать» (год) → в месяцы периодов проставятся записи
   «О» (источник «авто», tooltip), плановая пунктирная рамка исчезнет
   (ячейка стала записью). Существующие ручные правки не тронуты.
5. Изменить период в «Отпуска» (удалить часть, добавить другую) →
   «Сформировать» снова → старые авто-«О» сняты, новые проставлены
   (идемпотентность; в тосте — «удалено N устаревших отпусков»).
6. Приоритет при совпадении дней: ручная правка > отпуск >
   инструктаж > плановая смена.

## Поведение после деплоя

- `workSchedule.listVacations` (чтение, роль Админ): периоды,
  пересекающие выбранный год; период 29.12–11.01 попадает в оба года,
  дни считаются по году отдельно.
- `workSchedule.addVacation` (запись): валидация — часть 1..3,
  конец ≥ начала, отсутствие пересечения с периодами сотрудника,
  уникальность «части» в году начала; аудит
  WORKSCHEDULE_ADD_VACATION.
- `workSchedule.deleteVacation` (запись): удаление строки по id;
  аудит WORKSCHEDULE_DELETE_VACATION.
- `workSchedule.generateMonth`: дни периодов в месяце получают
  «О» (авто) на пустые дни и дни авто-смен/инструктажей; ручные
  записи не меняются; авто-«О» вне текущих периодов удаляются
  (сверху вниз, после вставок/обновлений).

оставить — до деплоя он не читается.
