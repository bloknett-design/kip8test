## 3. СЕРВЕР Apps Script — ОБЯЗАТЕЛЬНО ОБНОВИТЬ (иначе «Уволить» даст ошибку)

Новый маршрут **`workSchedule.dismissEmployee`**:

- `payload: { token, таб_номер, дата_увольнения (ISO «ГГГГ-ММ-ДД») }`
- право записи `workschedule.edit` (как addEmployee — `_requireWrite`);
- в листе «Сотрудники» находит строку по таб_№ (A — текст, ведущие
  нули) и пишет: **H = дата_увольнения, I = в_архиве = 1**; строка НЕ
  удаляется (архив); повторный вызов перезапишет дату (идемпотентно);
- аудит `WORKSCHEDULE_DISMISS_EMPLOYEE`; ошибки:
  `invalid_таб_номер` / `invalid_дата_увольнения` / `not_found_таб_номер`.

Колонки H/I в листе «Сотрудники» СУЩЕСТВОВАЛИ с самого начала
(структура листа не меняется) — сервер только учится их писать.
`listEmployees` без `includeArchived` уже скрывает архив (архивная
логика чтения была готова) — увольнение «выключает» сотрудника из
шахматки/селектов.
