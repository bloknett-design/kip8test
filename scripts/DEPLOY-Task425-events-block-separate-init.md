# Task 425 — мероприятия: свои отдельные страницы, инструктажи не трогаем

**Заявка (kip8test):** «Подожди, мне не нужно объединять инструктажи и
мероприятия, инструктажи менять не нужно, а для мероприятий нужно
создать свои отдельные страницы, так же нужно проверить что бы они
не влияли друг на друга в приложении. Потому что это совершенно
разные по информационному наполнению блоки. Главное отличие, новые
инструктажи формируются автоматически в зависимости от предыдущих,
а мероприятия каждый раз вносятся вручную и без автоматического
продления, потому что у них нет закономерности, это как правило не
плановые мероприятия, и по большей части фиксирующие уже случившееся
события».

## Что изменилось (переработка Task 424)

**Сервер `scripts/WorkSchedule.gs`** — ДВА изменения:

1. **`eventsInit` — теперь ТОЛЬКО «Мероприятия»** (главное, заявка):
   - создаёт **лист «Мероприятия»** (id / таб_номер / тип / тема /
     дата_начала / дата_окончания / длительность_дней /
     комментарий), если его нет, — это **своя отдельная страница
     блока** и одновременно **постоянный архив** (строки не
     удаляются, годовые архивы карточки читают все записи);
   - **«Инструктажи» НЕ создаётся и НЕ изменяется, строки НЕ
     переносятся** (в Task 424 eventsInit создавал оба листа и
     переносил легаси-строки обучение/прогул/примечание из
     «Инструктажей» — именно это выглядело как объединение блоков);
   - идемпотентно; отчёт
     `{ ok, sheets: { "Мероприятия": "created" | "existing" } }`;
   - существующий лист «Мероприятия» не перезаписывается.
   Функция `trainingsSplitInit` (перенос строк) осталась в коде
   как отдельный ручной инструмент, но из `eventsInit` больше НЕ
     вызывается — по умолчанию данные «Инструктажей» не трогаются.

2. **Стоп-правило «мероприятия — без автопродления»** (независимость
   блоков): в `_autoCreateNextTrainings` добавлена проверка типа
   отмечаемой строки — если это обучение/прогул/примечание
   (легаси-строки прежней объединённой таблицы могли остаться в
   «Инструктажах»), отметка выполнения фиксируется, но **новых
   записей НЕ создаётся** (note: «автосоздания нет — вносится
   вручную, без продления»). Автосоздание новых сроков —
   **ТОЛЬКО у инструктажей** (правила Task 419..423 не тронуты:
   общий → 9-ОГЭ +3 мес + общий +6 мес — регресс покрыт тестами).

3. `srvVer` '423' → **'425'** (маркер нового сервера в ответе
   `setTrainingDone` — клиент молчит, предупреждение о старой
   версии остаётся для серверов < 423).

**Клиент `index.html` — БЕЗ ИЗМЕНЕНИЙ**: блоки в приложении и так
раздельны (Task 405/410 — «+ Мероприятие…» со списком
обучение/прогул/примечание и «+ Инструктаж…» со списком
«Список_И_и_ПЗ», блоки карточки фильтруются по типу). sync-to-desktop
НЕ запускался (index.html не тронут — корректно).

## ⚠ СЕРВЕРНЫЙ ШАГ пользователя (обязательно, 2 пункта)

1. Заменить `WorkSchedule.gs` в проекте Apps Script (табель_КИП_ИОС)
   на файл из репозитория `scripts/WorkSchedule.gs` и создать
   **НОВУЮ ВЕРСИЮ развёртывания** (Deploy → Manage deployments →
   Edit/New deployment). `Code.gs` / `instrListInit` / `PPEInit.gs`
   не менялись.
2. Если листа «Мероприятия» ещё нет в файле табель_КИП_ИОС —
   **один раз** запустить в редакторе Apps Script функцию
   **`eventsInit`** (выпадающий список функций → ▶ Run): создаст
   **только лист «Мероприятия»**, «Инструктажи» не тронет. Если
   лист уже есть (создавался первой записью addTraining — Task
   405/413) — запуск не обязателен (вернёт `existing`), но и не
   вреден. Результат — в журнале (Ctrl+Enter):
   `eventsInit: {"ok":true,"sheets":{"Мероприятия":"existing"}}`.
   Повторный запуск безопасен.

**Подтверждение нового сервера:** после отметки выполнения
инструктажа в консоли браузера (F12) — `[инструктажи] автосоздание:`
с разбором; сервер Task 425 отличает ответ `srvVer: '425'`
(виден там же в объекте ответа / сетевом логе).
