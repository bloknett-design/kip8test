## 2. Дубли строк hozraschet_archive (сервер, Apps Script) — ⚠️ ТРЕБУЕТСЯ «Новая версия»

**Причина дублей:** Apps Script выполняет запросы **параллельно**, а архив пишется
`appendRow` без проверок. Повторная доставка ОДНОГО показания — нормальная ситуация:
- outbox ретраит запись после потерянного ответа (сеть),
- `sendBeacon` «последнего шанса» летит рядом с ещё живым fetch'ем при закрытии вкладки,
- два окна приложения флашат общий localStorage независимо.

Каждая такая доставка дописывала строку — «иногда один раз, иногда несколько раз подряд».

**Решение (FlowmeterArchive.gs):**
- `appendToArchive` выполняется под `Utils.withLock` (Task 348) — атомарная пара
  «прочитал хвост → дописал»: две доставки одного показания больше не проходят проверку
  одновременно.
- Дедуп: запись с тем же ключом **meterId (A) + prev (C) + curr (D) + dateCurr (G) +
  entryType (R)** среди последних 50 строк архива — НЕ дописывается (`Archive (Task 366):
  дубль пропущен`). У повтора payload идентичен → ключ совпадает полностью; разные
  показания расходятся хотя бы одним полем. Правка в окне 1 ч идёт через
  `updateLatestReading` (на месте) — её дедуп не касается. Legacy-строки без R (до
  Task 286) трактуются как «сутки».
- Сбой проверки (лист глючит) = «не дубль» → запись идёт: лучше редкий дубль, чем
  потерянная запись.
- `server_busy` при таймауте замка → клиент повторяет (см. п.1).

**Деплой серверной части (руками, один раз):**
1. Открыть проект Apps Script (тот же, что Flowmeter.gs / Code.gs).
2. Заменить содержимое файла `FlowmeterArchive.gs` на версию из репо
   (kip8test `scripts/FlowmeterArchive.gs`, коммит Task 366).
3. «Развернуть» → «Новое развертывание» / «Управление развертываниями» → «Изменить» →
   версия «Новая» → «Развернуть».
4. Проверка: ввести показание и быстро закрыть/обновить страницу — в
   `hozraschet_archive` должна появиться ОДНА строка.

**Откат:** вернуть прежний `FlowmeterArchive.gs` тем же способом; клиент работает и со
старым сервером (дубли просто вернутся).
