## Что изменилось

### 1. Бейдж плановой смены — только у «сменных» (Task 305 → 306)

Бейдж плановой смены на днях отпуска (правый нижний угол, формат
мероприятия) теперь показывается **только сотрудникам с типом
«сменный»** (Д/Н по циклу). Дневные сотрудники (Д8/Д7,2) и работники
без типа бейдж **не показывают** — их день отпуска отображает только
код отпуска.

- Реализация: `_renderCell` → `empIsShift = String(emp['тип']||'').trim() === 'сменный'`
  входит в условие `vacMain` (фильтр только на отрисовке; сам расчёт
  `_plannedShiftAt` не зависит от типа — паритет с сервером сохранён).
- Пример живой таблицы: 2741 (Хадасевич, «сменный») — бейджи Д/Н на
  03,04,08,09,13,14,18,19.09; 0392 (Федосов, «дневной») — бейджей
  больше НЕТ (были «Д7,2» до Task 306).

### 2. ПР (прогул) и «*» (примечание) — новые типы мероприятий

В форме «Новое мероприятие» к типам инструктаж/обучение/проверка
знаний добавлены **прогул** (код ПР) и **примечание** (код `*`).

- Клиент: `_EVENT_CODES` = И/ОБ/ПЗ/ПР/`*`; `_trainingCodeOf`:
  прогул→ПР, примечание→`*`; `_renderTrainings` — единая карта,
  плашки ПР `#EF5350` и `*` `#FFAB91` (цвета справочника; CSS-селектор
  `*` через escape `.ws-type-\*`).
- Сервер `WorkSchedule.gs`: `TRAINING_TYPE_TO_STATUS` + прогул/примечание
  (addTraining принимает новые типы); `_isEventStatusCode` включает
  ПР и `*` → генерация пишет их на дни без смены (как И/ОБ/ПЗ), на
  сменных днях — бейдж; шаг 4.6 снимает устаревшие авто-строки ПР/`*`;
  **ручные** строки ПР/`*` (прогул/примечание через попап ячейки)
  не трогаются.
- Справочник «Коды_статусов»: **НЕ меняется** — ПР и `*` уже есть в
  живом листе (16 кодов, цвета совпадают).
- Приоритеты не изменились: ручная > отпуск > смена > мероприятие.

### 3. Кнопки «Обновить» + «Сформировать» → одна «Сформировать»

Кнопка «Обновить» (производственный календарь, Task 272) **удалена**
из тулбара вместе с диалогом `confirmRefresh`. Клик по
«Сформировать» → прежний диалог («Весь год» / «Текущий месяц») →
после подтверждения **параллельно** с серверной генерацией идёт
**тихое** обновление производственного календаря
(`WorkSchedule._refreshProdCalendarQuiet` → `ProdCalendar.refreshNow(true)`):
без диалога и тостов; сбой не мешает формированию — календарь
остаётся на офлайн-кэше (TTL 7 суток). Окошко норм в тулбаре
(`#wsCalPanel`) и фоновая автозагрузка календаря (Task 260) — как было.
