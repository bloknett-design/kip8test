# Task 295 — Этап 3: серверный шлюз прав (деплой и проверка)

## Что это

Матрица доступа **KIP8_Access** (Task 293/294) теперь — источник истины
не только «на бумаге», но и **на сервере**: права проверяются при
каждом запросе до вызова модулей.

| Файл | Что меняется |
|---|---|
| **RoleMatrixGate.gs** (НОВЫЙ) | центральный шлюз: токен → пользователь (Utils) → роль → матрица; каждый отказ — в audit_log (`RM_ACCESS_DENIED`); `getMyAccess` — карта прав для клиента; `rmGateStatus` — диагностика |
| **Code.gs** | гейт до модуля: `admin*` → право `admin.panel`; записи каб. журнала (`appendRow/updateRow/deleteRow`) → `cablejournal.edit`; новый action `getMyAccess` |
| **Flowmeter.gs** | `_requireRead`/`_requireEdit` → права `flowmeter.view` / `flowmeter.input` из матрицы (legacy-списки — запас) |
| **WorkSchedule.gs** | `_requireRead`/`_requireWrite` → права `workschedule.view` / `workschedule.edit` из матрицы (legacy-списки — запас) |

## Изменения поведения (осознанные, по вашей матрице Task 293)

1. **«ИТР8 pro» теперь ВИДИТ график работы** (просмотр). Ранее
   (Task 204) — только Админ. У вас в матрице `workschedule.view` у
   «ИТР8 pro» включён — это решение применено.
2. **«ИТР ИОС» теперь ВВОДИТ показания расходомеров** (`flowmeter.input`).
   Ранее — только «КИП ИОС дежурный» и Админ.
3. Запись графика (`workschedule.edit`) — по-прежнему только Админ.
4. Остальное совпадает со старыми списками.

Если это не нужно — снимите галочки в matrix (KIP8_Access), подождите
≤5 минут или вызовите `roleMatrixInvalidateCache()` в редакторе.

## Деплой (4 файла)

1. В проекте Apps Script создайте **RoleMatrixGate.gs** и вставьте код
   из репозитория (`scripts/RoleMatrixGate.gs`). Сохраните.
2. Замените содержимое **Code.gs** на версию из репозитория
   (`scripts/Code.gs`) — целиком.
3. Замените содержимое **Flowmeter.gs** и **WorkSchedule.gs** на версии
   из репозитория — целиком.
4. **Деплой → Manage deployments → ( AKfycbyt… ) → Edit → Version:
   New version → Deploy.** URL не меняется, клиент обновлять не нужно.

Порядок важен: RoleMatrixGate.gs вставляется ДО Code.gs (иначе между
сохранениями будет legacy-режим — это не страшно, но лучше сразу
правильно).

## Защита от частичного деплоя

Если RoleMatrix.gs/RoleMatrixGate.gs не вставлены, а Code.gs уже новый:
гейты **пропускаются** (сайт работает как до Этапа 3), в консоль
Executions падает предупреждение `[Code.gs] RoleMatrixGate.gs не
задеплоен…`. `getMyAccess` при этом возвращает понятную ошибку.

Flowmeter/WorkSchedule в этой ситуации работают по прежним спискам
ролей (READ_ROLES/INPUT_ROLES/… сохранены в коде как legacy-запас).

## Проверка после деплоя

1. В редакторе Apps Script запустите **`rmGateStatus`** — в журнале
   таблица «роль × ключевое право» (A=админ-панель, C=каб.журнал,
   F=расх.просмотр, I=расх.ввод, G=график.просмотр, W=график.запись;
   прописная = право есть). Сверьте с галочками в matrix.
2. Зайдите на сайт под обычным пользователем (не Админом) — админ-панель
   скрыта (как раньше); при попытке прямого вызова `adminListUsers` —
   `access_denied` (в логах — `RM_ACCESS_DENIED` с email и правом).
3. Под «ИТР8 pro»: раздел «График работы» открывается на просмотр
   (согласно матрице); кнопки записи вернут отказ.
4. Под «ИТР ИОС»: ввод показаний расходомеров работает.

## Как теперь менять права (без деплоев!)

Правка галочки в matrix → сервер применяет её в течение ≤5 минут
(кэш CacheService). Мгновенно — `roleMatrixInvalidateCache()` в
редакторе. Новый сотрудник: добавьте в users роль, которая есть в
matrix — права подхватятся сами.

## Если что-то пошло не так

- Все закрытые разделы стали недоступны ВСЕМ (включая Админа) →
  матрица не читается. Запустите `roleMatrixDebug` (RoleMatrix.gs) —
  покажет причину; проверьте лист matrix в KIP8_Access. Это fail-closed
  по дизайну: поломанная матрица = закрытый доступ, а не открытый.
- Роль пользователя «не проходит» → сверьте написание в `users!role`
  и `matrix!B` (`roleMatrixDebug` подсвечивает «РОЛИ НЕТ В MATRIX»).
- Мок-тест: `node scripts/task295-mock-test.js` (75 проверок; данные —
  реальные, сняты с таблицы; + регресс `task294-mock-test.js` 133/133,
  сьют репозитория 1324/0).
