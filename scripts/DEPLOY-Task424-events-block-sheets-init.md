# Task 424 — проработка блока «Мероприятия»: листы табель_КИП_ИОС + соответствие функционала

**Заявка (kip8test):** «Теперь необходимо проработать блок Мероприятия.
В мероприятиях должны выбираться из списка обучение/прогул/примечание,
и также вся информация должна архивироваться в архиве. Для этих целей
нужно создать листы в файле табель_КИП_ИОС, и проверить функционал
данного блока приложения на соответствие».

## Что уже было (аудит перед правками)

- **Форма «Новое мероприятие»** — поле «Тип» РОВНО список из трёх
  пунктов: обучение / прогул / примечание (Task 306 добавил, Task 410
  убрал из него инструктаж/проверку знаний — у «Инструктажей» свой
  вход «+ Инструктаж…» со строгим выбором пункта «Список_И_и_ПЗ»).
- **Маршрутизация по типу** — addTraining пишет обучение/прогул/
  примечание в лист «Мероприятия», инструктажи/ПЗ — в «Инструктажи»
  (Task 405); оба листа создаются автоматически при первом добавлении
  (Task 405/413 — если лист удалён вручную).
- **Архив** — лист «Мероприятия» хранит записи ПОСТОЯННО (ничего не
  чистится), `listTrainings.eventsAll` возвращает ВСЕ записи без
  фильтра года, карточка работника листает годы стрелками
  «Мероприятия · ‹год›» (Task 408).
- **Бейджи шахматки** — ОБ/ПР/* с тултипом «код — тема» (Task
  303/306/314/388); окно «Мероприятия · месяц» тулбара; колонка
  «Мероприятия · год» сводной «Общая» (Task 394/405).

Вывод аудита: клиентская функциональность блока заявке СООТВЕТСТВУЕТ
(проверено браузером 35/35 ниже). Отсутствовало одно — ГОТОВАЯ
ИНИЦИАЛИЗАЦИЯ ЛИСТОВ в файле табель_КИП_ИОС: до сих пор листы
создавались либо первой записью addTraining, либо переносом
`trainingsSplitInit` (имя неочевидное, падает без листа «Инструктажи»).

## Реализация

**Сервер `scripts/WorkSchedule.gs`** — НОВАЯ разовая функция
**`eventsInit`** (запуск из выпадающего списка функций редактора
Apps Script, как `instrListInit` / `trainingsSplitInit`; через API
приложения НЕ доступна):

1. создаёт лист **«Инструктажи»** с каноническими заголовками Task
   418 (id / таб_номер / тип / тема / дата_проведения / выполнение /
   просрочен / комментарий), если листа нет; **существующий лист НЕ
   трогается** (формат столбцов определяет `_trainingsSheetFormat`
   по заголовкам строки 1);
2. создаёт лист **«Мероприятия»** с каноническими заголовками
   (id / таб_номер / тип / тема / дата_начала / дата_окончания /
   длительность_дней / комментарий), если листа нет — это
   ПОСТОЯННЫЙ АРХИВ записей блока;
3. переносит строки обучение/прогул/примечание из «Инструктажей» в
   «Мероприятия» (легаси прежней объединённой таблицы —
   `splitTrainingsSheet` Task 405: id и значения сохраняются, связки
   Записи_графика не ломаются, done-формат конвертируется:
   дата_окончания = дата_проведения, длительность 1 день); листа
   «Инструктажи» нет — перенос пропускается (не ошибка);
4. идемпотентно: повторный запуск не трогает существующие листы и
   не находит строк к переносу (`moved: 0`); отчёт —
   `{ ok, sheets: {Инструктажи: created|existing, Мероприятия:
   created|existing}, moved, split }` + аудит
   `WORKSCHEDULE_EVENTS_INIT` + `Logger.log` (журнал Ctrl+Enter).

Обновлён док-блок структуры листа «Мероприятия» (архив, eventsInit).

## ⚠ СЕРВЕРНЫЙ ШАГ пользователя (обязательно, 2 пункта)

1. Заменить `WorkSchedule.gs` в проекте Apps Script (табель_КИП_ИОС)
   на файл из репозитория `scripts/WorkSchedule.gs` и создать
   **НОВУЮ ВЕРСИЮ развёртывания** (Deploy → Manage deployments →
   Edit/New deployment). `Code.gs` / `instrListInit` / `PPEInit.gs`
   не менялись.
2. **Один раз** запустить в редакторе Apps Script функцию
   **`eventsInit`** (выпадающий список функций → ▶ Run; первый запуск
   может попросить авторизацию): создаст листы «Инструктажи» /
   «Мероприятия» (если их нет — существующие не тронет) и перенесёт
   строки обучение/прогул/примечание из «Инструктажей» в «Мероприятия»
   (если таковые остались от прежней объединённой таблицы). Результат —
   в журнале выполнения (Ctrl+Enter), например:
   `eventsInit: {"ok":true,"sheets":{"Инструктажи":"existing",
   "Мероприятия":"created"},"moved":2,...}`.
   Повторный запуск безопасен. Далее листы создаются сами при
   добавлении записей — `eventsInit` больше не нужен.

**Лист «Мероприятия» и есть архив блока:** записи хранятся постоянно,
годовые архивы карточки читают их все (стрелки «‹ год ›»). Тип в
приложении выбирается списком: обучение / прогул / примечание.
