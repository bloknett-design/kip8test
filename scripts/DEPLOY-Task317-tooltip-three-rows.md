# Task 317 — Деплой: тултип «данные от…» кнопки «Обновить» + кнопки тремя рядами ровно в высоту окон

## Что менялось (ТОЛЬКО фронтенд — index.html, sw.js, tests/, scripts/)

**Суть (заявка пользователя):** строка «данные от…» убрана из бара —
живёт в информационном окне, которое появляется при наведении мыши на
кнопку «Обновить». Все кнопки бара собраны в ТРИ РЯДА, которые
занимают РОВНО высоту окон справа (95px); расстояние между рядами
кнопок — 3px; рамки бара — 5px со всех сторон и не изменяются.

### 1) Тултип «данные от…» (информационное окно кнопки «Обновить»)
- Штамп `#wsCacheStamp` (Task 314, стоял в ряду 1 и занимал место)
  УДАЛЁН вместе со стилем `.ws-cache-stamp`.
- Новое `#wsRefreshTip` (`.ws-refresh-tip`): fixed, z-index 9450
  (выше попапов ячеек 9401–9402), `pointer-events: none` — клики
  проходят сквозь, max-width 300px, `[hidden]` → display: none.
- Содержимое:
  - строка-дата «данные от 04.09, 14:22» — `#wsRefreshTipDate`
    (жирная, яркая): `_updateCacheStamp` пишет СВЕЖУЮ дату при каждом
    вызове; без данных — «локальных данных ещё нет»;
  - описание кнопки (бывший нативный `title`) — вторичная мелкая
    строка, переносится.
- ПОКАЗ: `mouseenter` (наведение) и `focus` (клавиатура). СКРЫТИЕ:
  `mouseleave` (уход курсора), `blur`, клик (через 120мс — итог
  обновления покажет тост) и ПРОКРУТКА (document-scroll в
  CAPTURE-фазе — ловит и скролл окон бара: fixed-позиция
  устаревает).
- ПОЗИЦИЯ: НАД кнопкой (`top − h − 8`); сверху < 4px — ПОД ней
  (`bottom + 6`); лево — по кнопке (минимум 6px).
- Нативный `title` кнопки УДАЛЁН (иначе два окна одновременно).
- `_updateCacheStamp`/`refreshData`/кэш — НЕ менялись (только адресат
  строки: `#wsRefreshTipDate` вместо удалённого `#wsCacheStamp`).

### 2) Кнопки — ТРИ РЯДА ровно в высоту окон (95px)
- Строки 2 (`.ws-actions-row` — «Сохранить»/«Отменить») и 3
  (`.ws-generate-row` — «Сформировать») ПЕРЕЕХАЛИ внутрь колонки
  кнопок `.ws-toolbar-main` (Task 315 ставил их отдельными рядами
  бара во всю ширину ПОД окнами).
- `.ws-toolbar-main` — flex column, `gap: 3px` (расстояние между
  рядами кнопок — заявка). Ряд 1 — в обёртке `.ws-toolbar-row`
  (`#wsSelectsRow`: месяц/год/«Обновить»).
- Десктоп (media ≥1024px):
  - колонка `height: 95px` — РОВНО высота окон справа;
  - каждый ряд `height: calc((95px − 6px)/3)` ≈ 29.7px + два зазора
    3px = ровно 95px (border-box): три ряда кнопок занимают РОВНО
    высоту окон — последний ряд у самого низа;
  - кнопки/селекты `height: 100%` (во всю высоту ряда) + padding
    4px 12px (текст 14px входит); nowrap + stretch + overflow hidden;
  - СКРЫТЫЙ ряд (нет правок / нет права записи) габаритов кнопок НЕ
    меняет — слот остаётся пустым, колонка ВСЕГДА 95px → сетка под
    баром НЕ прыгает при появлении/скрытии ряда 2 (численно: gridY
    совпадает до/после правки и после отмены);
  - высота БАРА: 95 + 2×5 + 1 = 106px (было ~145 — строки 2/3
    добавляли высоту).
- Мобильный (<1024px): колонка кнопок (3 ряда, gap 3px, кнопки 34px)
  → окна мероприятий/календаря под ней.

### 3) Рамки бара — 5px, не изменяются
- `.ws-toolbar` padding: 5px (Task 270, не менялся). Проверено
  перебором всех правил `.ws-toolbar` в файле: единственное с
  padding — 5px; ни одна тема/брейкпоинт его не переопределяет.
- Computed-проверка в браузере: 5px со всех четырёх сторон.
