# DEPLOY — Task 286: ввод «расход за неделю/месяц» + счётчик переданных показаний (Хозрасчёт №1)

**Что добавлено** (в `kip8test`, кэш `kipia-test-v532`):

1. **Ввод показаний за неделю и за месяц** — в детальной карточке
   «Расходомеры хозрасчётные / Хозрасчёт №1» кнопка «Ввести показания»
   открывает переключатель периода: **За сутки / За неделю / За месяц**.
   - Значения — **расход за период** (агрегат от Тэкон-19, как суточный
     ввод), Гкал — опционально.
   - Периоды — **прошедшие**: неделя пн–вс, календарный месяц. Даты
     предзаполнены, поля «Период с … по …» можно поправить.
   - Запись идёт **только в архив** (`hozraschet_archive`, новая колонка
     R `entryType` = `неделя`/`месяц`): meters-строка не меняется —
     «Последние показания» в карточке остаются последними СУТОЧНЫМИ.
   - В хронологии такие записи показывают диапазон дат + бейдж
     «нед»/«мес»; график строится только по суточным записям.
   - Редактирование (1 час) не поддерживается для записей периода —
     при ошибке вводится заново (история остаётся в архиве).

2. **Суммарный счётчик переданных показаний** (контроль, БЕЗ записи в
   архив) — блок «Передано показаний (контроль)» в карточке №1, перед
   хронологией, три строки:
   - «За сутки (ДД.ММ)» — сумма т + Гкал и число записей за сегодня;
   - «За 7 дней (ДД.ММ–ДД.ММ)» — … и «за M дн.» (пропущенные дни видны);
   - «За месяц» — текущий календарный месяц.
   Считаются только СУТОЧНЫЕ записи (записи «за неделю/месяц» —
   агрегаты, иначе двойной учёт). Вычисляется на клиенте из загруженного
   архива — на сервер ничего не пишется.

## Шаги деплоя

### 1. Обновить Apps Script (сервер) — 3 файла

В проекте Apps Script (тот же, где развёртывание `AKfycbyt…/exec`)
замените содержимое файлов:

| # | Файл в Apps Script | Откуда взять (справочные копии в репо) |
|---|--------------------|------------------------------------------|
| 1 | `Flowmeter.gs` | `scripts/Flowmeter.gs` |
| 2 | `FlowmeterArchive.gs` | `scripts/FlowmeterArchive.gs` |
| 3 | `Code.gs` | `scripts/Code.gs` (добавлен один case — см. ниже) |

⚠️ **Code.gs — единственное изменение**: добавлен маршрут

```javascript
case 'flowmeter.updatePeriodReading':
  return _json(Flowmeter.updateReading(payload));
```

(вставлен сразу после `case 'flowmeter.updateReading':`).
Если вам проще — вставьте только этот блок вручную в существующий
Code.gs, остальное в Code.gs не менялось.

Зачем отдельный маршрут: если фронтенд уже обновлён, а сервер ещё нет,
ввод «за неделю» вернул бы **«Unknown action»** и ничего не записал
(иначе недельный агрегат записался бы как суточные показания и испортил
бы meters-строку). Это защита, а не ошибка.

### 5. Проверка

1. Откройте «Расходомеры хозрасчётные» → «Хозрасчёт №1»:
   - блок «Передано показаний (контроль)» с тремя строками над
     «Хронологией показаний»;
   - «Ввести показания» → chips «За сутки / За неделю / За месяц».
2. Введите «За неделю» (например 85,4 т / 210,2 Гкал, даты прошлой
   недели подставятся сами) → Сохранить:
   - тост «Расход за неделю сохранён»;
   - в хронологии — новая строка с диапазоном дат и бейджем «нед»;
   - «Последние показания» в карточке НЕ изменились (остались
     суточными);
   - счётчик «за 7 дней» НЕ вырос (агрегат не в счётчике).
3. Аналогично «За месяц» (бейдж «мес»).
4. Обычный суточный ввод работает как раньше (проверьте разом).
5. Суточная запись за сегодня → счётчик «За сутки» обновился.
6. В Google Таблице лист `hozraschet_archive`: у новых строк
   R = `неделя`/`месяц`, заголовок R1 = `entryType`.
