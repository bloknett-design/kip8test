# Task 434 — печать: коды в ДВЕ КОЛОНКИ под «Коды:» + профиль: дата проверки знаний до 1000 В после знака группы + окна мероприятий ячеек: дата дд.мм.гггг

**Заявка (kip8test):** «Коды на печати сделать в две колонки под
названием "Коды:". В картах работников, в блоке профиля, после
знака группы указывать дату последней выполненной проверке знаний
до 1000В, в формате "от дд.мм.гггг". Также в окнах мероприятий
ячеек табеля, дату указывать в формате "дд.мм.гггг"».

## Что изменилось

**Клиент `index.html` (сервер Apps Script НЕ тронут — srvVer 427,
WorkSchedule.gs/Code.gs без изменений):**

1. **Печать — коды в ДВЕ КОЛОНКИ под названием «Коды:»** (заявка:
   «коды на печати сделать в две колонки под названием "Коды:"»;
   строка-абзац Task 433 и столбик Task 360–431 сняты):
   - **заголовок «Коды:» — отдельной строкой СВЕРХУ** сетки
     (`.wsp-legend-t`: `display: block`, `margin-bottom: 1mm`,
     `font-weight: 700`);
   - **сетка `.wsp-legend-cols` — `display: grid` +
     `grid-template-columns: 1fr 1fr`** (`column-gap: 6mm`,
     `row-gap: 0.8mm`, `align-items: start`): ДВЕ равные колонки
     на всю ширину листа ДО КОНЦА (замер предпросмотра: треки
     519.7px × 2 при сетке 1062px);
   - **каждая запись-код — своя строка колонки** (`.wsp-lg`:
     `display: block`, `white-space: normal` — длинное
     каноническое наименование переносится ВНУТРИ своей колонки
     на 2+ строки, не выходя за её ширину; `break-inside: avoid` +
     `page-break-inside: avoid` — запись не рвётся между
     колонками/страницами; `min-width: 0`);
   - **DOM**: «Коды:» и `<div class="wsp-legend-cols">` открываются
     сразу за легендой; закрытия сетки, легенды и обёртки — ТРИ
     последовательных оператора; сноска `wsp-foot` — ниже.
     Мероприятия — прежние записи-блоки [дата][текст→конец листа]
     (Task 433 жив, НЕ тронуты). Работает и в диалоге
     предпросмотра (Task 430), и при прямой печати, и в
     сохранённом HTML (тот же CSS через `_printCssText`).

2. **Профиль карточки — после знака группы дата последней
   ВЫПОЛНЕННОЙ проверки знаний до 1000 В** (формат «от
   дд.мм.гггг», итог вида «IV от 15.03.2026»):
   - НОВЫЙ метод `_lastExam1000Date(tabNo)`: сканирует пул
     «Инструктажей» ВСЕХ лет (`_INSTR_ALL` + годовой срез
     `_TRAININGS` старого сервера); запись подходит, когда
     работник совпадает, тип — `проверка_знаний` (нормализация
     пробелов/регистра), тема пункта содержит «до 1000 В»
     (толерантно к слитному «до 1000В»), отметка `выполнение = 1`
     (невыполненные и просроченные НЕ считаются); дата —
     `дата_проведения` с фолбэком `дата_начала` (легаси-записи);
     из нескольких выполненных берётся САМАЯ ПОЗДНЯЯ;
   - пул «Мероприятий» (`_EVENTS_ALL`) НЕ сканируется — разделы
     независимы (Task 429);
   - в `_renderWorkerCard` строка «Группа допуска» строится из
     `grpVal` (знак группы из столбца «группа_допуска») + « от » +
     `_fmtDateRu(дата)`; нет выполненной проверки — только знак
     группы, как прежде; нет группы — «—» без даты.

3. **Окна мероприятий ячеек табеля — дата в формате «дд.мм.гггг»**
   (прежде выводилась ISO «2026-09-05»):
   - подстрока окна «Мероприятия в этот день» (`.ws-events-sub`,
     `_renderEventsPopup`): `this._esc(this._fmtDateRu(isoDate)) +
     ' · ' + ФИО` → «05.09.2026 · Иванов И. И.»;
   - заголовок окна кодов (`_renderCellPopup`):
     `var popupDate = this._fmtDateRu(isoDate)` (название
     праздника/переноса рядом — Task 260 жив);
   - зрительский путь (`_openEventsOnlyPopup`) — тот же рендер,
     окно мероприятий ячейки и зрителю показывает дд.мм.гггг.
