## Заявка (с поправкой пользователя)
1) «В разделе Расходомеры хозрасчётные, в Хозрасчёте №12 период
   указан еженедельно, но фактически нужно ежедневно, в
   соответствии с формой ввода данных».
2) Первоначальная формулировка: «значения введённых расходомеров
   должны быть красными с шести утра до семи утра этих же суток,
   то есть ровно час…» — ОТМЕНЕНА поправкой: «красным должно быть
   с шести утра новых суток от суток ввода данных, пока не введут
   новые данные, а не ровно час».

## Что изменилось (клиент — index.html + data/flowmeters.json + sw.js)

1. **Нормализация периода №12** (`FlowmeterData._normalizeMeters`):
   заявка оперирует данными из Google-таблицы hozraschet_meters,
   где у №12 хранится устаревший «Еженедельно» (записать туда из
   песочницы нельзя). Период №12 нормализуется в «Ежедневно» на
   клиенте при ЛЮБОМ источнике данных — все 3 точки наполнения
   `_METERS`:
   - `load()` — ответ сервера `flowmeter.list`;
   - `_restoreCache()` — кэш localStorage `kip8_flow_cache_v1`;
   - `_loadFallback()` — data/flowmeters.json.
   Идемпотентно: когда период в таблице станет «Ежедневно»,
   нормализация ничего не меняет. Настоящие недельные (№3, №11) и
   месячный (№9) расходомеры не тронуты.
   Итог: бейдж «Ежедневно» в списке и в детальной карточке,
   суточная логика «пора вводить», форма — по-прежнему одно поле
   «Дата за предыдущие сутки» (как у всех не-№1).
2. **data/flowmeters.json**: у №12 `period` «Еженедельно» →
   «Ежедневно» (файл в кэш-листе SW — обновится с новой версией
   кэша).
3. **Красный «пора вводить» (поведение подтверждено поправкой,
   логика Task 357 не менялась)**: «Ежедневно» — красный стартует
   в 6:00 НОВЫХ суток (следующих за сутками ввода данных) и
   ДЕРЖИТСЯ, пока не введут новые данные; часового окна
   6:00–7:00 НЕТ. Зелёный — сразу после сохранения новых
   показаний и до 6:00 следующих суток. Поправка закреплена в
   комментариях блока `_isOverdue` и CSS `.flow-summary-val-due`
   (чтобы часовое окно никто не «дореализовал») и в тестах
   (персистентность красного после 7:00).

## ДЕПЛОЙ
1. Git push → GitHub Pages (CI гоняет тесты, Pages деплоит).
2. Пользователю: Ctrl+Shift+R ×1–2 (SW kipia-test-v593 → v594).
3. Apps Script / Google Sheets НЕ трогать — изменения только
   клиентские.
4. (Опционально, руками) В таблице hozraschet_meters период №12
   можно поправить на «Ежедневно» — поведение не изменится
   (нормализация идемпотентна), но данные станут едины.

### Проверка после публикации (1 минута)
1. Открыть «Расходомеры хозрасчётные» — у «Хозрасчёта №12» бейдж
   «Ежедневно» (и в списке, и в карточке).
2. У ежедневных расходомеров без данных за вчера (после 6:00) —
   показания КРАСНЫЕ; ввести новые показания → ЗЕЛЁНЫЙ сразу.
3. Красный не исчезает сам ни через час, ни позже — только с
   новыми данными (с 6:00 следующих суток снова красный).
