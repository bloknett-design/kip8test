# DEPLOY-Task359 — расходомеры: красный «пора вводить» ярче/крупнее + правка в окне 1 часа

**Репозиторий:** kip8test (мастер-версия; перенос в kip8 — см. kip8/scripts/DEPLOY-Task359-*.md)
**Дата:** 2026-09-10
**Тип:** КЛИЕНТ (index.html + sw.js) **+ СЕРВЕР (Apps Script: Flowmeter.gs,
FlowmeterArchive.gs)** — в отличие от Tasks 357/358, деплой требует
обновления серверных файлов и «Новой версии» (как в Task 347).

## Заявки (2 замечания пользователя по разделу расходомеров)

1. «Красный цвет показаний по периодам сделай ярче, а шрифт немного
   больше, чтобы он лучше привлекал внимание пользователя» — значение
   «Последние показания» в карточке, окрашенное красным по «пора вводить
   новые данные» (Task 357: ежедневно с 6:00 нет данных за вчера;
   еженедельно/ежемесячно — прошла неделя/месяц), было приглушённым и
   того же размера, что зелёное.
2. «При вводе очередных показаний расхода и после записи их на сервер,
   при необходимости отредактировать значение, создаётся новая запись,
   а не редактирование введённому ранее расходу — по условию в течение
   часа» — кнопка «Изменить показания» (окно правки 1 ч, Task 108)
   обновляла meters-строку, но в «Хронологии показаний» появлялась
   НОВАЯ строка архива — история обрастала дублями за одну дату.

## Решение

### 1. CSS — яркий красный + укрупнённый шрифт

`.flow-summary-val-due` (класс вешает renderList по `_isOverdue`):

| | Было (Task 357) | Стало (Task 359) |
|---|---|---|
| Тёмная тема | `#e74c3c` | **`#ff5c47`** |
| Светлая тема | `#c0392b` | **`#e8230a`** |
| Шрифт | 16px / 700 (как зелёный) | **18px / 800** |

Зелёный «свежие показания» не тронут (16px/700/#5ab870) — крупнее только
красное. Контраст на светлой теме ≈3,9:1 для крупного жирного шрифта —
норма для «привлечения внимания», читаемость сохранена.

### 2. Правка в окне 1 часа — обновление записи НА МЕСТЕ

**Корневая причина:** `Flowmeter.updateReading` при `isEdit=true` (проверки
«тот же пользователь» по meters.M и «менее 1 часа» по meters.N проходят)
обновляла meters-строку, но затем БЕЗУСЛОВНО вызывала
`FlowmeterArchive.appendToArchive` — в «Хронологии показаний» на каждую
правку добавлялась новая строка.

**Сервер (Flowmeter.gs + FlowmeterArchive.gs):**

- Новая функция `FlowmeterArchive.updateLatestReading(...)`: ищет с конца
  архива последнюю **суточную** запись расходомера (записи «за
  неделю/месяц» — другие логические записи, пропускаются), сверяет её
  свежесть (timestamp O < 1 ч, окно зеркалит meters-проверку) и
  **обновляет колонки на месте**: C prev, D curr, E consumption,
  F/G даты, H daysBetween, I unit, J temp, K Gcal, L period, M modRole,
  N modName, O timestamp (= время правки), Q anomaly.
  Идентичность (A/B/R) не трогается. **P (комментарий) не стирается**
  пустым значением — комментарий принадлежит этой же записи.
- `Flowmeter.updateReading` при `isEdit`: вызывает `updateLatestReading`
  вместо `appendToArchive`. **Фолбэк:** свежей суточной записи нет
  (запись архива при исходном вводе не удалась — archive write
  non-critical) → строка создаётся `appendToArchive`'ом, комментарий
  meters.O переносится в P новой строки (не теряется).
- **Комментарий meters.O при правке больше НЕ сбрасывается** (guard
  `!payload.isEdit` на блоке миграции Task 237): комментарий — атрибут
  той же логической записи. Раньше правка стирала активный комментарий.
- Аудит `FLOWMETER_UPDATE_READING` помечает правку: «… (правка в
  окне 1 ч)».
- Записи «за неделю/месяц» (`_writePeriodEntry`) не затронуты — как
  прежде, `isEdit` не поддерживается (задокументировано).

**Клиент** не менялся: он и так посылает `isEdit=true` (кнопка «Изменить
показания»), outbox (Task 358) сохраняет флаг при ретраях/beacon. После
правки детальная карточка перерисовывается и история подтягивается с
сервера — теперь в ней ОДНА строка с новым значением. Дедуп outbox
сверяется с meters-строкой (правка её обновляет) — совместимо.

**Обратная совместимость:** старый сервер + новый клиент = прежнее
поведение (правка создаёт строку) — ничего не ломается, просто новая
логика ещё не активна. Новый сервер + старый клиент — тоже корректно.

## Деплой

### Часть 1 — сервер (Apps Script, ОБЯЗАТЕЛЬНО для правки в окне 1 ч)

1. Открыть проект Apps Script (тот же, где Code.gs/Utils.gs).
2. Заменить содержимое файлов **Flowmeter.gs** и **FlowmeterArchive.gs**
   на версии из репозитория (`scripts/Flowmeter.gs`,
   `scripts/FlowmeterArchive.gs`).
3. Deploy → **«Управление развертываниями» → «Изменить» → версия
   «Новая»** → Развернуть (как Task 347).
4. Другие файлы проекта не трогать.

### Часть 2 — клиент (git push, уже выполнено)

1. `git push` → GitHub Pages.
2. Пользователям: Ctrl+Shift+R (или SW-обновление v588).

Порядок частей не важен (см. обратная совместимость выше): красный
цвет появится после Части 2, правка-на-месте — после Части 1.

## Проверки после публикации

1. **Красный:** расходомер «Ежедневно» без данных за вчера (после 6:00)
   → в списке карточек его показания — ярко-красные, визуально крупнее
   зелёных соседей; переключить тему — остаётся ярким в обеих.
2. **Правка:** ввести показания → «Сохранить» → сразу «Изменить
   показания» → другое значение → «Сохранить» → открыть карточку →
   «Хронология показаний»: ОДНА строка за сегодняшнюю дату с НОВЫМ
   значением (раньше было две); комментарий (если был) на месте.
3. **Окно 1 ч:** после часа с момента последнего ввода кнопка «Изменить
   показания» даст серверный отказ «Прошло более 1 часа» (как прежде).
4. **Новый ввод** другого пользователя/после окна — как прежде: новая
   строка истории, активный комментарий мигрирует в архив прежней.

## Откат

- Клиент: `git revert` коммита Task 359 → push → SW v587 вернёт старый
  CSS.
- Сервер: вернуть прежние Flowmeter.gs / FlowmeterArchive.gs в Apps
  Script → «Новая версия». Данные не мигрировали (формат архива A–R
  не менялся) — откат бесследен.
