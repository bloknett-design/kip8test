# Task 304 — Деплой «Таб_№ текстом: ведущие нули не теряются»

## Что менялось (баг из живой таблицы 03.09.2026)

**Симптом:** при добавлении инструктажа из приложения в листе
«Инструктажи» таб № с ведущим нулём записывался БЕЗ нулей — «0871»
(Романов Д. А.) сохранялся как `871`. То же грозило листам «Отпуска»,
«Сотрудники» и «Записи_графика» (ручная вставка/генерация).

**Причина:** Apps Script `appendRow` / `setValues` записывают значения
по USER_ENTERED-семантике Google Sheets («как будто напечатали в
ячейку»): числоподобная строка «0871» конвертируется в ЧИСЛО 871,
ведущий ноль теряется. Дальше таб перестаёт сопоставляться со
справочником «Сотрудники» (там текст «0871»): бейдж мероприятия в
шахматке молча не показывается, генерация не проставляет строки,
на странице «Инструктажи» вместо ФИО — «таб. № 871».

**Живой пример:** «Инструктажи», строка с id=4, «Повторный»
инструктаж, таб 0871, 30.09.2026 — записан числом `871`.

## Исправление

### Сервер `WorkSchedule.gs` (ТРИ уровня защиты)

| Уровень | Что делает |
|---------|-----------|
| 1. Запись | Новый хелпер `_appendRowKeepText(лист, строка, [колонки])`: таб-ячейкам СНАЧАЛА ставится текстовый формат `@`, ПОТОМ пишется строка. Заменил `appendRow` во всех 4 местах: `addEmployee` (A), `addTraining` (B), `addVacation` (B), `setManualEntry` (B, вставка и обновление) |
| 2. Генерация | `generateMonth`: диапазону вставки (колонка B «Записи_графика») — формат `@` до `setValues` |
| 3. Видимость | `generateMonth` возвращает `warnings[]`: мероприятия/отпуска, чей таб_номер НЕ найден в «Сотрудниках» (например, «871» после потери нуля). Раньше это была ТИХАЯ ошибка — теперь виден в тосте |

### Клиент `index.html` (SW v543)

- Тост «Сформировать» (месяц/год): предупреждения генерации
  показываются («⚠ … таб_номер «871» не найден в «Сотрудниках» —
  вероятно, потерян ведущий ноль»; максимум 3 + «(и ещё N)»).
- Страница «Инструктажи»: если таб записи не найден в справочнике —
  красный маркер «⚠ нет в справочнике» (сразу видно битую запись).

### Разовая починка уже испорченных данных — `scripts/TabNumbersFix.gs`

Новый код защищает БУДУЩИЕ записи; ячейки, уже записанные старым
кодом (число 871), остаются числами. Чинит их `TabNumbersFix.gs`
(одноразовый инструмент в стиле `StatusCodesInit.gs`, Task 299):

- `tabNumbersStatus()` — только диагностика: покажет проблемные
  ячейки и что будет исправлено;
- `fixTabNumbers()` — чинит: «871» → «0871» (если в справочнике есть
  подходящий таб), числа → текст; ставит колонкам таб_№ текстовый
  формат на весь столбец (будущий ручной ввод тоже сохранит нули);
  идемпотентен (повторный запуск — 0 исправлений); неизвестные таб
  не трогает — только журнал.

## Деплой

### 1. Apps Script — ОБЯЗАТЕЛЬНО (сервер менялся!)

Заменить `WorkSchedule.gs` в проекте Apps Script табели (тот же
проект, где `Code.gs`, `Utils.gs`) на копию из репозитория
`scripts/WorkSchedule.gs` — целиком. `Code.gs` НЕ менялся.

Затем: **Deploy → Manage deployments → ✏️ Edit → Version: New
version → Deploy** (тот же URL `AKfycbyt…`, редеплой Web App).

> Без этого шага новые записи продолжат терять ведущие нули, а
> тосты «Сформировать» не будут показывать предупреждения.

### 2. Починка живой таблицы — один раз после шага 1

Вариант А (рекомендуется):

1. В редакторе Apps Script: **+ → Создать файл «TabNumbersFix.gs»**,
   вставить содержимое `scripts/TabNumbersFix.gs` из репозитория.
2. Выбрать `tabNumbersStatus` → **▶ Run** — в журнале (Ctrl+Enter)
   увидеть список проблемных ячеек (ожидаемо: «Инструктажи»!B5 =
   «871» → будет «0871»).
3. Выбрать `fixTabNumbers` → **▶ Run** — журнал покажет исправления
   и самопроверку (0 оставшихся проблем).
4. Файл `TabNumbersFix.gs` можно удалить из проекта (приложение его
   не использует — это разовый инструмент).

Вариант Б (вручную, если строка одна): открыть таблицу → «Инструктажи»
→ ячейка B в строке с id=4 → заменить `871` на `'0871` (апостроф
принудительно делает текст) — или удалить запись в приложении и
добавить заново (уже новым кодом, нули сохранятся).

### 3. Фронтенд — автоматически

GitHub Pages подхватит `index.html` + `sw.js` (v543) после push.
У пользователя: **Ctrl+Shift+R ×1–2** (сброс старого кэша SW).

### 4. Проверка после деплоя (5 минут)

1. Приложение → «Инструктажи»: у записи «Повторный» (30.09)
   отображается **Романов Д. А.** и таб. № **0871** (не «таб. № 871»
   и не красный «⚠ нет в справочнике»).
2. Шахматка сентябрь: ячейка Романова Д. А. на 30.09 — смена «Д7,2»
   + бейдж «И» (два значения, как в Task 303).
3. «Сформировать» сентябрь: в тосте НЕТ «⚠» (все таб находятся).
4. Таблица → лист «Инструктажи»: в строке id=4 видно `0871`, ячейка
   текстовая (ноль не пропадает после правок).
5. Добавить тестовое мероприятие для таб 0292 (Чикризов) из
   приложения → в листе «Инструктажи» появилось `0292` — ноль на
   месте → удалить мероприятие.
