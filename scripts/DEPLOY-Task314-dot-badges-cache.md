## Что изменилось (заявка пользователя)

> «Замени символ кода "." на символ "·", а цвет фона ячейки сделай как в
> пустых, и напиши код цвета - заменю в таблице. Мероприятия из таблицы
> "Инструктажи" должны отображаться в ячейках шахматки маленькими
> бейджами-«иконками». Сделай, что бы последняя загруженная информация по
> графику работы сохранялась локально в приложении на устройстве
> пользователя, что бы каждый раз при открытии графика, он открывался
> моментально без ожидания подгрузки новых данных, а функцию обновления
> данных графика с подгрузкой новых мероприятий и прочего сделай с помощью
> кнопки обновления данных графика (не формирования).»

1. **Символ «·» + фон пустой ячейки (код «.»)**:
   - ячейка «.»-статуса рендерится как ПУСТАЯ: символ «·» (U+00B7 — тот же,
     что у пустых ячеек), фон — CSS-класс `ws-dot-code` (тёмная тема —
     `var(--bg-primary)`, светлая — `#eef0f2` = фон ЯЧЕЕК сетки, Task 250;
     правило выше специфичности базового, выходные — розовые как пустые);
     **inline-цвет из листа «Коды_статусов» для «.» НЕ применяется**
     (`_renderCell` не ставит background) — совпадение с пустой ячейкой в
     любой теме; класс — и маркер для тестов;
   - попап выбора статуса: строка «.» показывает символ «·» (свотч —
     `ws-swatch-dot`, фон пустой ячейки темы, БЕЗ inline-стиля);
   - select шита «Дополнительно…»: метка «· — Плановый выходной день»
     (value остаётся «.» — данные/сервер не меняются);
   - fallback-набор кодов: цвет «.» синхронизирован `#FAF9F5` → `#EEF0F2`;
   - **цвет фона «.»-ячейки для листа: `#EEF0F2`** (фон пустой ячейки
     сетки, светл. тема) — сообщён пользователю для замены в
     «Коды_статусов».

2. **Мероприятия «Инструктажи» — бейджи-«иконки» ГЛАВНАЯ форма показа**:
   - статус-мероприятие (И/ОБ/ПЗ/ПР/* в «Записи_графика» — generateMonth
     пишет его днём события без смены) больше НЕ показывается большим
     кодом по центру: ячейка выглядит пустой («·»), событие — СПЛОШНОЙ
     бейдж; записи в «Инструктажи» уже нет (событие удалено, строка
     осталась) — ВИРТУАЛЬНЫЙ бейдж из самого статуса (день не «теряет»
     мероприятие);
   - бейджи видны и на днях отсутствия (ОТ/Б/… — раньше скрывались по
     правилу Task 303, событие жило только в окне «Мероприятия в этот
     день») — сплошные: день сформирован;
   - пустая ячейка (в т.ч. план отпуска) — ПУНКТИРНЫЙ бейдж
     («заполнится при Сформировать»);
   - смена остаётся основным кодом, мероприятие — мини-бейдж в правом
     нижнем углу (точка переработки — в правом верхнем, конфликтов нет);
   - `_ABSENCE_CODES` остаётся справочником семейства отсутствий
     (документация/тесты), бейджи на этих днях больше не фильтруются.

3. **Локальная копия данных графика (localStorage `kip8_ws_cache_v1`) +
   кнопка «Обновить»**:
   - схема как у кэшей журналов (KipCableJournal `kip8_cj_cache_v1`):
     сохраняется ПОСЛЕДНЕЕ состояние справочников (коды/шаблоны/
     сотрудники) + планы отпусков ПО ГОДАМ + записи/мероприятия ПО ВИДАМ
     «год-месяц» (последние 12 — лимит от распухания квоты
     localStorage, вытесняются самые старые);
   - `init()`: `_restoreCachedView()` поднимает из localStorage ВСЁ для
     текущего месяца — `loadGrid()` НЕ ходит в сеть, рендер мгновенный
     (заявка: «открывался моментально без ожидания подгрузки»); кэша
     нет (первый запуск/другой месяц) — прежний путь: справочник кодов →
     шаблоны → загрузка вида с «Загрузка…»;
   - `_cacheWrite()` — после КАЖДОЙ загрузки с сети (в т.ч. после правок
     и генерации: `loadGrid(true)` — 11 мест мутаций: сохранение пакета,
     генерация месяц/год, удаление/правка мероприятий, отпуска и др.);
   - НОВАЯ кнопка **«Обновить»** (`#wsRefreshBtn`, `refreshData()`):
     перезагрузка ДАННЫХ с сервера (сотрудники, записи, мероприятия,
     планы отпусков, справочник кодов — тихо, `_loadStatusCodes(true)`
     не затирает живые коды fallback-набором при сбое) — это НЕ
     «Сформировать» (генерации записей нет, только чтение); видна ВСЕМ
     ролям (зритель обновляет свои данные так же, как редактор);
     иконка крутится (`@keyframes wsRefreshSpin`), кнопка блокируется;
     по успеху — тост «Данные графика обновлены» + запись в локальную
     копию; сбой — тост ошибки, старые данные остаются на экране;
   - штамп **«данные от 04.09, 14:22»** (`#wsCacheStamp`,
     `_updateCacheStamp`) — возраст локальной копии рядом с кнопкой;
     пусто = данных ещё не было;
   - `loadGrid(force)`: force=true — сеть обязательно (кнопка «Обновить»
     и перезагрузки после правок/генерации) + запись в локальную копию;
     force=false — сперва локальная копия; при принудительном обновлении
     сетка ОСТАЁТСЯ на экране (не мигает «Загрузка…» — индикатор на
     кнопке), «Загрузка…» — только первый показ вида без данных; при
     сбое обновления живой сетки — НЕ стирается экраном ошибки (тост
     достаточен);
   - побочно — офлайн-толерантность: без сети график всё равно
     открывается из локальной копии.
