# Task 423 — 9-ОГЭ создалось через 6 месяцев а не через 3

**Заявка (kip8test):** «9-ОГЭ создалось через 6 месяцев а не через 3».

## Диагноз

Правило (2) `_autoCreateNextTrainings` создаёт запись ребёнка на
«дата выполненного общего + период 9-ОГЭ из строки листа
«Список_И_и_ПЗ»». В живом листе пользователя в строке 9-ОГЭ стоит
**«6»** — скопировано с родителя (формулировка заявки 419: «9-ОГЭ
включён в Повторный инструктаж по рабочим инструкциям ОТ
(6 месяцев)»). Встроенная связь Task 420 дефолтирует только ПУСТУЮ
ячейку периодичности в 3 мес; заполненная «6» побеждала → отметка
общего создавала 9-ОГЭ **+6 мес**. Все тесты 419..422 использовали
период 3 или пусто — вариант живого листа не покрывался.

Эталон заявки (419): «У инструктажа по инструкции 9-ОГЭ особенность
формирования даты: **период 3 месяца**»; заявка 421: «9-ОГЭ через
**три месяца** от даты выполненного общего инструктажа».

## Реализация

**Сервер `scripts/WorkSchedule.gs`** (`_readInstrListSheet`):

1. **ГЛАВНЫЙ ФИКС:** при эффективной связи 9-ОГЭ → встроенный общий
   (столбец «в составе» пуст / опечатка / указывает на него же)
   период ребёнка = **3 мес ЭТАЛОНА заявки** — значение листа НЕ
   главнее (симметрично спасению опечаток «в составе» в Task 420).
   Связь на ДРУГОЙ пункт листа — период из листа (осознанное
   решение пользователя, не форсируем). Дефолт «пустая → 3»
   сохранён. Выполнение общего создаёт 9-ОГЭ **РОВНО через 3
   месяца** при любом значении ячейки листа.
2. `srvVer: '422'` → `'423'` — версия серверного кода автосоздания.

**Клиент `index.html`:**

3. `_normalizeInstrList` (дубль логики сервера) — тот же форс-3:
   «след. срок» 9-ОГЭ = дата общего + 3 мес, бейдж группы
   «раз в 3 месяца» — при любом значении листа («6» больше не
   уводит показ на +6).
4. `toggleTrainingDone` — предупреждение «⚠ Сервер Apps Script
   старой версии…» теперь и при `srvVer < 423` (сервер 422 и
   старше: период 9-ОГЭ ещё по значению листа — заявка «создалось
   через 6 месяцев»), не только при отсутствии поля.

## ⚠ СЕРВЕРНЫЙ ШАГ пользователя (обязательно)

Заменить `WorkSchedule.gs` в проекте Apps Script (табель_КИП_ИОС)
на файл из репозитория `scripts/WorkSchedule.gs` и создать **НОВУЮ
ВЕРСИЮ развёртывания** (Deploy → Manage deployments → Edit/New
deployment). Без этого сервер остаётся на логике 419..422:
период 9-ОГЭ берётся из листа («6» → запись +6 мес), а клиент
после каждой отметки показывает «⚠ Сервер Apps Script старой
версии…». `Code.gs` / `instrListInit` не менялись.

Правка листа «Список_И_и_ПЗ» НЕ требуется: значение «6» в строке
9-ОГЭ больше не влияет на срок (форс эталона 3 мес). При желании
можно привести ячейку к 3 — показ «раз в 3 месяца» уже и так верный.
