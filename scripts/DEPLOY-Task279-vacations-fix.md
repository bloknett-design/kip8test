# Task 279 — Hotfix: при «Сформировать» не проставлялись отпуска в шахматке

Заявка: «при формировании не формируются отпуска в шахматке».

## Причина (подтверждена симуляцией серверного кода на мок-таблицах)

Серверный `listVacations` **молча отбрасывал** строки листа «Отпуска», у которых:

1. **пустой `id`** (столбец A). Деплой-док Task 274 разрешал «id можно
   не заполнять» — но код требовал непустой id → строка исчезала из
   плана и из «Сформировать»;
2. **даты записаны текстом** («10.08.2026» — ручной ввод в локали, не
   распознавшей дату): проверка `instanceof Date` не проходила →
   строка тоже исчезала молча.

Логика самого шага 4.5 (`generateMonth`) корректна — это подтверждено
симуляцией (scripts/task279-sim.js, 23/23 PASS): дни периодов
получают «О» (включая Сб/Вс), авто-смены на днях отпуска
перекрываются, ручные правки не трогаются, границы месяца/года и
идемпотентность работают. Терялись данные ДО шага 4.5 — при чтении
листа. Дополнительно: ошибка чтения (листа нет и т.п.) тоже
проглатывалась молча — теперь видна в ответе и тосте.

## Что меняется

| Компонент | Изменение |
|-----------|-----------|
| `WorkSchedule.gs` | хелпер `_parseSheetDate` (+`_safeDate`): Date \| «dd.mm.yyyy» / «dd.mm.yy» / ISO → Date, мусор → null; `listVacations` — строки без id читаются (id: null), текстовые даты парсятся; «пустая строка» = нет id И таб_номера И даты; `addVacation` — пересечения/дубли проверяются и по текстовым датам; `generateMonth` — новые поля ответа `vacationsFound` / `vacationError` / `vacationDays` (и в аудите) |
| `VacationsInit.gs` | самолечение данных: повторный запуск дозаполняет пустые id (max id + 1) и конвертирует текстовые даты в настоящие Date (идемпотентно, данные не теряются) |
| `index.html` | тосты «Сформировать» (месяц и год) показывают «отпусков отмечено N дн.» и предупреждение «отпуска не проверены: …»; кнопка «Удалить» периода скрыта при id=null (подсказка «без id») |
| `sw.js` | кэш kipia-test-v528 → **v529** |

`Code.gs` НЕ меняется (маршрутизация прежняя — три case Task 274).

## Деплой (3 шага)

1. **`WorkSchedule.gs`** — заменить содержимое файла в Apps Script-проекте
   табели на `scripts/WorkSchedule.gs` из репозитория (kip8test, Task 279).
2. **`VacationsInit.gs`** — заменить на `scripts/VacationsInit.gs`;
   в редакторе выбрать `vacationsInitSheet` → **▶ Run** (БЕЗ force).
   В логе (Ctrl+Enter) увидите либо «Task 279 — самолечение данных:
   дозаполнено id: N, дат сконвертировано из текста: M», либо «Данные
   листа в порядке: пустых id и текстовых дат нет».
3. **Deploy → Manage deployments → ✏️ Edit → Version: New version →
   Deploy** (URL веб-приложения не меняется).

## Проверка (в приложении, роль «Админ»)

1. График работы → «Сформировать» → «{Текущий|Выбранный} месяц» или
   «Весь год» → в тосте появилась строка
   **«…, отпусков отмечено N дн.»**:
   - N > 0 — отпуска проставлены: в шахматке дни периодов залиты
     кодом «О» (пунктирная рамка плана исчезла — ячейка стала записью,
     tooltip: статус «Отпуск», источник «авто»);
   - N = 0 — либо периодов в листе на этот год нет (страница
     «Отпуска» покажет список), либо лист не читается — тогда в тосте
     будет «; отпуска не проверены: …» (причина, например
     `sheet_not_found`).
2. Страница «Отпуска»: строки, введённые вручную без id, отображаются;
   вместо кнопки «Удалить» — серая пометка «без id» (после перезапуска
   `vacationsInitSheet()` id дозаполнятся и кнопка появится).
3. Повторное «Сформировать» после изменения/удаления периода в листе —
   старые «О» сняты, новые проставлены (идемпотентность, в тосте
   «удалено N устаревших отпусков»).

## Откат

Вернуть прежние `WorkSchedule.gs` / `VacationsInit.gs` (Task 278-состояние):
тосты потеряют отпускные счётчики, строки без id/с текстовыми датами
снова перестанут читаться. Данные листа «Отпуска» конверсией не
портятся (валюативно безопасно: текстовые даты становятся настоящими
датами — это и так требовалось).
