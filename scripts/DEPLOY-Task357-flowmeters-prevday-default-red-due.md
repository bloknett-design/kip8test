# Task 357 — ДЕПЛОЙ: расходомеры хозрасчётные — дата «за предыдущие
# сутки» по умолчанию в форме ввода + КРАСНЫЙ цвет показаний
# «пора вводить новые данные»
Дата: 2026-09-10
Репозиторий: kip8test (ТЕСТОВЫЙ — проверить в бою ДО переноса в kip8)

## Заявка
1) В форме ввода показаний поле «Дата за предыдущие сутки» по
умолчанию содержит дату ПРЕДЫДУЩИХ СУТОК: если пользователь забудет
выбрать дату — при сохранении введённых данных сохранится дата
предыдущих суток. При редактировании записи — предзаполнение
СУЩЕСТВУЮЩЕЙ датой записи (правка больше не сдвигает дату показаний
на «сегодня»).
2) Цвет шрифта показаний в списке карточек расходомеров: зелёный →
КРАСНЫЙ, когда «пора вводить новые данные»:
   - «Ежедневно» — с 6:00 нет данных за предыдущие сутки; после ввода
     и сохранения — зелёный до 6:00 следующих суток;
   - «Еженедельно» — прошла календарная неделя (пн–вс) последних
     данных;
   - «Ежемесячно» — прошёл календарный месяц последних данных.

## Что изменилось (только клиент — index.html + sw.js)

1. **Дефолт даты в форме ввода** (`_applyEntryTypeFields`): при новом
   вводе (суточный режим / не-№1 расходомеры) поле
   `#flowInputDate` предзаполняется ВЧЕРАШНЕЙ датой — совпадает с
   подписью «Дата за предыдущие сутки». При редактировании (isEdit)
   поле предзаполняется датой записи (`m.dateCurr`, M/D/YYYY →
   input value): правка записи не сдвигает её дату на «сегодня»
   (раньше подставлялось «сегодня» молча). Битая/отсутствующая дата
   записи — откат на дефолт «вчера». Диапазонный ввод (период с…по,
   Task 286) не тронут.
2. **Сохранение без даты** (`submitInput`): если поле даты оставлено
   пустым, на сервер уходит дата ПРЕДЫДУЩИХ суток (было «сегодня»).
   Дефолт поля и fallback теперь согласованы — «забыл выбрать дату»
   больше не создаёт запись сегодняшней датой.
3. **Логика «пора вводить»** (`FlowmeterData._isOverdue(m, now)` +
   хелперы `_parseMdy` / `_dayKey` / `_mondayOf`):

   | Период        | КРАСНЫЙ («пора»)                            | Граница цикла |
   |---------------|---------------------------------------------|---------------|
   | Ежедневно     | последних данных старше «предыдущих суток»  | 6:00 (до 6:00 действует цикл прошлых суток — «вчера» для него ещё на день старше) |
   | Еженедельно   | календарная неделя данных прошла            | понедельник 00:00 (неделя пн–вс) |
   | Ежемесячно    | календарный месяц данных прошёл             | 1-е число 00:00 |
   | Нет данных / битая дата | КРАСНЫЙ (пора вводить)          | — |
   | Неизвестный период | считается как ежедневный              | — |

   Данные «из будущего» — зелёный. Сравнение дат локальное, без
   времени; переходы месяца/года/недели обработаны (тесты A).
4. **Цвет показаний в списке** (`renderList`): `<span
   class="flow-summary-val">` получает класс `flow-summary-val-due`,
   когда `_isOverdue` = true. CSS: тёмная тема `#e74c3c`, светлая
   `#c0392b`; базовый зелёный `#5ab870` не тронут. Подписи, даты,
   прочие элементы карточек — без изменений.
5. **Минутный таймер** (`_startOverdueTimer`): цвет меняется сам при
   переходе границы (6:00 / понедельник / 1-е число) БЕЗ перезагрузки
   страницы. Запуск в `init()` с guard от повторного запуска; раз в
   минуту пересчитывается сигнатура состояний (`_calcOverdueSig`,
   'id:0/1,…') и `renderList` вызывается только при реальном
   изменении И если открыт раздел расходомеров. Ошибки таймера
   глотаются (try/catch) — на работу раздела не влияют.
6. **SW**: `CACHE_VERSION` kipia-test-v585 → **v583** (кэш-лист не
   менялся — только версия; файлы кэша те же 43).

### Проверка после публикации (1 минута)
1. Открыть «Расходомеры хозрасчётные» — у расходомеров с ежедневным
   периодом, по которым нет данных за вчера (после 6:00), показания
   КРАСНЫЕ; со свежими данными — зелёные.
2. «Ввести показания» → поле даты = вчера; ничего не меняя, ввести
   значение и сохранить → запись сохранилась ЗА ВЧЕРА (проверить в
   карточке: «Последние показания за ДД.ММ.ГГГГ»), цвет стал зелёным.
3. «Изменить показания» (в течение часа после ввода) → поле даты =
   дата записи, а не «сегодня».
4. Не закрывая страницу, дождаться перехода 6:00 (или открыть до
   6:00 и подождать) — красный появится сам, без перезагрузки.
