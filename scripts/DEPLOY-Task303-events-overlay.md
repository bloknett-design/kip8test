# Task 303 — Деплой «Два значения в ячейке» (слой мероприятий И/ОБ/ПЗ)

## Что меняется

**Сценарий:** у работника в рабочий день инструктаж или проверка знаний —
в ячейке шахматки отображаются ДВА значения: код смены (основной, цвет
фона + текст) + мини-бейдж мероприятия (И / ОБ / ПЗ) в правом нижнем
углу. До Task 303 генерация ЗАТИРАЛА смену кодом мероприятия («Д8»
превращался в «И») — данные о смене терялись.

**Модель данных (без изменений листов!):**

| Компонент | Роль | Изменение |
|-----------|------|-----------|
| `Записи_графика` | основной код ячейки (смена/отпуск/…) — один на день | данные НЕ меняются структурно; шаг 4 генерации больше не пишет И/ОБ/ПЗ на сменные дни |
| лист `Инструктажи` | ЕДИНСТВЕННЫЙ источник истины о мероприятиях (тип, тема, даты) | не меняется — клиент строит бейджи прямо из него |
| колонка I `инструкция` | связка запись ↔ мероприятие (FK) | проставляется и на сменных днях (для аудита) |

**Новый приоритет статуса дня:** ручная правка > отпуск > плановая
смена > мероприятие (И/ОБ/ПЗ — только на день БЕЗ плановой смены;
раньше мероприятие стояло выше смены и затирало её).

Новая логика шага 4 (`generateMonth`):
- день со плановой сменой + мероприятие → смена остаётся кодом,
  мероприятие видно бейджем (клиент), связка `инструкция=id`;
- день без смены + мероприятие → вставляется строка И/ОБ/ПЗ (как
  раньше — мероприятие в выходной по циклу);
- шаг 4.6 (новый): авто-строки И/ОБ/ПЗ, чей день больше не покрыт
  мероприятием (мероприятие удалено/перенесено), — смена
  восстанавливается (если день сменный) или строка удаляется.
  До Task 303 такие строки «висели» вечно — теперь повторное
  «Сформировать» сходится к актуальному состоянию листа «Инструктажи».

## Клиент (index.html, SW v542)

- `_eventsAt(дата, таб)` — мероприятия дня из листа «Инструктажи»
  (загружаются уже сейчас, отдельного запроса нет).
- Бейдж в ячейке: смена + цветной мини-чип кода мероприятия;
  на днях отсутствия (ОТ/Б/…) бейдж скрыт — событие в тултипе;
  пустая ячейка + мероприятие → пунктирный бейдж-подсказка
  «заполнится кодом … при «Сформировать»» (аналог плана отпуска).
- Тултип ячейки: название мероприятия, тема, дата.
- Попап ячейки: секция «Мероприятия в этот день» (справочно) +
  строка «+ Мероприятие…» — форма мероприятия с уже вписанными
  сотрудником и датой ячейки (быстрое добавление второго значения).
- После добавления/удаления мероприятия шахматка перезагружается —
  бейдж появляется/исчезает сразу.

## Деплой

### 1. Apps Script — ОБЯЗАТЕЛЬНО (сервер менялся!)

Заменить `WorkSchedule.gs` в проекте Apps Script табели
(тот же проект, где `Code.gs`, `Utils.gs`) на копию из репозитория
`scripts/WorkSchedule.gs` — целиком. `Code.gs` НЕ менялся.

Затем: **Deploy → Manage deployments → ✏️ Edit → Version: New
version → Deploy** (тот же URL `AKfycbyt…`, редеплой Web App).

> Без этого шага старый скрипт продолжит затирать смены кодами
> мероприятий при «Сформировать» — бейджи будут, но смена в БД
> потеряется. Клиент v542 + старый сервер = неверные данные.

### 2. Фронтенд — автоматически

GitHub Pages подхватит `index.html` + `sw.js` (v542) после push.
У пользователя: **Ctrl+Shift+R ×1–2** (сброс старого кэша SW).

### 3. Проверка после деплоя (5 минут)

1. Открыть «График работы» → месяц с мероприятием на рабочем дне.
2. Убедиться: ячейка показывает код смены (Д/Д8/Д7,2/Н) + бейдж И/ПЗ.
3. Нажать «Сформировать» (текущий месяц) → в тосте появилась строка
   «дней мероприятий N (строк И/ОБ/ПЗ …, восстановлено смен …,
   удалено мероприятий …)».
4. Тап по ячейке с бейджем → в попапе секция «Мероприятия в этот
   день» с темой; «+ Мероприятие…» открывает форму с вписанными
   сотрудником/датой.
5. Удалить мероприятие (страница «Инструктажи») → бейдж исчез сразу;
   повторное «Сформировать» снимает авто-строку И/ОБ/ПЗ (если была).
