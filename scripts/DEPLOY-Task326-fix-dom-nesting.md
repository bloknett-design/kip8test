# DEPLOY — Task 326: BUGFIX — незакрытый `</div>` страницы «Табель» ломал открытие разделов и полных карточек расходомеров (kip8test)

**Дата:** 2026-09-05 · **Репо:** kip8test (тест) · **Кэш SW:** kipia-test-v564 → **kipia-test-v565**

## Заявка пользователя

«Проверь баг, не открываются некоторые разделы и полные карточки расходомеров.»

## Причина (разбор)

- **Task 323** (боковая шторка итогов) при перестройке рабочей области табеля
  в `#wsWsBody` (сетка + шторка) **потерял один закрывающий `</div>`** страницы
  `#page-work-schedule`.
- Следствие в DOM: **все разделы, идущие в разметке ПОСЛЕ табеля** — «КИП ИОС»,
  «Приборы», «Блокировки», «Задвижки», «Регуляторы», «Проекты», «Кабельный
  журнал», «План 114», калькуляторы/конвертеры, «Сапёр», «Телефонный
  справочник», админ-панель, «Библиотека», «Билеты», «Что нового» — и
  **ДЕСКТОПНАЯ ПАНЕЛЬ ДЕТАЛЕЙ `#detailPanel`** оказывались **вложенными** в
  скрытую (`display:none` без `.active`) страницу табеля.
- Симптомы совпадают с заявкой один-в-один: клик по разделу — «не открывается»
  (страница получает `.active`, но родитель скрыт); клик по карточке
  расходомера на десктопе — панель `#detailPanel` наполняется контентом
  (`.active`, заголовок, показания), но **не видна** (`offsetWidth=0`).
  Мобильные полные страницы расходомеров (`#page-flowmeter-detail`) идут в
  разметке РАНЬШЕ табеля — потому на телефоне всё работало.
- Диагностика: стек-парсер тегов `<div>` (пропуск `<script>`/`<style>`/
  комментариев) → ровно **1 незакрытый div**; git-бисекция баланса по коммитам:
  Task 322 — баланс 0, **Task 323 — баланс 1** (баг с v562; v562–v564 затронуты).
  Продуктовый kip8 (v417, Tasks до 314) **не затронут** — баланс 0.
