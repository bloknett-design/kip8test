# DEPLOY Task 282 — «отпуска не отображаются, добавить из приложения не получается»

## Симптом (заявка пользователя 2026-08-31)

> «отпуска не отображаются, из приложения не получается добавить
> отпуск, нажимаю добавить отпуск, заполняю форму, нажимаю добавить
> и ни чего не происходит»

## Причина

**Фронтенд: фантомная тост-API.** В коде модулей (WorkSchedule,
Flowmeter, CableJournal) ~100 сообщений обратной связи вызываются
через `KipToast.show(...)` под guard'ами
`typeof KipToast !== 'undefined'`. Но `KipToast` **нигде не был
определён** — реальная тост-система приложения называется
`showToast` (элемент `#toast`). Все guard'ы возвращали false, и
каждое сообщение — ошибка валидации формы («Выберите
сотрудника»), ошибка сервера (`overlap`, `sheet_not_found`,
`no_session`), сообщение об успехе — **молча подавлялось**.
Любая неудача выглядела как «нажал кнопку — и ничего не
произошло»: диалог не закрывался, объяснения не было.

Дополнительные дефекты того же контура:

1. `KipAuth.api` при ошибке ответа выбрасывал только КОД ошибки
   (`overlap`), а человекочитаемое пояснение сервера (`message`:
   «Период пересекается с уже заданным отпуском…») терялось.
2. Сервер `addVacation` при проверках пересечения/дубля части
   пропускал строки листа «Отпуска» БЕЗ id (ручные периоды) —
   контроль дырявился (несоответствие с семантикой Task 279).

## Фикс

**index.html (фронтенд):**

- определён `KipToast = { show: … }` — алиас реальной тост-системы
  `showToast`/`#toast` (одна вставка включает все ~100 вызовов);
- `KipAuth.api` сохраняет пояснение сервера в `err.serverMessage`;
- новый хелпер `WorkSchedule._apiErrText(err)` (serverMessage →
  message → строка), применён в отпусках: форма добавления,
  удаление периода, сообщение «Ошибка: …» на странице «Отпуска»;
- SW-кэш `kipia-test-v529` → `kipia-test-v530`.

**WorkSchedule.gs (сервер):**

- `addVacation`: строки без id участвуют в проверках пересечения
  и дубля части (та же семантика «пустой строки», что
  в `listVacations` — Task 279).

**Code.gs — НЕ менялся.**

## Шаги деплоя (2 шага)

1. **Фронтенд — ничего делать не нужно** (GitHub Pages после
   push). Открыть приложение, **Ctrl+Shift+R** (2 раза, чтобы
   service worker обновился на v530).
2. **Сервер**: в Apps Script открыть `WorkSchedule.gs`, выделить
   всё (Ctrl+A), удалить, вставить содержимое нового файла из
   `download/kip8test/WorkSchedule.gs`, сохранить (Ctrl+S) →
   **Deploy → Управление развертываниями → ✏️ → Версия: Новая
   версия → Развернуть** (URL не меняется).

## Проверка после деплоя

1. Открыть «График работы → Отпуска». Если отпуска не
   отображаются — на странице теперь будет **понятное**
   «Ошибка: …» (например `sheet_not_found: Отпуска` — значит,
   нет листа; `unknown action` — не задеплоен сервер). Текст
   ошибки можно прислать в чат — по нему сразу видна причина.
2. Нажать «+ Добавить отпуск», выбрать сотрудника, даты,
   «Добавить»:
   - при ошибке теперь **виден тост с пояснением** (например
     «Период пересекается с уже заданным отпуском…» — если этот
     период уже введён вручную в таблице);
   - при успехе диалог закрывается, тост «Отпуск добавлен…»,
     период появляется в списке.
3. «Сформировать» в шахматке — «О» на днях отпуска.
