# DEPLOY Task 346 — Фикс logout: выход из моба больше НЕ выкидывает десктоп

**Симптом (подтверждён 08.09.2026 в проде):** параллельный вход работает
(моб + десктоп), но **выход из мобильного приложения автоматически выкидывал
и десктоп** — сессия десктопа оставалась в таблице, однако через ≤5 минут
(heartbeat) приложение уходило в гостевой режим.

**Причина (по живому Sessions.gs):** `Sessions.logout` удалял только СВОЮ
строку сессии — но затем **безусловно сбрасывал `login_status` пользователя**
в «вход не выполнен». А `login_status` — флаг **пользователя**, не сессии:
heartbeat параллельного устройства (каждые 5 минут) проверяет
`user.login_status !== 'вход выполнен'` → удалял свою строку и бросал
`session_expired` → клиент (`handleSessionExpired`, SERVER-ответ) →
гостевой режим. Десктоп выкинут.

**Лечение:** `login_status` сбрасывается **только если это была последняя
сессия пользователя**. Пока жива другая (моб ИЛИ десктоп) — статус не
трогается, heartbeat параллельного устройства проходит штатно.

**Бонус-фикс в том же файле:** `getCurrentUser` возвращал
`userId: user.id` (строчными) → `undefined` (заголовок листа users — «ID»,
см. Task 37). Клиент кэшировал пустой `userId`. Теперь `user.ID` — как в
`createSession` и `Auth.verifyOTP`.

---

**Состав активации — 1 правка (~5 минут):**
1. заменить содержимое файла `Sessions.gs` целиком.

**НЕ требуется:** `sdpInit` (структура листа `sessions` не меняется — колонка
`device` уже есть с деплоя политики), правки `Code.gs` (роутер уже вызывает
`Sessions.logout(payload.token)` — сигнатура не менялась), правки `Auth.gs`,
`SessionsDevicePolicy.gs`. Клиент (PWA/десктопы) обновлять не нужно — баг
был полностью серверным.

## Шаг 1. Заменить Sessions.gs

1. Открыть **Apps Script Editor** проекта KIP8_Access
   (script.google.com — тот же проект, где уже правили `Auth.gs`,
   `Code.gs` и добавляли `SessionsDevicePolicy.gs`; развёртывание
   AKfycbyt…/exec).
2. Слева «Файлы» → выбрать файл **Sessions**.
3. **Ctrl+A → Ctrl+V** — заменить ВСЁ содержимое кодом из репозитория
   `scripts/Sessions.gs` (kip8test и kip8 идентичны). Сохранить (Ctrl+S).
4. Перед заменой сверьте, что ваш текущий `Sessions.gs` совпадает с тем,
   из которого делался патч (сигнатуры: `logout: function(token)`,
   `getCurrentUser: function(token)`; в logout — безусловный вызов
   `Utils.updateUserStatus(user.row, 'вход не выполнен', user.last_login)`).

**Если предпочитаете точечную правку вместо замены целиком — их две:**

**1.1. logout — сброс статуса только без других сессий:**
```js
// БЫЛО:
      Utils.deleteRow('sessions', session.row);
      const user = Utils.findUserById(session.user_id);
      if (user && user.login_status === 'вход выполнен') {
        Utils.updateUserStatus(user.row, 'вход не выполнен', user.last_login);
      }
      Utils.audit(session.email, 'LOGOUT', '', '', 'User logged out');
// СТАЛО:
      Utils.deleteRow('sessions', session.row);
      const user = Utils.findUserById(session.user_id);
      let keptParallel = false;
      if (user && user.login_status === 'вход выполнен') {
        if (!Sessions._userHasOtherSession(session.user_id, session.email)) {
          Utils.updateUserStatus(user.row, 'вход не выполнен', user.last_login);
        } else {
          keptParallel = true;
        }
      }
      Utils.audit(session.email, 'LOGOUT', '', '',
        keptParallel
          ? 'User logged out (another session stays active — Task 346 parallel mode)'
          : 'User logged out');
```
и добавить в объект `Sessions` (например, сразу после `logout`)
приватный метод `_userHasOtherSession(userId, email)` — взять из
`scripts/Sessions.gs` патча целиком (пересчитывает строки листа
`sessions` этого пользователя по user_id/email; fail-safe: любая
ошибка → `true` → статус НЕ сбрасывается).

**1.2. getCurrentUser — userId заглавными:**
```js
// БЫЛО:
    return {
      userId: user.id,
      email: user.email,
      role: user.role
    };
// СТАЛО:
    return {
      userId: user.ID,   // Task 37: заголовок листа users — «ID»
      email: user.email,
      role: user.role
    };
```

## Шаг 3. Проверка (~5 минут)

1. Войти в **мобильной** PWA (device=mobile), войти с той же почтой в
   **десктопе** (device=desktop) — обе сессии живут параллельно, в
   листе `sessions` две строки.
2. **Выйти из мобильного** → лист `sessions`: осталась только
   десктоп-строка; лист `users`: `login_status` — по-прежнему
   «вход выполнен» (пользователь ведь залогинен на десктопе).
3. **Десктоп НЕ выкинут:** подождать 5+ минут (интервал heartbeat),
   полистать разделы, перезагрузить приложение — сессия жива.
4. Админ-панель → Сессии: ровно одна строка с бейджем «десктоп».
5. audit_log: свежая строка `LOGOUT` с деталью
   «another session stays active — Task 346 parallel mode».
6. Обратный случай — выход из десктопа при живом мобиле: аналогично,
   мобильная сессия продолжает работать.
7. **Одиночный вход** (пользователь зашёл только с телефона и вышел):
   `login_status` = «вход не выполнен» — прежнее поведение сохранено.
8. (Бонус) В DevTools консоли браузера: `localStorage.getItem('kip8_cached_user_id')`
   после входа — больше не пустая строка, реальный ID.

**Признак «не применилось»:** после выхода из моба в `users` у
пользователя `login_status` = «вход не выполнен», при живой второй
сессии — значит заменили не тот файл или не опубликовали «Новую версию»
(Шаг 2).

---

**Как это работает / отказоустойчивость:**

| Ситуация | Поведение |
|---|---|
| Выход из моба при живом десктопе (и наоборот) | удаляется только строка вышедшего устройства, `login_status` НЕ сбрасывается, параллельная сессия живёт |
| Выход последней сессии | `login_status` = «вход не выполнен» (как раньше) |
| Админ сбросил `login_status` (Admin.resetLogin) | по-прежнему выгоняет ВСЕ сессии пользователя на ближайшем heartbeat — механизм администратора не тронут |
| Смена роли на «Запрет» | по-прежнему принудительный logout (getCurrentUser не изменён в этой части) |
| Старые строки sessions с пустым user_id (баг Task 37) | совпадение считается и по email — сессия не потеряется |
| Ошибка чтения листа в `_userHasOtherSession` | fail-safe: `true` → статус НЕ сбрасывается; рассинхрон (если он есть) починит самосинхронизация `Auth.sendOTP` при следующем входе |
| Удаление пользователя / сессии админом | ветки heartbeat/getCurrentUser не менялись |

**Откат:** вернуть прежний `Sessions.gs` (до замены) и опубликовать
«Новую версию». Вернётся баг выкидывания параллельной сессии при logout,
больше ничего не изменится.
