## Что изменилось (только index.html, сервер НЕ менялся)

### 1. Мобильная версия — карточки столбиком
- `@media (max-width: 1023px)`: `.ts-cards-grid { grid-template-columns: 1fr; }`
  (было `repeat(auto-fill, minmax(150px, 1fr))` — 2 колонки).
- `.ts-page { padding: 4px 12px 12px; }` (было `4px 0 12px`) — небольшие
  отступы по краям; карточка занимает всю строку.
- Десктопная сетка `minmax(240px, 1fr)` не тронута.

### 2. Избранное (по примеру расходомеров хозрасчётных, FlowFav)
- Новый модуль **TempFav** — localStorage-ключ `kip8_temp_fav_v1`
  (изолирован от KipFav и FlowFav), API has/add/remove/toggle/count.
  Drag-and-drop НЕ переносился: порядок избранных = порядок каталога
  (каталог фиксированный, в отличие от списка расходомеров).
- Табы **«Все 17 / Избранные N»** вверху страницы выбора (инлайн,
  `.ts-tabs` — работают и на мобильном, и на десктопе).
- Звёздочка **☆/★** в правом верхнем углу каждой карточки
  (`.ts-card-fav-btn`, синий акцент раздела, `event.stopPropagation()` —
  клик по звезде не открывает датчик).
- Звёздочка **☆/★** в шапке страницы датчика (`#tempSensorFavBtn`,
  как flowFavBtn) — добавление/удаление текущего датчика; синхронизирована
  со звёздами карточек.
- Режим «Избранные»: только избранные датчики, заголовки пустых групп
  скрыты; без избранного — заглушка «Нет избранных датчиков» с подсказкой.
- `renderTempSensorCards()` перерисовывается при каждом вызове
  (идемпотентность из Task 372 убрана — состояние звёзд/таба меняется).

### 3. Бейджи ТС/ТП убраны из карточек и полных карточек
- Из карточек списка и чипа страницы датчика бейджи удалены вместе с
  CSS-классами `.ts-card-badge*`.
- В заголовках ГРУПП («Термометры сопротивления» / «Термопары») бейджи
  `.ts-group-badge*` ОСТАВЛЕНЫ (заявка касается карточек).
- Верхняя строка карточки получила `padding-right: 34px` — стрелка «›»
  не перекрывается звёздочкой.

### 4. Термопара ТХК (L) — хромель-копель, ГОСТ Р 8.585-2001
- Каталог: 17 датчиков (8 ТС + 9 ТП); `L` идёт после `E`
  (ТХА K, ТЖК J, ТМК T, ТНН N, ТХКн E, **ТХК L**, ТПП R, ТПП S, ТПР B);
  диапазон НСХ −200…800 °C, электроды «хромель-копель».
- **Расчёт:** типа L нет в МЭК 60584 и базе НИСТ (SRD 60), поэтому
  полиномы аппроксимации подобраны по таблице ГОСТ Р 8.585-2001
  (два диапазона: −200…0 °C — степень 6; 0…800 °C — степень 8).
  - Точность: ≤0,0009 мВ по 101 точке таблицы (шаг 10 °C) и ≤0,0002 мВ
    по 18 контрольным точкам эталонного калькулятора ГОСТ 8.585
    (kipia.xyz: E(42)=2,7595; E(555)=45,1498; E(−137)=−7,3094;
    E(317)=24,2933; E(777)=64,5152 мВ и т.д.).
  - Таблица сверена по ДВУМ независимым источникам (kipservis.ru +
    kipia.xyz); расхождения источников в 4 точках (±1 мкВ,
    OCR-артефакты) разрешены через калькулятор.
  - Ключевые точки: E(−200)=−9,488; E(−100)=−5,641; E(0)=0;
    E(100)=6,862; E(500)=40,299; E(800)=66,466 мВ.
  - Монотонность на всём диапазоне подтверждена (бисекция
    tempCalcInvertValue работает корректно).
- Справка для L: отдельная строка НСХ — «тип ТХК (L) есть только в ГОСТ
  (в МЭК 60584 и базе НИСТ отсутствует); расчёт — аппроксимирующий
  полином по таблице стандарта». Список распространённых типов дополнен.

### 5. Панель «Расчёт произвольных значений» — статичная, НАД формой
- Панель (Task 371) перенесена из результатов calcTempSensor в СТАТИЧНУЮ
  разметку `#page-temp-sensor-view`: блок `.ts-calc-panel`
  (id `tempCustomCalcPanel`) в колонке ввода СРАЗУ НАД `.scale-form`
  (Тип датчика / Диапазон измерения / Шаг таблицы).
- Отображается ВСЕГДА (не только после «Рассчитать»); живой
  двусторонний расчёт t ↔ R(t)/E(t) — прежние функции
  tempQueryFromTemp/tempQueryFromValue.
- Подпись второго поля и плейсхолдер подставляет openTempSensor() под
  тип датчика: «Сопротивление R(t), Ом» / «Например: 61,8» (ТС) или
  «Термо-ЭДС E(t), мВ» / «Например: 2,2» (ТП); оба поля очищаются
  при открытии датчика.
- Генератор `tempCustomCalcHtml()` УДАЛЁН; из результатов calcTempSensor
  панель убрана (старая форма под расчётной таблицей — по заявке).
