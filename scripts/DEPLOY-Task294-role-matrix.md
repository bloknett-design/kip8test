# Task 294 — RoleMatrix.gs (Этап 2): деплой и проверка

## Что это

Серверное чтение матрицы доступа из таблицы **KIP8_Access** (лист
`matrix`, создан `RoleMatrixInit.gs` в Task 293 v4). Модуль отвечает
на вопрос «что разрешено роли/пользователю»:

- **динамика** — количество ролей/прав не фиксировано (новая строка/
  колонка подхватывается сами; границы ищутся по контенту, т.к. лист
  имеет «стилевой холст» A1:Z1000 и `getLastRow()` возвращает 1000);
- **fail-closed** — любая проблема → доступ закрыт + предупреждение,
  функции никогда не бросают исключений (сервер сайта не падает);
- **«Админ» всегда все права** (кроме режимного `kipios.restricted`,
  которое уважается по чекбоксу) и `admin.panel` у админа неотключаем;
- **кэш** 5 минут (после правки галочек: подождать ≤5 мин или вызвать
  `roleMatrixInvalidateCache()`).

## Деплой

1. В проекте Apps Script (тот же, что привязан к KIP8_Access и
   деплоится как Web App) создайте файл **RoleMatrix.gs** и вставьте
   в него содержимое `scripts/RoleMatrix.gs` из репозитория.
2. Сохраните. Ничего запускать не надо — это библиотека.
3. Быстрая проверка (необязательно): в редакторе выберите функцию
   **`roleMatrixDebug`** → «Выполнить». Журнал покажет: сколько прав
   и ролей видит сервер, наборы прав, всех пользователей users и
   найдена ли их роль в matrix. Должно быть:
   `Права (matrix r4, C+): 13`, `Роли (matrix r6+): 12`,
   по каждому пользователю «роль есть в matrix»,
   «Предупреждений нет — ОК».

## API (вызовы из вашего серверного кода)

```javascript
// Права по роли (как в users!role / matrix!B; регистр не важен):
var acc = roleMatrixGetAccess('ИТР ИОС');
// acc = { role:'ИТР ИОС', roleId:'itr_ios', found:true, isAdmin:false,
//         permissions:{ 'calc.view':true, … }, granted:[…], warnings:[] }

// Точечная проверка (удобно в doGet/обработчиках):
if (!roleMatrixHasPermission('ИТР ИОС', 'kipios.view')) { /* скрыть */ }

// Права пользователя по email (роль берётся из листа users):
var acc = roleMatrixGetAccessForEmail('shaman00986@gmail.com');
// + email, userFound. Незнакомый email → доступ закрыт (fail-closed).

// После правки галочек в матрице (мгновенно, не ждя 5 минут):
roleMatrixInvalidateCache();          // кэш матрицы
roleMatrixInvalidateCache(email);     // + кэш роли пользователя

// acc.permissions['<perm_id>'] — быстрые проверки на клиентских данных:
if (acc.permissions['charts.view']) { … }
```

## Связка с users

`users!role` (названия: «Админ», «ИТР ИОС», …) → `matrix!B` (та же
колонка «Название»). Названия роли должны совпадать (регистр и
пробелы по краям прощаются). Пользователь с ролью, которой нет в
matrix → доступ закрыт; `roleMatrixDebug()` подсвечивает это
строкой «⚠ РОЛИ НЕТ В MATRIX».

## Правила «Админа» (зашиты в код)

| Правило | Поведение |
|---|---|
| Все права | админ получает ВСЕ права независимо от чекбоксов |
| Исключение | `kipios.restricted` — по чекбоксу (режимное, конфликтует с `kipios.view`) |
| `admin.panel` | у админа НЕОТКЛЮЧАЕМ (нельзя потерять доступ к своей панели) |

## Если что-то пошло не так

- `roleMatrixDebug()` → «Лист «matrix» отсутствует»: запустите
  `roleMatrixInit` из RoleMatrixInit.gs (Task 293).
- Права «не обновились» после правки галочек: кэш — вызовите
  `roleMatrixInvalidateCache()` или подождите 5 минут.
- Роль пользователя «не находится»: сверьте написание в
  `users!role` и `matrix!B` (см. `roleMatrixDebug`).
- Мок-тест: `node scripts/task294-mock-test.js` (133 проверки;
  данные сняты с реальной таблицы 02.09.2026).
