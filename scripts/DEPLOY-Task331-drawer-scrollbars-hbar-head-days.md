## Заявка
«При открытии шторки итогов учёта, не должно быть полосок вертикальной
прокрутки в шторке и в шахматке табеля. Кнопку с шевроном в шторке
сделай в два раза уже по ширине и прозрачней, левый бордюрчик сделай
полосой как между сменными и дневными сотрудниками в шахматке. В шторке
полоску горизонтальной прокрутки сделай под нижним бордюром, как под
шахматкой табеля, но при неполном открытии шторки, шторка должна
открываться достаточно для того чтобы вся информация в столиках её
таблицы просматривалась, и не должно быть при этом нижней горизонтальной
полоски прокрутки. Высота шапки названия столбцов в таблице шторки
должна выравниваться по высоте шапки шахматки табеля. В названиях
столбцов Явки и Переработка, в скобках подпиши что количества в днях.
Текст в шапке таблицы шторки и в ячейках значений выровни по центру.
Уровень нижнего бордюра шорки должен всегда выравниваться по бордюру
шахматки табеля.»

## Что изменилось (только клиент — index.html + sw.js)
1. **Нет полосок вертикальной прокрутки** (оба контейнера, все движки):
   причина — Firefox `scrollbar-width: thin` рисовал тонкую ВЕРТИКАЛЬНУЮ
   полоску и в шторке (.ws-tt-body), и в шахматке (gridwide
   .ws-grid-wrap), а съедая ширину тела шторки — ещё и горизонтальную
   даже при свёрнутых столбцах. Исправлено: `.ws-tt-body { scrollbar-width:
   none; ::-webkit-scrollbar { display: none } }`; gridwide-правила
   сетки (thin + webkit-ползунок) УДАЛЕНЫ. Скролл жив (колесо/свайп +
   синхронизация сетка⇄шторка).
2. **Кастомные горизонтальные ползунки** (замена нативных): `.ws-grid-hbar`
   (#wsGridHbar — шахматка; виден только в широком режиме) и
   `.ws-tt-hbar` (#wsTtHbar — шторка) — дорожка + бегунок
   `.ws-hbar-thumb`; зона 12px зарезервирована ВСЕГДА, без переполнения
   ПУСТАЯ («при неполном открытии — без полоски»), с переполнением —
   ползунок ПОД нижним бордюром («как под шахматкой табеля»).
   Перетаскивание — pointer capture; клик по дорожке — страница;
   JS: `_attachHbars` (init) / `_hbarSync` / `_hbarSyncAll`
   (после подгонок/рендеров/тогла/resize).
3. **Колонки рабочей области одинаковой сборки** → нижние бордюры
   ВСЕГДА на одном уровне (заявка): сетка — новая обёртка `#wsGridCol`
   [.ws-grid-wrap (flex 1) → СТАТИЧНЫЙ #wsGridFoot (5px) → #wsGridHbar
   (12px); _renderGrid полосу в контейнер больше не рендерит — она не
   уезжает при длинной сетке и не пересоздаётся при рендерах];
   шторка — панель БЕЗ рамок [скролл-зона → .ws-tt-foot (5px) →
   #wsTtHbar (12px)]. `_fitGrid`: budget = avail − headH (полоса и
   ползунок вне контейнера; поправка clientHeight удалена).
4. **Шеврон** `#wsTtChv`: 22→11px (вдвое уже), заливка 0.92→0.55
   (светлая 0.94→0.6), svg 7×12, высота прежняя 48px.
5. **Левый бордюрчик** `.ws-tt-edge`: стальной bevel 5px → ПОЛОСА 2px
   #4a8fc7 / светлая #6e8ba4 — как разделитель сменных/дневных
   (tr.ws-group-first) в шахматке.
6. **Шапка столбцов шторки = шапке шахматки**: пустая шапка шторки
   ПРЯЧЕТСЯ ЦЕЛИКОМ ([hidden], 16px-филлер удалён); thead th шторки
   height 38px + vertical-align middle; var --ws-tt-head-h =
   шапка(0/32) + thead(38) — шапки совпадают полосой в полос, строки
   итогов ровно по строкам сетки (и в месяце, и в году).
7. **Подписи «(дни)»**: «Явки (дни)» / «Переработка (дни)» (месяц),
   «Перераб. (дни)» (год); столбцы расширены 36/38/56 → 44/42/80
   (свернуто 166px, развёрнуто 550px — «вся информация видна, без
   полоски прокрутки»).
8. **Текст по центру**: `.ws-tt-table th, td` — center (год тоже);
   колонка «Сотрудник» — по-прежнему слева.
