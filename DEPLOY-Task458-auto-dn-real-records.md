## ЧТО СДЕЛАНО

Task 456/457 реализовали авто-«д»/«н» (замещение отпуска сменного
персонала) производным слоем: коды жили только в памяти открытого
месяца, на сервер не писались, в «Год»/архивы не попадали, а «в»
поверх виртуального кода был no-op (очистка пустой ячейки). Заявка
Task 458 меняет архитектуру: план МАТЕРИАЛИЗУЕТСЯ в записи.

### 1. `_autoDnMaterialize()` — план → правки `_PENDING` (как ручной ввод)
Пустые ячейки плана `_autoDnPlan` становятся правками `_PENDING`
(поля — в точности как ручной ввод «д»/«н» сменному: переработка 0,
без замещения/комментария/часов). Кнопка «Сохранить» отправляет их
обычным путём (`saveAll` → `setManualEntry`, на сервере источник
«руч») — **сервер, архивы, «Год» и другие устройства видят
авто-«д»/«н» как обычные ручные записи**. Итоги/Талоны/печать/PDF/
Excel читают их ШТАТНО (эффективные записи); виртуальные записи
`_autoDnEntries` Task 457 и подмешивания в `printGrid`/
`_renderTotalsMonth`/`_talonsRows` УДАЛЕНЫ. Материализация — только
редакторам (`_canEdit`): зрители правок не создают, сетка показывает
им серверные записи. Хук в `_renderGrid` (после пересчёта плана) +
тост «Авто: N кодов «д»/«н» (замещение отпуска) — нажмите
«Сохранить»».

### 2. Реестр `_AUTO_DN_KEYS` + `localStorage ws_auto_dn_keys`
`{ 'YYYY-MM': { 'ISO|таб': 1 } }` — ключи материализованных авто
(правки И сохранённые записи; ключ localStorage автоматически
получает префикс репозитория через `isolateLocalStorage`).
`_autoDnKeysLoad` (при каждом рендере, merge; живыми остаются только
ключи с действующим «д»/«н»), `_autoDnKeysSave` (merge по месяцам,
try/catch — приватный режим не роняет), `_autoDnIsKey`,
`_autoDnUnmark`. Реестр переживает перезагрузку страницы — «в»
поверх СОХРАНЁННОЙ авто-записи тоже даёт «.» (не delete-цикл).

### 3. БАГ ЗАЯВКИ: «в» (Выходной) поверх авто — «.»-надгробие
`_applyCellStatus('')` на ячейке реестра — ручной плановый выходной
«.» (паттерн авто-записей Task 453): запись-надгробие занимает
ячейку — план повторно код НЕ расставит; рендерится пустой белой
(Task 314/356), в Итогах/Талонах/печати — не рабочий день. Иной код
(«Б» и т.п.) поверх авто — обычная правка (реестр снят); «д»/«н»
поверх авто метку реестра СОХРАНЯЮТ — защита «в»-надгробия от цикла
«удалить → расставить заново». Авто-ветка стоит ПЕРВОЙ в пути
очистки (до авто-записей Task 453), пути без реестра не изменились.
`submitCellForm` («Дополнительно…») — тот же принцип.

### 4. Идемпотентность плана: ПОКРЫТИЕ дня
Найденный browser-check'ом каскад: пересчёт плана не учитывал, что
смена отпускника УЖЕ закрыта сохранённой «д»/«н» — после каждого
сохранения план добавлял ДУБЛЬ другому работнику (двойное замещение
одной смены). Теперь карта `covered[day] = {day, night}` по
эффективным записям «д»/«н» (ручные И материализованные): тип смены
с покрытием НЕ назначается повторно — максимум одна «д» и одна «н»
на день по типам, глобально (как у нескольких отпускников).
«.»-надгробие покрытием НЕ является — смена отпускника требует
замены, план назначает другого кандидата (повторное замещение).

### 5. Отображение
Материализованная правка рендерится штатно КАК РУЧНОЙ «д»/«н»
(рамка `ws-manual-dn` + метка `ws-source-manual` + янтарный пунктир
`ws-pending` правки; после «Сохранить» — обычная серверная запись).
`ws-auto-dn` — ИНЕРТНЫЙ маркер реестра (DOM-селекторы/тесты;
собственных стилей нет). Попап: подсказка «Авто: «д» — … (замещение
отпуска; правка — как у ручной записи)» по реестру + активная
строка «д»/«н» (current = эффективный статус). Дисплей-ветка слоя в
`_renderCell` и псевдо-записи в `_printCell`/`_printModel` удалены.
