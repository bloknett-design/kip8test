## Суть изменений

| Элемент | Было (Task 465/466) | Стало (Task 467) |
|---------|---------------------|------------------|
| Окно «Предпросмотр печати / Мероприятия» (кнопка-принтер в окне «Мероприятия» бара табеля) | Белый лист списка смещён вправо: правый край срезался границей окна предпросмотра, слева от листа — серая полоса | **Лист по центру, целиком в границах окна предпросмотра** |

Подробности:

- Причина дефекта: iframe предпросмотра наследовал альбомные 1063px из
  `.wspprev-frame` (Task 430 — печать графика), а масштабирование
  `_eventsPrevFit` считает книжный лист 794px и обрезает «бумагу»
  (`overflow: hidden`) по этой ширине. Лист (центрировался flex-ом в
  широком viewport 1063px, отступ ~134px) уезжал вправо — правый край
  срезался границей окна.
- Фикс (приём Task 449, талоны): новый класс `wsev-prev-frame` →
  CSS-правило `.wspprev-frame.wsev-prev-frame { width: 794px; }` —
  iframe получает книжную ширину, совпадающую с W масштабирования.
  В `_openEventsPreview` — `frame.className =
  'wspprev-frame wsev-prev-frame'`.
- Диалог/кнопки («Печать / Сохранить PDF / Сохранить Excel / Отмена»),
  генераторы PDF/Excel, содержимое листа — НЕ менялись.
- Предпросмотр графика (альбомный 1063px) и талонов (`wst-prev-frame`)
  — не тронуты.

## Шаги деплоя

НЕ ТРЕБУЮТСЯ. Клиент задеплоится GitHub Pages автоматически после пуша
(CI: Tests + pages). Service Worker поднят до `kipia-test-v691`
(kip8test) / `kipia-v503` (kip8) — у пользователей кэш обновится при
следующем открытии приложения (в течение пары переходов).

## Проверка после деплоя

1. Открыть раздел «Табель учёта рабочего времени». В окне «Мероприятия»
   нажать принтер (левый значок пары).
2. В диалоге «Предпросмотр печати / Мероприятия — месяц год г.» белый
   лист со списком — по центру, целиком виден (включая колонку
   «Работник»), не выходит за правую границу окна.
3. Сузить окно браузера — лист масштабируется и остаётся в границах
   предпросмотра.
4. Печать / сохранение PDF / Excel работают как раньше.
