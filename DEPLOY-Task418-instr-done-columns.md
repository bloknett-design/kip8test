# Task 418 — столбцы «дата_проведения» / «выполнение» / «просрочен» листа «Инструктажи» + отметка о выполнении в карточке

**Заявка:** «В таблице "Инструктажи" я заменил название столбца
"дата_начала" на "дата_проведения", столбца "дата_окончания" на
"выполнение", столбца "длительность_дней" на "просрочен". Суть
логики заполнения переименованных столбцов должна быть такая: в
столбце "дата_проведения" указывается дата планируемого
проведения; в столбце "выполнение" находится 0, если
пользователь через интерфейс (новый - который необходимо
добавить) в блоке Повторные инструктажи и периодическая проверка
знаний, в карточке работника не сделал отметку о выполнении, и или
цифра 1 - если сделал отметку о выполнении; в столбце "просрочен"
находится цифра 0 - если дата проведения не просрочена или сделана
отметка о выполнении (столбец "выполнение" = 1), находится цифра
1 - если дата проведения просрочена и не сделана отметка о
выполнении (столбец "выполнение" = 0)».

## Что изменилось

### 1. Логика столбцов листа «Инструктажи» (сервер)

Формат листа определяется по **заголовкам строки 1**
(`_trainingsSheetFormat`): переименованные столбцы → новый формат
`done`, прежние заголовки → прежний формат `legacy`
(работает как раньше — на случай, если столбцы не переименованы).

- **дата_проведения (E)** — дата планируемого проведения;
- **выполнение (F)** — 0/1: отметка пользователя; ставится/снимается
  галочкой в карточке работника (см. п. 2). Новые записи — 0.
  Легаси-даты прежнего «дата_окончания» в ячейках читаются как 0;
- **просрочен (G)** — 0/1, **пересчитывается автоматически**:
  1 — дата проведения прошла И выполнение = 0;
  0 — дата сегодня/в будущем ИЛИ отметка стоит.

Пересчёт происходит:

- **при чтении** (открытие/обновление табеля) — устаревшие
  значения и легаси-даты в F/G **нормализуются прямо в листе**
  (одним пакетом на столбец, только при отличии) — столбцы
  остаются корректными сами, вручную ничего чистить не нужно;
- **при добавлении записи** (дата пишется в E, F = 0 или отметка
  правимой записи, G = пересчёт);
- **при отметке о выполнении** (эндпоинт `setTrainingDone`).

Лист «Мероприятия» (обучение/прогул/примечание) — **прежний
формат** (дата_начала/дата_окончания/длительность_дней), ничего не
менялось. Автосоздание листа «Инструктажи» (если удалён) теперь
сразу с новыми заголовками; перенос строк между листами
(trainingsSplitInit) конвертирует форматы.

### 2. Новый интерфейс отметки о выполнении (карточка работника)

В блоке **«Повторные инструктажи и периодическая проверка знаний»**
карточки (страница «Работники») у каждой записи справа появилась
**галочка**:

- пустой кружок — отметки нет («выполнение» = 0);
- зелёный кружок с ✓ — выполнено (= 1); строка приглушена;
- рядом с датой красный бейдж **«просрочен»** — дата прошла, а
  отметки нет (G = 1); после отметки бейдж исчезает.

Клик переключает 0 ↔ 1 (отметку можно снять). Зрители (уровень
view) видят состояние (зелёная галочка «Выполнено», бейдж), но
кликать не могут. Правка записи (✎) **сохраняет отметку** — она
переносится в новую строку при сохранении изменений.

### 3. Совместимость

Записи «Инструктажей» несут и прежние поля (дата_начала =
дата_окончания = дата_проведения, длительность_дней = 1) — бейджи
шахматки, окна мероприятий и печать табеля работают без изменений.
Если столбцы НЕ переименовывать — всё работает как раньше (форма,
просмотр), но галочек и отметок не будет: сервер вернёт понятную
ошибку «Столбцы листа "Инструктажи" не переименованы…».

## Серверные шаги (ОБЯЗАТЕЛЬНО)

1. Открыть Apps Script проекта табель_КИП_ИОС;
2. Заменить содержимое **WorkSchedule.gs** на новую версию
   (репозиторий, `scripts/WorkSchedule.gs`);
3. В **Code.gs** добавить маршрут (уже в новой версии
   `scripts/Code.gs`): `case 'workSchedule.setTrainingDone':` —
   если меняли Code.gs вручную, добавьте этот case рядом с
   `workSchedule.deleteTraining`;
4. **Создать НОВУЮ версию развёртывания** (Deploy → Manage
   deployments → Edit → New version) — без этого новый эндпоинт
   вернёт «неизвестное действие»;
5. Столбцы листа «Инструктажи» уже переименованы пользователем
   (дата_проведения/выполнение/просрочен) — больше ничего делать
   не надо: при первом открытии табеля значения F/G нормализуются
   автоматически.

## Что проверять после обновления

1. Обновить страницу (после выхода SW kipia-test-v645 —
   перезагрузка дважды или закрыть/открыть вкладки приложения);
2. Открыть табель → «Обновить» → лист «Инструктажи»: старые даты
   в столбце «выполнение» заменились на 0, «просрочен» у прошедших
   дат без отметки — 1, у будущих — 0;
3. «Работники» → карточка → блок «Повторные инструктажи…»:
   галочки у записей, бейдж «просрочен» у просроченных;
4. Клик по галочке — зелёная, строка приглушена, бейдж исчез,
   в листе «Инструктажи» выполнение = 1, просрочен = 0;
   повторный клик — возврат;
5. ✎ правки записи с отметкой — после сохранения отметка на месте;
6. Регресс: бейджи шахматки, окна мероприятий, печать табеля —
   работают как раньше; правка/удаление записей — прежние.
