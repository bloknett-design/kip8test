# Task 402 — тип работника третьей строкой ячейки + столбец «группа_допуска»

**Заявка**: «В разделе Табель учёта рабочего времени, в столбце работники, в
ячейках с фамилиями работников, данные типа работника размести в третьей
строчке снизу, не меняя при этом шрифта и высоты ячеек. В файле табель_КИП_ИОС
я добавил новый столбец "группа_допуска", необходимо сделать чтобы данные из
него также редактировались из приложения и отображались в приложении после
данных "должность"».

**Репозиторий**: kip8test (тестовый сайт)
<https://bloknett-design.github.io/kip8test/>

**Версия SW**: kipia-test-v628 → **v629**
**Тесты**: 3776 passed / 0 failed (было 3749/0; +27 в test-task402.js,
адаптация test-work-schedule.js / test-task384.js / test-task396.js)
**Браузер-чек**: 32/32 ×3 контекста (тёмная view / светлая edit / мобайл),
0 JS-ошибок; VLM ×3 (glm-5v-turbo) — подтверждено визуально.

## Что изменилось

### Часть 1 — ячейка сетки (тип работника — ТРЕТЬЯ строка)

- Данные типа («смена №1» / «сменный» / «дневной») переехали из суффикса
  строки должности («Слесарь КИПиА смена №1») на собственную **третью
  строку** ячейки: ФИО → должность → тип. Рендер: новый хелпер
  `_empTipLine(emp)` + блок `.ws-emp-tip` (рендер только при непустом типе).
- **Шрифт и стили — те же, что у строки должности** (10px/400,
  line-height 12px, эллипсис; светлая тема #666; ярусы compact/tight — те
  же подстройки, что у должности). Своих height/padding у строки нет.
- **Высота ячеек не меняется**: на десктопе высоту строк задаёт растяжка
  `_fitGrid` (реальные ~12 работников → ~70px ≥ природных 52px трёх
  строк; ярусы compact/tight пересчитываются сами по замеру природной
  высоты). Сужение (мобайл, `.ws-narrow`) скрывает строку типа вместе с
  должностью и таб.№. Печатная форма НЕ менялась (`_posLabel` — прежний
  склеенный формат, Task 361).
- `_measureEmpCol` меряет и строку типа — колонка ФИО по самому широкому
  тексту из ТРЁХ строк.

### Часть 2 — столбец «группа_допуска» (лист «Сотрудники», файл табель_КИП_ИОС)

Данные отображаются **после данных «должность»** везде в приложении:

- **Ячейка сетки**: строка должности = «должность · группа»
  («Слесарь КИПиА · IV»; без группы — просто должность). Хелпер
  `_empPosLine(emp)`.
- **Карточка работника** (попап шахматки и страница «Работники»): строка
  «Группа допуска» — сразу после «Должности» (пусто — «—»).
- **Сводная таблица вкладки «Общая»** (страница «Работники»): колонка
  «Группа допуска» — сразу после «Должности».
- **Шторка создания/правки работника**: селект «Группа допуска» рядом с
  «Должностью»; наполнение `_fillGroupSelect` — уникальные значения листа
  (listEmployees includeArchived) + стандартные II/III/IV/V + «— не
  указана —»; текущее значение сохраняется поверх подгрузки (как
  «Должность», Task 318). Submit шлёт `группа_допуска` в
  `workSchedule.addEmployee` / `workSchedule.updateEmployee`.

### Сервер (справочная копия scripts/WorkSchedule.gs)

- Столбец «группа_допуска» ищется **по ЗАГОЛОВКУ строки 1** листа
  «Сотрудники» (позиция любая — обычно L; толерантно к регистру и
  пробелу/подчёркиванию): `_accessGroupColIndex(sheet)`.
- `listEmployees` — отдаёт поле `группа_допуска` (чтение расширено до
  найденного столбца; нет столбца — пусто).
- `updateEmployee` / `addEmployee` — пишут группу в найденный столбец;
  **guard по наличию поля в payload** (старый фронтенд из кэша SW без
  поля НЕ затирает значение листа); нет столбца — запись пропускается
  (обратная совместимость).

## ⚠ СЕРВЕРНЫЙ ШАГ (у пользователя)

Обновить `WorkSchedule.gs` в Google Apps Script проекта табель_КИП_ИОС
(скопировать `scripts/WorkSchedule.gs` из репозитория — изменились
`listEmployees`, `updateEmployee`, `addEmployee`, добавлен хелпер
`_accessGroupColIndex`). До деплоя: фронтенд работает, но поле
«группа_допуска» не читается и не сохраняется (мелкая деградация, без
ошибок); старый GAS с новым фронтом — поле просто игнорируется, данные
не портятся.
