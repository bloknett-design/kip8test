# DEPLOY Task 537 — Телефонный справочник: архив пользовательских данных (Google Таблица)

> Дата: 2026-10-17 · Заявка: «Необходимо проработать телефонный справочник.
> создать файл с google таблицей для телефонного справочника, придумай для него
> название, в этом файле я планирую организовать сохранять данные внесённые
> пользователями в разделах телефонного справочника избранное и добавленные
> примечания, доступные только тем пользователям которые их внесли для себя,
> то есть таблицы с архивами данных общие, но данные индивидуальные привязанные
> к email. и в дальнейшем по необходимости расширение архива данных для
> телефонного справочника.»

## Что сделано (СЕРВЕР — этап хранения; клиент НЕ менялся)

- **НОВЫЙ файл `PhonebookArchive.gs`** — модуль архива пользовательских данных:
  - создаёт файл Google Таблиц **«Телефонный справочник — Архив пользователей»**
    (название придумано по заявке) — `SpreadsheetApp.create`, файл появится
    на Drive владельца проекта; ID сохраняется в Script Properties
    (`PHONEBOOK_ARCHIVE_SPREADSHEET_ID`), открытие всегда по ID — файл можно
    свободно переименовывать и перемещать по Drive;
  - листы: **«Избранное»** (id, дата_добавления, email, контакт_id, фио,
    должность, телефон, организация, контакт_json, статус, дата_удаления),
    **«Примечания»** (id, даты создания/изменения/удаления, email, контакт_id,
    снимки, контакт_json, примечание до 500 символов, статус),
    **«Служебное»** (версия структуры, назначение, правила доступа, порядок
    расширения архива — описание внутри листа);
  - **принцип заявки**: таблицы общие, данные индивидуальны — каждая строка
    привязана к `email`; чтение всегда фильтруется по email, запись/удаление
    возможны только для своих строк; чужие записи ни при каком запросе не
    возвращаются и не меняются;
  - мягкое удаление (статус «активна»/«удалена» + дата_удаления) — история
    сохраняется, повторное добавление создаёт новую строку;
  - гейт `secret.view` (то же право, что открывает страницу «Телефонный
    справочник»; fail-closed без RoleMatrixGate.gs), `LockService` на записи,
    аудит `PHONEBOOK_*` в audit_log, текстовый формат `@` (Task 304) +
    экранирование `=+-@` апострофом (защита примечаний от формул);
  - **расширение архива** (по заявке): новые разделы данных — новыми листами
    по образцу существующих; новые колонки — дописывать в конец строк,
    инкрементировать «Версию структуры» в «Служебном».
- **`Code.gs`** — роутинг `phonebook.getMyData` / `phonebook.setFavorite` /
  `phonebook.setNote` (+ строка в шапке-индексе модулей).
- Контракт эндпоинтов (для клиентской интеграции — СЛЕДУЮЩАЯ задача) — в шапке
  `PhonebookArchive.gs`: `getMyData → {srvVer, favorites: {id: true},
  notes: {id: 'текст'}}` (форма карт — как у клиента в localStorage).

## Шаги деплоя (одноразово, ~5 минут)

1. Открыть Apps Script Editor проекта развёртывания AKfycbyt… (тот же, где
   Code.gs / PlanEvents.gs).
2. **+ → Создать файл `PhonebookArchive.gs`** — вставить содержимое
   `scripts/PhonebookArchive.gs` ЦЕЛИКОМ.
3. **Заменить `Code.gs`** — содержимым `scripts/Code.gs` (добавлены 3 case
   `phonebook.*`; остальное не менялось).
4. **Создать файл-архив**: в выпадающем списке функций выбрать
   `phonebookArchiveInit` → ▶ Run:
   - первый запуск попросит авторизацию — Review permissions → разрешить;
   - в журнале (Ctrl+Enter) — URL созданного файла «Телефонный справочник —
     Архив пользователей»; файл появится на Drive владельца;
   - повторный запуск безопасен (идемпотентно: файл уже есть — ничего не
     меняет, в журнале URL того же файла).
5. **Deploy → Manage deployments → Edit (карандаш) → Version: New version →
   Deploy**.
6. Проверка: `phonebookArchiveStatus` → Run — в журнале `file=true`, три
   листа, `schemaVersion=1`.

## Откат

- Удалить `PhonebookArchive.gs` из проекта; вернуть прежний `Code.gs`; New
  version → Deploy. Файл-архив на Drive можно удалить (или оставить — данные
  персональные, кроме владельца не видны).
- Клиент НЕ менялся: откат сервера ни на что не влияет (эндпоинты просто
  вернут «Unknown action» — как до Task 537).

## Примечания

- Файл-архив принадлежит аккаунту-владельцу Apps Script (чтение/запись идут
  от его имени). Ссылку на файл можно дать другим аккаунтам для ПРОСМОТРА;
  редактировать руками не нужно — колонки и статусы обслуживает скрипт
  (ручные правки строк не ломают чтение: битые строки молча пропускаются,
  но лучше не надо).
- Клиентская интеграция (синхронизация избранного/примечаний из localStorage
  в архив по email) — следующая задача; сейчас приложение работает как прежде,
  а файл и API готовы принимать данные.
- kip8test-desktop НЕ синкается (смена без index.html — норма, как docs-пуши);
  kip8-desktop синкнется автоматически (триггер `scripts/*.gs`).
