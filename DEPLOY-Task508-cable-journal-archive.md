# DEPLOY — Task 508: «Кабельный журнал» — АРХИВ правок и удалений

**Дата:** 12.10.2026. **Что менялось:** клиент (index.html + sw.js + sync-cables.py —
в репозитории kip8test, деплой GitHub Pages автоматически) + **СЕРВЕР Apps Script**
(по этой инструкции — 2 шага: полная замена CableJournal.gs + новая версия развёртывания).

## Суть

Заявка: «Добавь сохранение в архив журнала кто последний вносил правки в каждый
кабель, по столбцу name в таблице users файла KIP8_Access. И удалённый кабель так
же должен сохраняться с пометкой как архивный по причине "Удалён", кто удалил, и
не должен отображаться в распечатываемом или сохраняемом в PDF файле, а в excel
отображается.»

| Элемент | Поведение |
|---------|-----------|
| Правка записи (updateRow) | Сервер пишет в лист P «Последний редактор» (name из users KIP8_Access; пустой name → email) и Q «Дата правки» |
| Новая запись (appendRow) | Создатель сразу записывается в P/Q (он — последний, кто вносил правки) |
| Удаление записи (deleteRow) | Строка **НЕ удаляется физически**: R «Архив» = «Удалён», S «Кем удалён» (name), T «Дата удаления» |
| Список в приложении | Архивные записи **скрыты** (как раньше — после удаления строка исчезает) |
| Печать / «Сохранить PDF» | Архивные записи **не попадают** (модель печати — только активные) |
| «Сохранить Excel» | Архивные записи **отображаются** + блок колонок «Архив» (K–O: Статус / Кем удалён / Дата удаления / Последний редактор / Дата правки) |
| Данные (data/cables.json, sync) | Архивные строки в снимок НЕ попадают (снимок активного журнала; сами записи остаются в Google-таблице) |
| «Старый сервер» (до шагов ниже) | Клиент работает как прежде: строк с пометкой нет — все записи активные; Excel без блока архива |

**Колонки листа «Кабельный журнал» (P–T создаются сами при первом обращении
к API — отдельный init-скрипт НЕ нужен, `_ensureArchiveColumns` идемпотентен):**

| Столбец | Заголовок | Содержимое |
|---------|-----------|-----------|
| P (16) | Последний редактор | name из users (KIP8_Access); пустой name → email |
| Q (17) | Дата правки | Date обновления записи |
| R (18) | Архив | причина архивации — «Удалён» (пусто = активна) |
| S (19) | Кем удалён | name удалившего (users KIP8_Access) |
| T (20) | Дата удаления | Date архивации |

`list` по-прежнему отдаёт ВСЕ строки, но у архивных флаг `_archived: true`
(`total` — активные, `archivedTotal` — архивные): клиент решает, что скрыть.
`getFilters` архивные строки пропускает. Аудит-коды прежние
(`CABLE_JOURNAL_APPEND/UPDATE/DELETE`) — в сообщениях теперь имя автора/удалившего.

## Шаги деплоя

### 1. Apps Script: полная замена CableJournal.gs

Открыть Apps Script (script.google.com, проект развёртывания AKfycbyt… — ОДИН
проект на kip8 и kip8test), открыть файл **CableJournal.gs**, выделить всё
(Ctrl+A) и вставить содержимое `scripts/CableJournal.gs` из репозитория kip8test
**ЦЕЛИКОМ** (файл-эталон обновлён по актуальному исходнику + правки Task 508).
Сохранить. Маршрутизация Code.gs НЕ меняется (эндпоинты те же).

### 2. Новая версия развёртывания

Deploy → Manage deployments → ✏️ (Edit) → Version: **New version** → Deploy
(тот же URL AKfycbyt… — один деплой на kip8 и kip8test).

### 3. Клиент — GitHub Pages (автоматически)

Коммиты kip8test уже в репозитории: SW `kipia-test-v730` (Ctrl+Shift+R ×1–2).
**Перенос в kip8 — ПО КОМАНДЕ** (команды в заявке НЕ было; одним инкрементом
`kipia-v526→v527` + та же замена CableJournal.gs на общем Apps Script уже
выполнена шагами 1–2 — сервер один на оба приложения).

### 4. Проверка после деплоя

- открыть «Кабельный журнал» → «Обновить» → список прежний (архивных не видно);
- правка любой записи → в Google-таблице P/Q заполнились (name из users);
- удаление записи → строка в таблице осталась с R = «Удалён», S = кто, T = когда;
  в приложении строка исчезла из списка;
- «Печать»/«Сохранить PDF» — без удалённой записи; «Сохранить Excel» — с ней
  (блок «Архив» K–O, статус «Удалён», кем/когда, последний редактор);
- завтрашний крон sync-cables: data/cables.json уменьшается на архивную строку
  (это НОРМА — снимок активного журнала).
