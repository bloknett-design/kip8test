# Task 399 — окно мероприятий: записи мастеров скрыты уровню «min»

**Дата:** 23.09.2026. **Заявка:** «Установи ещё одно условие, если у
пользователя нет доступа к просмотру информации мастеров в табеле
учёта, то и в окне мероприятий не должно быть информации мастеров
(мероприятия, отпуска, СИЗ)».

## Что это

Клиентский фикс (index.html): уровень «min» (`workschedule.view.min`,
ограниченный просмотр табеля) не видит работников «Мастер КИПиА» в
шахматке (скрыты с Task 340 фильтром `_viewEmployees` по признаку
`_isMasterKipia`), но окно мероприятий месяца (`#wsEventsPanel`,
Task 315→394) показывало записи ВСЕХ работников — включая мастеров:
их мероприятия, отпуска и СИЗ ПРОТЕКАЛИ уровню, который в сетке
мастеров не видит.

## Условие «нет доступа к информации мастеров»

Уровень доступа из матрицы (`getMyAccess`, столбцы «График работы»):

| Уровень | Право | Мастера в сетке | Мастера в окне мероприятий |
|---|---|---|---|
| edit | `workschedule.edit` | видны | **показаны** (как прежде) |
| view | `workschedule.view` | видны | **показаны** (как прежде) |
| min | `workschedule.view.min` | скрыты (Task 340) | **скрыты** (Task 399) |
| null | прав нет | раздел целиком недоступен | окно не рендерится |

## Фикс

`_renderMonthEventsPanel` — единственная точка рендера окна
(десктоп-окно тулбара, мобайл-чип «Мероприятия», режим выбранного
дня — один и тот же innerHTML):

- у уровня «min» строится индекс таб. номеров мастеров по ПОЛНОМУ
  списку `_EMPLOYEES` (мастера есть в данных — фильтр сетки про
  отображение строк, не про данные; блок — ДО первого цикла
  записей);
- записи с таб. номером из индекса исключаются из ВСЕХ трёх секций:
  **мероприятия / отпуска / СИЗ** (тот же признак `_isMasterKipia`,
  что и фильтр сетки);
- записи с таб. номером БЕЗ сотрудника в справочнике мастером не
  считаются — показываются (как прежде);
- счётчики секций и пустые состояния пересчитываются сами
  («Мероприятия · сентябрь 2026 · 1» без мастерских записей; если
  после фильтра записей нет — «нет мероприятий в этом месяце»,
  секции «Отпуска»/«СИЗ» скрываются целиком);
- рендер симметричен смене уровня: `_onRoleUpdate` →
  `_applyView({rerender})` → `_renderGrid` → окно.

## После деплоя (пользователю)

Обновить PWA у клиентов: пункт «Обновить» в меню или повторное
открытие сайта (SW kipia-test-v627 подхватится автоматически).
Если роль должна ВИДЕТЬ записи мастеров — поставить ей в матрице
`workschedule.view` (просмотр) или `workschedule.edit` (правка)
вместо `workschedule.view.min`.
