## ЧТО СДЕЛАНО

### 1. Корень бага — пустой код слота «Выходной» трактовался как «очистка»
Слот канона «Выходной, плановый выходной день» несёт **ПУСТОЙ код** (Task 387 —
пользователь убрал «.» из листа «Коды_статусов»; выходной = пустая белая
ячейка). Клиент трактовал выбор «Выходного» как **очистку ячейки**, а
авто-запись (плановая смена после «Сформировать») очистить нельзя — сервер
запрещает `deleteEntry` для авто. Отсюда тост-отказ «Нельзя очистить
авто-запись. Установите статус вручную.» — при том, что пользователь именно
УСТАНАВЛИВАЕТ статус из таблицы.

### 2. `_applyCellStatus` — «Выходной» поверх авто = РУЧНАЯ запись «.»
Вместо отказа — **ручная запись «.»** (легаси-код «Выходного», слот канона с
пустым кодом):
- `«.»`-запись **заменяет** авто-смену на сервере (`setManualEntry` переводит
  запись в `источник='руч'`);
- ячейка **выглядит пустой белой** (рендер легаси-«.» — Task 314/356, класс
  `ws-dot-code`), т.е. день выглядит плановым выходным;
- в **Итогах учёта** и **Талонах** день НЕ рабочий (кроме `other`-счётчика
  итогов — как унаследовано для легаси-«.»), в **печати табеля** — пустая
  клетка;
- **регенерация («Сформировать») запись НЕ трогает** (generateMonth
  пропускает существующие дни) — выходной живёт поверх графика;
- поля записи чистые: `переработка=0`, `замещает=null`, `часы=null`,
  `комментарий=''`;
- уже стоявшая правка (любой код) заменяется — последнее действие
  пользователя выигрывает;
- тост: **«Выходной поставлен поверх авто-записи. Нажмите «Сохранить»»**.

Прочие случаи «Выходного» — без изменений: ручная запись → `__delete`
(удаление); пустая ячейка / локальная правка без записи → ячейка пустая
(запись не нужна — выходной = пустая ячейка).

### 3. `deleteCell` — undo для «.»-выходного
«Удалить запись» на правке **поверх авто** (в т.ч. «.»-выходной) теперь
**снимает правку** — ячейка возвращается к авто-смене, тост «Правка снята —
снова авто-запись» (откат чисто локальный, «Сохранить» не нужен). Прежде путь
уходил в `__delete` по авто-записи и падал бы при сохранении. Чистая
авто-запись без правки — прежний отказ «Можно удалять только ручные записи»;
ручная запись — прежний путь удаления.

### 4. `saveAll` — понятная подсказка при старом сервере
Если сервер отклоняет «.» (`unknown_статус: .` — Apps Script без правки из
п. 5), тост ошибки дополняется подсказкой: **«Код «.» («Выходной») не принят
сервером — обновите WorkSchedule.gs в Apps Script (см. DEPLOY-Task453) или
верните «.» в колонку A листа «Коды_статусов»»**. Правка при этом НЕ теряется
(остаётся в буфере несохранённых).

### 5. Сервер (СПРАВОЧНАЯ КОПИЯ scripts/WorkSchedule.gs) — «.» валиден всегда
`_validateStatusCode`: спец-ветка `if (status === '.') return { ok: true };`
ДО обращения к листу. Обоснование: слот «Выходного» существует на клиенте
ВСЕГДА (выходной = пустая ячейка сетки — состояние есть при любом составе
листа), а колонка A листа кода «.» не содержит (пустой код строки). Без этой
ветки вручную ставится ВСЁ из «Коды_статусов», КРОМЕ «Выходного».
