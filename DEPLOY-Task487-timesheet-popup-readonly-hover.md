# DEPLOY — Task 487: Табель — окно «Мероприятия в этот день» справочное + десктоп-ховер ячеек

**Тип: КЛИЕНТ-ONLY (серверных шагов НЕТ; Apps Script не тронут).**

Заявка: «В разделе "Табель учёта рабочего времени", в ячейках табеля,
в попапе мероприятия "И" или "ПЗ" убери возможность редактирования и
внесения изменений (убери все три кнопки), должен быть только просмотр,
а изменение теперь должно быть возможно только из карт работников. И в
десктопной версии сделай появление попапа, если есть мероприятие, при
наведении указателя мыши.»

## Что изменилось

### Часть 1 — окно «Мероприятия в этот день» стало СПРАВОЧНЫМ

- `_renderEventsPopup`: строки мероприятий БЕЗ кнопок для ВСЕХ ролей
  (включая редакторов) — удалены все ТРИ действия:
  - ✓ клик-галочка отметки выполнения (Task 482),
  - ✎ «Редактировать» — editTraining (Task 309),
  - ✕ «Удалить» — deleteTraining (Task 309);
  ни одного `onclick` в строках окна.
- Правка / удаление / отметка выполнения — **только из карточки
  работника** (страница «Работники», Task 385/418/427): кнопки там
  НЕ тронуты (регресс-тесты 309/427/432 живы).
- Состояние выполнения осталось ИНФОРМАЦИЕЙ: некликабельный маркер
  `ws-done-chk ws-done-on ws-done-ro` (тултип «Выполнено») — тот же
  вид, что прежде был у зрителей; у НЕвыполненных записей маркера нет
  (состояние несёт рамка бейджа сетки ws-ev-done/ws-ev-late, Task 482).

### Часть 2 — ДЕСКТОП-ХОВЕР по ячейке с мероприятием

- `_renderCell`: каждая ячейка `td.ws-cell` получает
  `onmouseenter`/`onmouseleave` (enter/leave НЕ всплывают — td с
  бейджами считается одной зоной).
- `onCellHover` — гейты: вьюпорт **≥1024px** И media
  **(hover: hover) + (pointer: fine)** (планшет/телефон ховера не
  получают); `_saving` (пакетное сохранение); живой КЛИКОВЫЙ попап
  `_popupCell` — неприкосновенен; ячейка без мероприятий окно не
  открывает; **анти-дребезг** `_popupClosedAt` 400 мс (браузер
  переотправляет mouseenter на ячейку под НЕПОДВИЖНЫМ курсором при
  скрытии кловера — окно не «возрождается» сразу после Esc/кловера/
  выбора статуса).
- `_openHoverPopup`: тот же справочный `_renderEventsPopup`,
  позиционирование как у `_openEventsOnlyPopup` (правее ячейки, не
  влезает — левее, клампы по краям), **БЕЗ** кловера `#wsPopupCloser`
  и **БЕЗ** записи `_popupCell`; `mouseenter` окна гасит grace-таймер
  (курсор может идти НА окно — читать длинную тему), `mouseleave`
  окна закрывает.
- `onCellLeave`: grace-таймер **350 мс**; при живом `_popupCell` —
  только сброс ховер-флагов, окно клика НЕ закрывается.
- `closeCellPopup` / `_openCellPopup` / `_openEventsOnlyPopup`
  сбрасывают ховер-состояние (клик перехватывает окно). Esc закрывает
  всё, как прежде.
- КЛИК работает без изменений: редактор — окно кодов + окно
  мероприятий; зритель — только окно мероприятий (Task 319 жив).
  При живом кловере реальные события до ячеек не доходят (оверлей
  перехватывает) — вторая линия защиты `_popupCell`.
