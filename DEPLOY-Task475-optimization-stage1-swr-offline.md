ранее подгруженные данные должны сохраняться в памяти устройства, загрузка

## Детали

- **SWR-данных**: клон кэша для сравнения делается ДО отдачи ответа
  (иначе `clone()` падает «body locked»); кэш обновляется и вкладки
  уведомляются ТОЛЬКО при фактическом отличии текста (защита от цикла
  «уведомление → перезагрузка → уведомление»); fallback на precache-копию
  из `CACHE_NAME` после чистой установки; Background Sync
  (exam-tickets) пишет в тот же персистентный кэш.
- **Слушатель страницы** (`DATA_REFRESHED` + `path`): сброс in-memory
  кэша раздела (`resetSectionDataCache`: devices/lockouts/valves/
  regulators/projects/cables/phonebook/exam-tickets) — свежая версия
  поднимется при следующем открытии раздела, БЕЗ перерисовки под
  пользователем (незаметно). Прежнее поведение для билетов сохранено.
- **Гигиена кэшей**: activate держит в `DATA_CACHE_NAME` только
  `/data/*.json`; `CACHE_NAME`-чистка по ASSETS — прежняя; bypass
  Apps Script НЕ тронут — авторизация/heartbeat ВСЕГДА напрямую в сеть.
- **Офлайн-вход**: токен сохраняется, роль догоняется
  (`_startOfflineTokenRetry` / `_stopOfflineTokenRetry`; ручной вход
  через verifyOTP останавливает повтор).
