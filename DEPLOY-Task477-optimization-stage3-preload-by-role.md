# DEPLOY — Task 477: Этап 3 оптимизации — фоновая предзагрузка по правам роли

**Тип: КЛИЕНТ-ONLY (серверных шагов НЕТ).**

Заявка (завершение этапов 1–2): «в принципе должны незаметно
подгружаться все данные приложения (только из тех разделов и
данных, к которым у пользователя есть доступ согласно его роли)».

## Состав изменений

### index.html

1. **KipPreload — новый модуль** (глобальный `var`, в script-блоке
   KipDB). После входа (задержка 4 с от показа интерфейса) строит
   манифест по правам роли и греет кэши ПО ОДНОМУ элементу:
   - **статические `data/*.json`** доступных по роли разделов —
     обычный `fetch` через SWR (Task 475): SW отвечает из
     персистентного DATA-кэша мгновенно и сам ревалидирует сеть
     фоном — прогрев тем же путём, что обычное открытие раздела;
   - **серверные данные** (табель / каб. журнал / расходомеры /
     отметки мероприятий) — те же READ-ONLY экшены, что используют
     разделы; копии пишутся в KipDB (Task 476) — разделы откроются
     мгновенно даже офлайн при первом заходе.
2. **Права роли**: манифест строится по `KipAuth.canAccess`
   (серверная матрица KIP8_Access + легаси-карта — как видимость
   кнопок UI). Гость («Общий доступ») — пустая очередь; роль
   «Запрет» — пустая очередь; серверные группы — только с токеном.
   Сервер остаётся источником прав: каждый экшен гейтится на его
   стороне, preload читает только то, что роль и так видит.
3. **Вежливость к сети/устройству**:
   - последовательная обработка (один элемент за раз),
     `requestIdleCallback` (+fallback `setTimeout`) и пауза
     **≥ 1.5 с** между элементами;
   - **Data Saver / 2g / slow-2g — очередь не запускается вовсе**;
   - офлайн — пауза, событие `online` — продолжение;
   - `logout` — остановка и сброс очереди (до чистки копий).
4. **KipAuth._schedulePreload** — запуск через 4 с после входа;
   вызывается из 5 точек (verifyOTP, bootstrap быстрый/медленный
   путь, офлайн-повтор входа, фоновая проверка сессии).
   `logout()` → `KipPreload.stop()` до `_wipeLocalServerData()`.

## Поведение пользователя (что изменится)

- После входа приложение в ФОНЕ (незаметно, по одному, в паузах
  простоя) подгружает все данные разделов, доступных роли: в
  следующий раз каждый раздел открывается мгновенно даже офлайн/при
  первой загрузке на этом устройстве.
- Пользовательский трафик приоритетнее: паузы ≥1.5 с между
  элементами, экономия трафика (Data Saver / 2G) отключает
  предзагрузку целиком.
- Никаких новых кнопок/интерфейса — предзагрузка полностью тихая
  (консоль: логи `[KipPreload]` для диагностики).
