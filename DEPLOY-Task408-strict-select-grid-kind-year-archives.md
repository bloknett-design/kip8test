**Заявка:** «Мне не нужно объединять блоки инструктажи и мероприятия, это разные
информационные блоки. В блоке Повторные инструктажи и периодическая проверка знаний
должна содержаться информация о дате проведения повторных инструктажей и повторной
периодической проверки знаний и период их проведения, на основании этих данных в шахматке
табеля учёта рабочего времени должны расставляться коды значков И и ПЗ с указанием вида
инструктажа или проверки знаний. Список шаблонных видов инструктажей и проверки знаний
должен храниться на отдельном листе, из него должна подтягиваться вся необходимая
информация в таблицу "Инструктажи", информация в которой будет формироваться при помощи
ручного выбора пользователем инструктажей и проверки знаний из шаблонного списка, а также
формироваться годовые архивы с отметкой выполнения этих событий, а также в зависимости от
периода проведения формироваться следующие сроки проведения. А блок мероприятия должен
содержать прогул, обучение, примечание, и также формировать коды значков в шахматке и
архив».

**Уточнения пользователя (все 5 — рекомендованные варианты):** стрелки ‹год› в блоках
карточки; тултип бейджа (вид); select по типу; снимок срока на конец года; строка-подсказка
пункта в форме.

**Контекст:** блоки и так раздельные (Task 405: «Мероприятия» — 1-я колонка,
«Повторные инструктажи…» — 2-я, СИЗ — 3-я) — объединения нет; бейджи И/ПЗ/ОБ/ПР/*
в шахматке из обеих таблиц уже ставились (Task 303/306/314); блок И-и-ПЗ с датами,
периодичностью и «след. срок/просрочено» — Task 407 (прод теста v634). Новый — только

## ЧТО СДЕЛАНО

### 1. СЕРВЕР (WorkSchedule.gs) — `eventsAll`
- `listTrainings` отдаёт новое поле **`eventsAll`** — ВСЕ записи листа «Мероприятия»
  БЕЗ фильтра года (аналог instrAll из Task 407, но для мероприятий);
- листа нет / старый сервер — пустой массив (клиент мягко деградирует к годовому
  срезу `_TRAININGS` года шахматки — архивная навигация при этом показывает
  только текущий год табеля, не ошибка);
- `trainings` (годовой срез) и `instrList`/`instrAll` (Task 407) — не тронуты:
  бейджи/окно месяца/печать/сводная работают как раньше.

### 2. ШАХМАТКА — тултип вида на бейджах (заявка: «коды И и ПЗ с указанием вида»)
- бейдж события в ячейке получает `title`: **«И — Охрана труда» / «ПЗ —
  Электробезопасность» / «ОБ — …» / «* — …»** — код + тема записи
  (наведение показывает вид инструктажа/проверки знаний);
- виртуальному бейджу (статус остался, запись удалена) — полное имя кода из
  справочника; сама ячейка (td) — по-прежнему БЕЗ title (Task 311 сохранён:
  единственный `title=` в `_renderCell` — бейдж);
- клик по ячейке по-прежнему открывает карточку с полным блоком.

### 3. КАРТОЧКА — годовые архивы (стрелки «‹ год ›»)
- заголовки блоков **«Мероприятия · 2026 ‹ ›»** и **«Повторные инструктажи и
  периодическая проверка знаний · 2026 ‹ ›»** (страница «Работники»): стрелки
  листают год ПО РАБОТНИКУ (выбор хранится в `_wtabYear[таб_номер]`,
  переживает перерисовки; возврат к году табеля снимает выбор);
- границы навигации: снизу — самый ранний год записи работника (по
  instrAll/eventsAll/срезу года), сверху — max(текущий год; год табеля);
  на границах стрелки приглушены (`ws-ynav-off`), кликов нет;
- записи выбранного года — `_wtabYearRecords`: единый пул
  instrAll + eventsAll + годовой срез `_TRAININGS` (для старого сервера),
  дедуп по id (без id — дата+тема), деление по типу → ins/evs — оба блока
  показывают отметки выполнения выбранного года;
- **снимок сроков в архиве**: «последний» ограничен концом выбранного года;
  архивный год — нейтральная строка **«след. срок (на конец 2025): 10.09.2025»**
  (без красного «⚠ просрочено» — состояние того года); текущий/будущий год —
  прежние правила «след. срок … ✓» / «⚠ просрочено с …»;
- пустые состояния: **«— за 2025 год не проводился»** (в текущем году читается
  естественно) / «— не проводился» (никогда);
- попап ячейки у сетки — по-прежнему за ГОД ШАХМАТКИ (без стрелок);
- сводная «Общая» — год табеля (не менялась).

### 4. ФОРМА — строгий выбор из шаблона (заявка: «ручной выбор»)
- тип «инструктаж»/«проверка знаний»: поле «Тема» — **СТРОГИЙ select** пунктов
  «Список_И_и_ПЗ» соответствующего вида («— выберите из списка —» + названия);
  свободного ввода нет — внеплановые темы сначала добавляются в список;
- **подсказка пункта** под полем (заявка: «вся необходимая информация
  подтягивается»): «раз в 6 месяцев · Основание: не реже 1 раза в 6 месяцев»
  (периодичность + основание из шаблона; разовый/без данных — строка скрыта);
- типы обучение/прогул/примечание — прежний свободный текстовый ввод;
  ОТСУТСТВИЕ шаблона (лист не создан/сервер старый) — деградация в свободный
  ввод (datalist Task 407 остаётся);
- ПРАВКА: тема совпала с пунктом (регистр/пробелы/«ё» не важны) — пункт
  выбран; тема «вне списка» — отдельный пункт «… (вне списка)» (значение
  сохранится, можно перевыбрать);
- SUBMIT: тема читается из select (валидация «Выберите пункт из списка»),
  из input — для остальных типов.
