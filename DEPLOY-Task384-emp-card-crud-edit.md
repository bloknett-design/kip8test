## ЧТО СДЕЛАНО (клиент — работает сразу после пуша)

### Карточка сотрудника (клик по ФИО в шахматке) — ЦЕНТР ПРАВКИ
- **Профиль** → строка «Правка данных…» (только редакторам `workschedule.edit`):
  шторка `#wsEmpSheet` в режиме ПРАВКИ («Правка сотрудника» / «Сохранить»),
  все поля профиля (ФИО/тип/смена/шаблон ротации/старт цикла/дата приёма/
  должность/комментарий), **таб. № — readonly** (PK: на него ссылаются листы
  «Записи_графика»/«Инструктажи»/«Отпуска»). Отправка →
  `workSchedule.updateEmployee`. Шапка сетки «Сотрудник +» — по-прежнему
  СОЗДАНИЕ («Новый сотрудник» / «Добавить», таб. № вводится).
- **Отпуска** → у каждого периода кнопки **✎ (правка)** и **✕ (удаление)**
  (редакторам, только записям с id): ✎ — шторка `#wsVacSheet` в режиме
  «Правка отпуска» («Сохранить»), префилл сотрудника/части/дат/комментария,
  проверки пересечения/лимита 42 дн. и подбор «части» НЕ считают саму
  редактируемую строку; отправка → `workSchedule.updateVacation`.
  ✕ — подтверждение → `workSchedule.deleteVacation` (был жив, UI вернули).
  «+ Отпуск…» (Task 312) — на месте.
- **Мероприятия** → правка/удаление ✎/✕ были (Task 309); добавлена строка
  **«+ Мероприятие…»** с префиллом сотрудника карточки
  (`onEmpAddTraining` → `openTrainingForm(tabNo)`).

### После правок
- Шахматка перезагружается автоматически (`loadGrid(true)`); перерасстановка
  кодов «О» (отпуска) и мероприятий — кнопкой **«Сформировать»** (как прежде).
- Зрители (`workschedule.view`) видят карточку БЕЗ кнопок правки (Task 340).

## ⚠️ СЕРВЕРНЫЕ ШАГИ — ВЫПОЛНИТЬ ВРУЧНУЮ В APPS SCRIPT

Новые эндпоинты требуют обновления Apps Script (ОДИН бэкенд на kip8 и
kip8test). Пока сервер не обновлён, кнопки «Сохранить» в режимах правки
данных сотрудника и правки отпуска вернут ошибку
`Unknown action: workSchedule.updateEmployee / updateVacation` —
клиент покажет её в тосте, ничего не сломается.

1. Открыть редактор Apps Script (тот же проект, где `Code.gs`,
   `Utils.gs`, `WorkSchedule.gs`):
   https://script.google.com/… (проект развёртывания AKfycbyt…)
2. **`Code.gs`** — в `doPost` после `case 'workSchedule.deleteVacation':`
   добавить два case (копия из репозитория `scripts/Code.gs`):
   ```js
   case 'workSchedule.updateEmployee':
     return _json(WorkSchedule.updateEmployee(payload));

   case 'workSchedule.updateVacation':
     return _json(WorkSchedule.updateVacation(payload));
   ```
3. **`WorkSchedule.gs`** — заменить целиком на версию из репозитория
   `scripts/WorkSchedule.gs` (добавлены методы `updateEmployee` — после
   `dismissEmployee`, и `updateVacation` — после `addVacation`; остальное
   без изменений; сверить по `git diff` при переносе).
4. Нажать **«Сохранить»**, затем **«Выполнить» → «Новое развёртывание»**
   (или Управление развёртываниями → Изменить → Новая версия) — тип
   «Веб-приложение», доступ «Любой», выполнение «от моего имени».
5. Проверить: открыть карточку сотрудника → «Правка данных…» → «Сохранить»
   без изменений → тост «Данные сотрудника обновлён».

### Семантика новых эндпоинтов (для аудита)
- `updateEmployee {таб_номер, ФИО, тип, смена, шаблон_ротации, старт_цикла,
  дата_приёма, должность, комментарий}` — гейт `_requireWrite`
  (право `workschedule.edit` из матрицы KIP8_Access); обновляет B..G и J..K
  строки листа «Сотрудники»; **A (таб_№) не меняется** (PK), **H/I
  (увольнение/архив) не трогаются** (для этого `dismissEmployee`); аудит
  `WORKSCHEDULE_UPDATE_EMPLOYEE`.
- `updateVacation {id, таб_номер, часть, дата_начала, дата_окончания,
  комментарий}` — гейт `_requireWrite`; находит строку листа «Отпуска» по
  id, обновляет B..F (B — текстовый формат `@`, Task 304: ведущие нули);
  валидации как `addVacation`, но **пересечение/дубль части не считают саму
  строку**; аудит `WORKSCHEDULE_UPDATE_VACATION`.
