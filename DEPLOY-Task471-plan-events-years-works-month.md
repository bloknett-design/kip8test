# DEPLOY — Task 471: «Плановые мероприятия» — кнопка предыдущих годов + динамичное окно «Работы на месяц»

**Дата:** 03.10.2026. **Что менялось:** клиент (index.html, sw.js — уже в
репозитории, деплой GitHub Pages автоматически) + **СЕРВЕР Apps Script

## Суть

Раздел «Плановые мероприятия» (таблица Task 460, отметки Task 463/464,
раскладка Task 468, описание Task 469, строки Task 470) получает
переключение годов и работы месяца (заявка Task 471):

| Элемент | Поведение |
|---------|-----------|
| Кнопка «◀» в шапке таблицы | СЛЕВА от «2026 год»; **активна только если в архиве есть записи за предыдущие годы** (`planEvents.years`); клик — к ближайшему младшему году архива (2026 → 2025 → 2024…), при исчерпании — возврат к текущему году. Отметки года перезагружаются |
| Месяцы шапки (Янв. … Дек.) | **Кликабельны**: выбирают месяц, за который правое окно показывает информацию (подсветка выбранного месяца + синхронизация с мобайл-селектором Task 464) |
| Ячейка «Работы на следующий месяц» (наименование) | Вместо описания раздела в правом окне — **интерфейс ввода работ на следующий месяц**: поле «Описание работы» + «Добавить» (Enter тоже работает), перечень внесённых работ с «×» (удаление) |
| Ячейка «Работы на месяц» (наименование) | В правом окне — **перечень работ на текущий (выбранный) месяц**: у каждой работы кнопки **Выполнено / Частично / Не выполнено**; отметка пишется в архив на лист «Работы на месяц» (дата отметки — сегодня) |
| Ячейка «Мероприятия» (шапка) | Снова показывает **описание раздела** (Task 469) |
| Выбранный месяц × вид | «Работы на месяц» → работы выбранного месяца; «Работы на следующий месяц» → работы следующего месяца (декабрь → **январь следующего года**) |
| «Обновить» (шапка страницы) | Перезагружает отметки + годы архива + открытый вид работ |
| Старый сервер (до шагов ниже) | Кнопка годов не активируется, окно работ показывает понятную ошибку; отметки/описание работают как раньше |

**Работы** — лист **«Работы на месяц»** файла Мероприятия_КИП_ИОС
(`https://docs.google.com/spreadsheets/d/1uX8Bz6FBS9HniZfWQnHeeyccTwwjwyvpPFWyFkIclCs/edit`):

| Столбец | Содержимое |
|---------|-----------|
| A `id` | автоинкремент (max + 1) |
| B `год` | год месяца работ (число) |
| C `месяц` | 1..12 |
| D `работа` | описание (до 500 символов, вносит пользователь) |
| E `статус` | `''` \| `выполнено` \| `частично` \| `не выполнено` |
| F `дата_статуса` | дата отметки выполнения (текст `ГГГГ-ММ-ДД`) |
| G `email` | кто внёс работу / отметил (из сессии) |
| H `время_изменения` | timestamp последнего изменения |

Доступ — то же право `plan.events` (Task 462): кто видит раздел — тот
вносит и отмечает работы. Идемпотентность: `planWorks.remove` работы
нет → `removed: false` без ошибки; `planWorks.setStatus` правит все
дубли id; битые строки листа молча пропускаются (как «Архив» Task 463).
Ручные правки листа поддерживаются.

## Шаги деплоя

### 1. Apps Script: обновить файл PlanEvents.gs

Открыть Apps Script (script.google.com, проект развёртывания AKfycbyt…
— ОДИН проект на kip8 и kip8test), открыть файл **PlanEvents.gs**,
**заменить содержимое ЦЕЛИКОМ** на `scripts/PlanEvents.gs` из
репозитория kip8test. Новое: `planEvents.years` + `planWorks.list /
add / remove / setStatus` (лист «Работы на месяц»), SRV_VER → 471.

### 2. Apps Script: маршрутизация Code.gs

В файле `Code.gs` того же проекта добавить ПЯТЬ case в `doPost` (перед
`default:`) — эталон `scripts/Code.gs` в репозитории уже содержит их:

```js
      // === Task 471: годы архива + работы месяца ===
      case 'planEvents.years':
        return _json(PlanEvents.years(payload));

      case 'planWorks.list':
        return _json(PlanEvents.listWorks(payload));

      case 'planWorks.add':
        return _json(PlanEvents.addWork(payload));

      case 'planWorks.remove':
        return _json(PlanEvents.removeWork(payload));

      case 'planWorks.setStatus':
        return _json(PlanEvents.setWorkStatus(payload));
```

### 3. Новая версия развёртывания

Deploy → Manage deployments → ✏️ (Edit) → Version: **New version** →
Deploy (тот же URL AKfycbyt… — один деплой на kip8 и kip8test).

### 4. Лист «Работы на месяц» (одноразовый скрипт)

**+ → Создать файл «PlanWorksInit.gs»**, вставить содержимое
`scripts/PlanWorksInit.gs` из репозитория, выполнить функцию
**`planWorksDeploy`** (первый запуск попросит авторизацию — разрешить).
Скрипт идемпотентен: создаст лист «Работы на месяц» с заголовками
(8 колонок, текстовый формат дат/работ — паттерн Task 304) и ничего не
перезапишет, если лист уже есть. После выполнения файл можно удалить
из проекта — копия-эталон в `scripts/` репозитория.
Проверка: функция `planWorksStatus` — наличие листа, заголовки, строки.

### 5. Клиент (kip8test)

Уже в репозитории (SW kipia-test-v695), GitHub Pages деплоится

## Проверка после деплоя

1. Войти под ролью с галочкой `plan.events` → «Документация ИОС» →
   «Плановые мероприятия»: описание раздела; кнопка «◀» слева от
   «2026 год»; текущий месяц подсвечен в шапке.
2. Кнопка «◀»: если в листе «Архив» есть записи за 2025 — клик
   переключает шапку на «2025 год» и перезагружает галочки; повторный
   клик (если 2024 нет) возвращает «2026 год». Если архива за
   предыдущие годы нет — кнопка тусклая и некликабельная.
3. Клик по месяцу в шапке (например, «Ноя.») — подсветка переезжает.
4. Клик по ячейке «Работы на следующий месяц» → правое окно: интерфейс
   ввода («Месяц работ: Ноябрь 2026»), поле + «Добавить», перечень.
   Внести работу → строка появилась; «×» → удалилась.
5. Клик по ячейке «Мероприятия» (шапка) → снова описание раздела.
6. Клик по ячейке «Работы на месяц» → перечень работ месяца; нажать
   «Выполнено» → зелёный бейдж «Выполнено — ДД.ММ.ГГГГ», кнопка
   подсвечена. Открыть файл Мероприятия_КИП_ИОС → лист «Работы на
   месяц»: строки работ + статус + дата + email + время.
7. Декабрь + «Работы на следующий месяц» → «Месяц работ: Январь 2027».
8. Мобильный (≤1023px): один месяц + селектор; смена селектора меняет
   месяц правого окна.
