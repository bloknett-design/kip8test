## НОВЫЙ ФАЙЛ = Excel-реимпорт: валидация + харденинг

Параметры `rtpof=true&sd=true` — признак файла Drive, пересохранённого
из Excel. Структура сверена ДО правки (scripts/task560-check-sheet.py):
валидный xlsx-экспорт, все 4 листа `_app` присутствуют, заголовки
Приборы_app 24 колонки с ключевые полями ППР-индикации (Task 478/479),
totals совпадают с текущими данными (1279/518/325/268), ppr_chart
идентичен. НО прогон sync-скриптов вскрыл ДВА артефакта реимпорта
(сверка data/*.json до/после, scripts/task560-compare-data.py):

1. **Пустые хвостовые колонки** — Excel растянул формат на колонки
   правее данных: Блокировки_app 13→26, Клапана_app 24→26,
   Регуляторы_app 12→26 заголовков (записи пустые ключи и так
   пропускали, но массив `headers` раздувался).
2. **Целые числа как float** — Excel хранит целые double'ом:
   `9984837` → `9984837.0`, `ID: 0` (число) → `"0.0"` (строка —
   ломается int-конвертация ID по isdigit), `45976` → `45976.0`.

Оба нейтрализованы ХАРДЕНИНГОМ 4 sync-скриптов
(scripts/task560-patch-sync.py, патчи A+B с маркерами Task 560):
(A) хвостовые пустые заголовки срезаются; (B) целые float приводятся
к int ДО str(). На Google-нативной таблице патчи НИЧЕГО не меняют
(там целые — int, пустых хвостовых заголовков нет) — сверено:
после патчей devices/valves/regulators — контент идентичен текущему
(у devices отличается ТОЛЬКО дата заметки «Изменения в перечнях от»
19.11 → 24.11 — правка пользователя), lockouts — реальные правки
пользователя (см. ниже). Без харденинга ночной крон залил бы
артефакты в data/*.json (ID строками, headers 26).
