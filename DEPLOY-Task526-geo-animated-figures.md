# DEPLOY — Task 526: Геометрия — анимированные «живые» пояснительные схемы в рамках

**Тип: ТОЛЬКО КЛИЕНТ (HTML + CSS + JS в index.html). Сервер (.gs),
листы Google Sheets и деплой веб-приложения НЕ менялись.**

Заявка: «В разделе Главная / Инженерные калькуляторы / Геометрия,
в расчётах геометрических фигур переделай пояснительные картинки,
сделай их анимированными с отображением реальных расчётов фигур,
и переделай их отображение немного больше и без погрешностей в
отображении линий и прочего, отобрази их в рамках с непрозрачным
фоном бежевого-бело-молочного цвета в светлой теме и на твой
выбор в тёмной теме.»

## Что сделано (код — kip8test @v739)

### Правка

На всех 6 страницах геометрии (Круг, Кольцо, Цилиндр
вертикальный, Цилиндр горизонтальный, Сфера, Конус) статичные
пояснительные SVG-картинки заменены «живыми» анимированными
схемами в рамках `.geo-fig-frame` с непрозрачным фоном:

- **светлая тема** — бежево-бело-молочная «бумага» `#F7F2E6`
  (по заявке), чернила `#2F5687`, размеры терракотой `#B05537`;
- **тёмная тема** (выбор агента) — графитово-синий «чертёжный
  лист» `#17222E`, контур `#8FBCE8`, размеры тёплым золотом
  `#E2A96E`, результат — канонный зелёный значений.

### «Живость» схем

1. **Реальные расчёты**: фигура строится JS-движком из ТЕКУЩИХ
   значений полей ввода: пропорции реальные (кольцо d/D, цилиндр
   H/D, конус H/D, горизонтальный резервуар L/D и уровень h/D);
   подписи размеров — фактические значения («D = 100 мм»,
   «h = 1,5 м»); под схемой — блок живого расчёта «формула =
   значение» (та же математика и то же `formatNumber`, что в
   `calcGeo*` — числа совпадают с панелью «Результат»).
2. **Анимация** (CSS keyframes `gf-*`): контур «прочерчивается»
   штрих-маской, у круга радиус обегает окружность и остаётся под
   45°, у горизонтального резервуара жидкость «наливается»
   (gf-rise + clipPath по силуэту), размеры и результат
   проявляются с каскадной задержкой. Открытие страницы и кнопка
   «Рассчитать» → `geoFigPlay` (с анимацией); ввод в поля →
   `geoFigUpdate` (мгновенная перестройка, класс `.geo-static`).
   `prefers-reduced-motion` — схема сразу в конечном состоянии.
3. **Размер и точность**: единый viewBox 240×190, рамка до 320px
   (прежде — 220px / 55% ширины). Стрелки размеров — ТОЧНЫЕ
   треугольники, вычисленные в координатах (`gfArrow`);
   SVG-маркеры убраны (их refX смещал остриё — прежние
   «погрешности отображения линий»); подписи цветом темы (прежде
   `#ffffff` — не читались в светлой теме); дуги и эллипсы — из
   вычисляемых координат, без «дрожания» разрядности.

### Детали реализации

1. **`index.html` — CSS**: система `.geo-fig-frame` (рамка,
   палитры обеих тем через `--gf-*`), `.geo-fig-res` (блок живого
   расчёта), keyframes `gf-draw/gf-fade/gf-dim/gf-res/gf-rise/
   gf-sweep`, гварды `:not(.geo-static)`, `@media
   (prefers-reduced-motion: reduce)`. Старые `.geo-svg-container`
   / `.geo-svg` удалены.
2. **`index.html` — разметка**: 6 рамок `#xxFigFrame` с пустым
   SVG `#xxFig` + блок `#xxFigRes`; рендер — JS при открытии
   страницы (хук `GEO_FIG_PAGES` в `navigateTo`).
3. **`index.html` — JS**: движок `[Task 526 geo-fig engine]`
   (`gfN/gfArrow/gfDimH/gfDimV` + 6 сборщиков фигур +
   `geoFigVals/geoFigBuild/geoFigRender/geoFigPlay/geoFigUpdate`);
   все 6 `calcGeo*` после валидации полей перезапускают схему
   (`geoFigPlay`); oninput всех 11 полей — `geoFigUpdate`.
4. **Тесты**: `test-task526.js` ×26 (SRC HTML/CSS/JS, VM:
   подписи, живые числа = calcGeo*, реальные пропорции, края
   h=0/h=D, точность стрелок, без маркеров/#ffffff; SW).
   Браузер 170/170 (обе темы, мобайл 390×844, взаимодействие:
   ввод → мгновенно, «Рассчитать» → анимация), VLM 32/32.
