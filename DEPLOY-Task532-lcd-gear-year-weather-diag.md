## ЧТО С ДОЖДЕМ ПОГОДОЙ (диагностика заявки)

Проверено снаружи: клиент корректен (KipAuth.api резолвит внутренний
`data`), живая страница meteoinfo.ru парсится теми же регэкспами
(HTTP 200, −0.7°C, время наблюдения на месте), кэш клиента неудачи НЕ
кеширует. Значит, «--» на экране — серверная сторона: либо
**развёртывание Apps Script не содержит эндпоинт** (файлы заменены,
но версия деплоя не создана — тогда сервер отвечает
`Unknown action`), либо **UrlFetchApp не может забрать meteoinfo.ru**
(исходящие IP Google / фильтрация по заголовкам).

Чтобы это больше не было невидимым, сделано (см. ниже): сервер
возвращает **diag-цепочку попыток**, клиент показывает её в
настройках информера, кнопка «Обновить сейчас» переспрашивает
мгновенно. Точная причина будет видна Вами сразу в панели настроек.

## Что сделано (код — kip8test @v745)

### 1. Погода: getWeather v2 — надёжность + видимость причин

- **Браузерные заголовки** `User-Agent` / `Accept` / `Accept-Language`
  у обоих запросов: «голые» запросы UrlFetchApp часть сайтов режет.
- **Резервный источник open-meteo.com** (JSON API — без разбора HTML,
  не зависит от вёрстки meteoinfo.ru): WMO-код → балл облачности +
  текст явления (маппинг иконок клиента работает без изменений),
  ветер в м/с, направление в румбах, давление гПа → мм рт.ст.,
  местное время наблюдения (Asia/Novokuznetsk). Основной источник —
  по-прежнему meteoinfo.ru (Гидрометцентр России, как в заявке
  Task 530); резерв включается только при сбое основного.
- **diag в ответе**: перечень попыток с HTTP-кодами и причинами
  (`meteoinfo:http_403; open-meteo:http_200`). Успех тоже несёт diag.
- Клиент: **статус в настройках** («Есть данные: −12° — meteoinfo.ru
  (набл. 15 октября, 13:00)» / «Источник не дал данных:
  meteoinfo:http_403; …» / «Сервер не знает эндпоинт getWeather —
  обновите развёртывание Apps Script…» / «Сеть/сервер недоступны») +
  кнопка **«Обновить сейчас»** — форс-опрос без ожидания цикла;
  панель перерисовывается по факту ответа.

### 2. Клик-семантика: шестерёнка / окно — РАЗДЕЛЬНЫЕ попапы

- **Шестерёнка `#wsLcdGear`** — в правом верхнем углу информера
  (в обёртке, справа от рамки): SVG-иконка, 22×22, стиль корпуса
  (выступ/утопление при активной), `aria-expanded`.
- Клик по шестерёнке → **ТОЛЬКО блок настроек** `#wsLcdSet`
  (по умолчанию под шестерёнкой у правого края).
- Клик по **окну** информера → **ТОЛЬКО календарь** `#wsLcdCal`.
- Попапы независимы: закрываются по отдельности, при открытых обоих
  панель настроек смещается СЛЕВА от календаря (CSS `:has()`),
  Esc / клик мимо / уход со страницы закрывают оба. z-фикс шторок
  «Итоги учёта»/«Обозначения» расширен на оба попапа.

### 3. Календарь: ВЫБОР ГОДА

- Строка «**Год ‹ [селект] ›**» под головой календаря: селект текущего
  года ±10 (список расширяется автоматически при навигации дальше),
  кнопки ‹ › — шаг ±1 год, синхронизация при переносе года
  (декабрь → январь), «Сегодня» возвращает текущие месяц и год.
- Заголовок — только название месяца (год — в своей строке).

### 4. Кириллица пиксельного шрифта (заявка «буквы не соответствуют»)

Найдены и исправлены объективные дефекты FONT5 (5×7):

- **«Ь» был НЕОТЛИЧИМ от «Е»** (стем + 3 перекладины) — главная
  видимая проблема: в «ПОНЕДЕЛЬНИК»/«ВОСКРЕСЕНЬЕ» мягкий знак
  читался как Е. Теперь: стем + высокая чаша (как Ъ без рожки);
  «Ы» приведена к той же форме.
- **«Ч»** — перекладина не доходила до левого стема (разрыв,
  читалось как «4»). Исправлено.
- **«Д»** — замкнутая коробка читалась как □/О: арка сверху +
  стемы + «ножки» (вариант выбран A/B/C/D-тестом чтения «ЛЬДИНЫ»).
- **«Л»** — дрейф левой ноги читался как «П» («КОНТРОЛЬ» →
  «КОНТОРПЬ» в тесте чтения): симметричный пик.
- **«З»** — левый стем сверху делал замкнутый угол («9»): гладкая 3.
- **«Э»** — угловые точки слева делали «Е»: полная средняя черта.
- **«Ю»** — асимметричная верхушка чаши: симметричная чаша.
- **ДОБАВЛЕН «Ё»** — его НЕ БЫЛО: «ё» в верхнем регистре не имела
  глифа и **исчезала** из сообщений (комментарий «нормализуется в Е»
  не соответствовал коду). Теперь Ё с двумя точками.
- **ДОБАВЛЕНЫ « » – — …** — исчезали из «пейджера» (данные Табеля
  содержат кавычки и тире). «№» → «N» (глифа номера в 5×7 нет).
- Верификация: VLM-тест **чтением** — все 7 дней недели,
  «КОНТРОЛЬ», «ЛЬДИНЫ», сообщение с «Ё», « » и «—» читаются
  однозначно как русские слова.
