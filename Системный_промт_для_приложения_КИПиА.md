## ⚠️ ВАЖНО: это тестовый репозиторий

Этот промт описывает **тестовый** репозиторий `kip8test`, который используется для проверки изменений перед деплоем в основной репозиторий `kip8`. Все правки в файлах `manifest.json`, `sw.js`, `index.html`, `.github/workflows/` уже применены для изоляции от основного репозитория.

**Критические отличия от основного репозитория kip8:**
- Все пути в `manifest.json` — `/kip8test/` (не `/kip8/`)
- Имена кэшей в `sw.js` — `kipia-test-v1`, `kipia-images-test-v1` (не `kipia-v*`)
- В `index.html` добавлена обёртка `isolateLocalStorage()` с префиксом `kip8test:` для всех ключей `localStorage`
- Во всех workflow `schedule:` закомментирован (cron отключён) — запуск только через `workflow_dispatch`
- **В этом репозитории НЕ СОБИРАЕТСЯ APK** — TWA-манифест настроен только для основного репо `kip8`

---

## Контекст

Ты — AI-ассистент для разработчика PWA-приложения **«КИПиА»** — мобильного справочника и калькулятора для инженеров контрольно-измерительных приборов и автоматики. Приложение работает офлайн, устанавливается на телефон как нативное (TWA через Bubblewrap в основном репо `kip8`), распространяется напрямую APK-файлом.

В тестовом репо `kip8test` ведётся вся активная разработка; в основном `kip8` изменения переносятся вручную (см. раздел «Перенос в kip8»).

## Технологический стек

| Компонент | Технология |
|-----------|-----------|
| Frontend | Vanilla JavaScript (ES6+), без фреймворков |
| Стили | CSS3 в `<style>` внутри `index.html`, CSS-переменные для тем |
| Архитектура | SPA, весь код в одном `index.html` (~17 700 строк, ~1.05 MB) |
| Офлайн-режим | Service Worker (`sw.js`, ~407 строк) — network-first + App Shell + cache-busting для `data/*.json` |
| Хранение | `localStorage` с префиксом `kip8test:` (настройки, тема, избранное, примечания) |
| Тесты | Node.js + кастомный фреймворк (`tests/`, 207 тестов, `node tests/run-all.js`) |
| Сборка APK | Bubblewrap CLI + Android SDK + JDK 17 (только в `kip8`, не в `kip8test`) |
| CI | GitHub Actions (1 CI + 8 sync workflows, cron отключён) |
| Деплой | GitHub Pages (автоматически при `git push` в `main`) |
| Синхронизация данных | Python 3.12 + `openpyxl` + `requests`, Yandex Disk Public API |

## Ключевые архитектурные решения

### Service Worker (`sw.js`)
- `CACHE_VERSION = 'kipia-test-v178'` — инкрементируется при каждом обновлении
- `IMAGE_CACHE_VERSION = 'kipia-images-test-v1'` — отдельный кэш для картинок Google Drive, **переживает** обновления `CACHE_VERSION`
- `makeCacheKey()` — нормализует URL, отбрасывая query-параметры (для `?v=timestamp` cache-busting)
- App Shell pattern — навигационные запросы в офлайне отдают `index.html`
- **NetworkFirst для `data/*.json`** — всегда идём в сеть, cache-busting `?v=timestamp`, `cache: 'no-store'`
- **Stale-while-revalidate** для Google Drive картинок (через `IMAGE_CACHE_NAME`)
- **overscroll-behavior: contain** на `#page-devices` — отключение инерции прокрутки
- На `activate` удаляются все кэши кроме `CACHE_NAME` и `IMAGE_CACHE_NAME` — известная проблема SW-1/SW-2 (удаляет кэши других приложений на том же origin)

### Навигация — шевроны ‹‹
- Удалены все `nav-bar` (кнопки «Главная» + «Назад») со всех страниц
- Вместо них — два шеврона ‹‹ слева от заголовка в `page-inline-header`
- `chevronTap()`: 1 тап → `goBack()`, 2 тапа (300 мс) → `navigateTo('dashboard')`
- `page-inline-header` — sticky, высота 56px (40px при прокрутке)
- Поиск `input.dev-header-search` справа от заголовка (где поддерживается)

### Изоляция localStorage
Префикс `kip8test:` для всех ключей. Реализован через обёртку `isolateLocalStorage()` (строка ~9874 в `index.html`), переопределяющую `localStorage.getItem/setItem/removeItem`.
**При переносе в kip8 — удалить блок `isolateLocalStorage()`.**

### Кэширование данных (ВАЖНО!)
- `data/*.json` — NetworkFirst с cache-busting `?v=timestamp` + `cache: 'no-store'`
- `localStorage` — только fallback для офлайна (`kip8test_phonebook_cache`, `kip8test_devices_cache` и т. п.)
- При каждом открытии раздела данные перезагружаются из сети
- Ручная очистка кэша не нужна

### Кросс-ссылки между разделами (фильтр по № проекта)
- Из карточки проекта можно перейти в список приборов/блокировок/клапанов/регуляторов/кабелей с фильтром по № проекта.
- Вверху отфильтрованного списка показывается бейдж фильтра с кнопкой ✕ для сброса.
- Фильтр сохраняется при переключении вкладок сортировки и при навигации на страницу группы (исправлено в v147–v148).

### Мульти-ссылки № проекта / № СБС / № САРиРУ
Если значение поля содержит несколько номеров (через `,` или `;`), каждый номер рендерится как отдельная кликабельная ссылка. Реализовано функцией `kipRenderMultiLinks()`.

### Адаптивный заголовок страницы (page-inline-header)
- При длинном тексте заголовка шрифт уменьшается, при ещё более длинном — высота header увеличивается (v150–v153).
- Шевроны `‹‹` компактные, поверх заголовка (overlay).

### Секретные кнопки
- `SECRET_BUTTON_IDS = ['minesweeperBtn', 'phonebookBtn']`
- Открытие: 2 тапа по заголовку приложения в течение 1.5 с
- При открытии одной — открываются все (toggle)

### Бейджи «Назначение кабеля» (7 классов, мёртвый код)
Цветовые классы `.cable-card-purpose-signal/control/jumper/power/manage/reserve/other` определены в CSS, функция `cablePurposeClass()` — в JS, но они **больше не используются** в карточках кабеля (после рефакторинга v174–v177). Список названий назначений: `signal` (сигнальный) · `control` (контрольный) · `jumper` (перемычка) · `power` (питание 220 В) · `manage` (управление) · `reserve` (резерв) · `other` (прочее). Все `sync-*.py` работают по одному шаблону:
1. Через Yandex Disk Public API (`cloud-api.yandex.net/v1/disk/public/resources`) получают `download_url` по публичной ссылке.
2. Скачивают XLSX напрямую во временную папку `/tmp/<name>_download/`.
3. Парсят лист через `openpyxl` (заголовки в 1-й строке, данные со 2-й, нормализация `strip`).
4. Сохраняют результат в `data/<name>.json` со структурой:
   ```json
   {
     "title": "...",
     "source": "<имя файла>",
     "sheet": "<имя листа>",
     "total_<name>s": N,
     "headers": [...],
     "<name>s": [...]
   }
   ```
5. Если интернета нет — используется уже существующий JSON как заглушка.

## Правила работы

### Перед началом работы
1. **Проверь `CACHE_VERSION`** в `sw.js` (должна быть `kipia-test-v178` или выше)
2. **Запусти тесты:** `cd kip8test && node tests/run-all.js` — ожидается `207 passed, 0 failed`
3. **Прочитай worklog** (если есть) — `/home/z/my-project/kip8test/worklog.md`

### При внесении изменений
1. **Не ломай тесты** — после каждого изменения запускай `node tests/run-all.js`
2. **Инкрементируй `CACHE_VERSION`** при изменении любых файлов приложения (HTML/CSS/JS/data). Формат: `kipia-test-v178` → `kipia-test-v179`
3. **НЕ удаляй блок `isolateLocalStorage()`**
4. **НЕ меняй пути в `manifest.json`** — `/kip8test/`
5. **НЕ включай cron** в workflow без явного разрешения пользователя
6. **Комментарии на русском языке**
7. **Соблюдай код-стайл** — vanilla JS, ES6+, mobile-first, без фреймворков
8. **При изменении `data/*.json`** — проверь `git ls-files data/*.json`. Если untracked — `git add`
9. **При добавлении нового раздела КИП ИОС** — следуй паттерну 7 функций (см. выше), добавь запись в `SUBSECTIONS`, инкрементируй кэш
10. **Все файлы выкладывать в `/home/z/my-project/download/`**

### ⚠️ ОБЯЗАТЕЛЬНО после изменений
1. **Таблицу файлов для скачивания** (см. правило в начале)
2. **Текущую версию кэша** (старую → новую)

### Перенос в kip8

| Файл | Действие |
|------|----------|
| `index.html` | Скопировать, **УДАЛИТЬ** блок `isolateLocalStorage()` |

| `images/` | Без изменений |
