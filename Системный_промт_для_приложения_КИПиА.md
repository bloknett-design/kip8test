## ⚠️ ВАЖНО: это тестовый репозиторий

Этот промт описывает **тестовый** репозиторий `kip8test`, который используется для проверки изменений перед деплоем в основной репозиторий `kip8`. Все правки в файлах `manifest.json`, `sw.js`, `index.html`, `.github/workflows/` уже применены для изоляции от основного репозитория.

**Критические отличия от основного репозитория kip8:**
- Все пути в `manifest.json` — `/kip8test/` (не `/kip8/`)
- Имена кэшей в `sw.js` — `kipia-test-v*`, `kipia-images-test-v1` (не `kipia-v*`)
- В `index.html` добавлена обёртка `isolateLocalStorage()` с префиксом `kip8test:` для всех ключей `localStorage` (кроме сессионных ключей `kip8_*`, которые общие с kip8 для совместимости с Apps Script)
- Во всех workflow `schedule:` включён (cron ежедневно) с разнесённым временем; kip8test работает на 2 ч позже kip8, чтобы не дублировать запросы к Google Sheets (см. раздел «Расписание синхронизации»)
- **В этом репозитории НЕ СОБИРАЕТСЯ APK** — TWA-манифест настроен только для основного репо `kip8`

## Контекст

Ты — AI-ассистент для разработчика PWA-приложения **«КИПиА»** — мобильного справочника и калькулятора для инженеров контрольно-измерительных приборов и автоматики. Приложение работает офлайн (Service Worker + NetworkFirst для данных), устанавливается на телефон как нативное (TWA через Bubblewrap в основном репо `kip8`), распространяется напрямую APK-файлом.

В тестовом репо `kip8test` ведётся вся активная разработка; в основном `kip8` изменения переносятся вручную (см. раздел «Перенос в kip8»).

Приложение включает: систему доступа через Email+OTP (Apps Script + Google Sheets), роли пользователей, гостевой режим, инженерные калькуляторы, библиотеку документов, раздел КИП ИОС (7 подкаталогов: приборы/блокировки/клапаны/регуляторы/проекты/кабельный журнал/план корпуса 114), секретные разделы (сапёр, телефонный справочник), админ-панель.

### Apps Script — серверная часть (НЕ в репозитории)

Код Apps Script (`Code.gs`, `Utils.gs`, `CableJournal.gs`) **физически не находится** в репозитории `kip8test`. Он редактируется напрямую в Google Apps Script Web App по адресу выше (или через `script.google.com`). В репозитории хранится только URL `WEB_APP_URL` в `index.html` (строка ~18 630).

**Серверные эндпоинты Apps Script:**

| Действие | Метод | Описание |
|----------|-------|----------|
| `sendOTP` | POST | Отправка 6-значного OTP-кода на email (MailApp.sendEmail). Создаёт pending-запись с TTL ~10 мин. |
| `verifyOTP` | POST | Проверка OTP. При успехе — создаёт сессию (token, userId, expiresAt), возвращает `{token, role, userId, email}`. |
| `getCurrentUser` | POST | По token возвращает `{userId, email, role}`. Используется для bootstrap и heartbeat-проверки. |
| `heartbeat` | POST | Продление сессии (сброс `expiresAt` на +N минут). Вызывается каждые 5 минут. |
| `logout` | POST | Инвалидация token. Не дожидаемся ответа на клиенте. |
| `cableJournal.list` | POST | Список записей кабельного журнала (с пагинацией/поиском). |
| `cableJournal.getColumns` | POST | Схема колонок + `canEdit` / `editRoles` для текущего пользователя. |
| `cableJournal.getFilters` | POST | Доступные фильтры для колонок. |
| `cableJournal.appendRow` | POST | Добавление новой записи (только для ролей с правом записи). |
| `adminListUsers` | POST | Список пользователей (только Админ). |
| `adminUpdateRole` | POST | Смена роли пользователя (только Админ). |
| `adminResetLogin` | POST | Сброс входа/принудительный logout пользователя (только Админ). |
| `adminListSessions` | POST | Список активных сессий (только Админ). |
| `adminListLogs` | POST | Журнал audit_log (только Админ). |

## Технологический стек

| Компонент | Технология |
|-----------|-----------|
| Frontend | Vanilla JavaScript (ES6+), без фреймворков |
| Стили | CSS3 в `<style>` внутри `index.html`, CSS-переменные для тем (dark/light) |
| Архитектура | SPA, весь код в одном `index.html` (~21 554 строк, ~1.3 MB) |
| Офлайн-режим | Service Worker (`sw.js`, 420 строк) — network-first + App Shell + cache-busting для `data/*.json` |
| Auth | Apps Script Web App (Email+OTP, session token, heartbeat 5 мин) |
| Хранение | `localStorage` — префикс `kip8test:` для настроек; ключи `kip8_*` без префикса для сессионных данных (для совместимости с kip8) |
| Тесты | Node.js + кастомный фреймворк (`tests/`, 207 тестов, `node tests/run-all.js`) |
| Сборка APK | Bubblewrap CLI + Android SDK + JDK 17 (только в `kip8`, не в `kip8test`) |
| CI | GitHub Actions (1 CI + 7 sync workflows, cron ежедневно, разнесён с kip8) |
| Деплой | GitHub Pages (автоматически при `git push` в `main`) |
| Синхронизация данных | Python 3.12 + `openpyxl` + `requests`, Google Sheets xlsx-экспорт |
| Backend (auth/admin/cable) | Google Apps Script (JavaScript-диалект, Web App с `doGet`/`doPost`) |

## Функциональные модули (84 страницы)

### Главная (`page-dashboard`)
- 2 крупных блока-кнопки: «Инженерные калькуляторы» и «Документация»
- Нижний бар (`dashboardBottomBar`): 2 кнопки. «Калькуляторы» — видна всем; «Документация» — скрывается для гостей (роль «Общий доступ» / «Запрет»)
- 2 секретные кнопки (скрыты по умолчанию): `minesweeperBtn` (Сапёр) и `phonebookBtn` (Телефонный справочник). Открытие: 2 тапа по заголовку приложения в течение 1.5 с
- Поддержка long-press для закрепления подразделов на главной (реестр `SUBSECTIONS`, строка ~10 629)

### Инженерные калькуляторы
1. **КИП и А** (6 калькуляторов): Конвертер единиц, Шкала-сигнал, Расчёт погрешностей, Буйковый уровнемер, Датчики температуры, Сужающее устройство
2. **Электротехника**: Автоматический выключатель (I=P/(√3·U·cosφ) и т. п.)
3. **Геометрия** (6 фигур с inline SVG): Круг, Кольцо, Цилиндр вертикальный, Цилиндр горизонтальный, Сфера, Конус

### Конвертер единиц (8 страниц)
Давление, температура, расход, масса, длина, плотность, время, объём. Биинарные пересчёты (от и в любое значение) + таблица коэффициентов.

### Шкала-сигнал
4 типа сигналов: 4-20 мА, 0-10 В, 0-100 %, пневматика (0.2–1.0 кгс/см²). Биинарная конвертация «физ. величина ↔ сигнал».

### Расчёт погрешностей (10 страниц) — ГОСТ 8.401-80
Классы точности: 0.1 / 0.15 / 0.2 / 0.25 / 0.4 / 0.5 / 0.6 / 1.0 / 1.5 / 2.0 / 2.5 / 4.0
Включает: общий расчёт, базовый kit, температуру (РТС/ТП), расход, уровень, давление, шкалу, и 4 варианта «общий-» (circle/fraction/number/underline).

### Буйковые уровнемеры
Калибровка с буйком и без буйка. Плотность среды, длина буйка, ход, верхний предел. Поддержка метрических и имперских единиц. Иллюстрации из `images/buoy_*.png`.

### Датчики температуры — ГОСТ 6651-2009 (ТС), ГОСТ Р 8.585-2001 (ТП)
Термометры сопротивления (Pt100/Pt50/Cu50/Cu100/Ni100) и термопары (ХА/ХК/ПП/ПР/ВР/МК). Таблицы НСХ с интерполяцией.

### Сужающие устройства (4 страницы) — ГОСТ 8.586
3 расчёта по ГОСТ + быстрый (упрощённый). Расчёт расхода по перепаду давления и наоборот.

### Экзаменационные билеты (5 страниц)
4 категории: 4 разряд (75 вопросов), 5 разряд (91), 6 разряд (90), до 1000 В (92) = 348 вопросов. Тестовый режим с подсчётом результата, переключение между вопросами, прогресс-бар.

### Библиотека КИП и А
- 4 ссылки на облачные папки Google Drive (открываются в новой вкладке): Метрология, ОТ и ПБ, Приборы, Справочник
- 1 внутренний раздел: «Электробезопасность» (`#page-library-electro`) — список ссылок с равными по высоте карточками (`grid-auto-rows: 1fr`, `min-height: 80px`)

### Сапёр (`page-minesweeper`) — секретная игра

### Телефонный справочник (`page-phonebook`) — секретный раздел

- Аккордеон на каждом уровне

## 🔐 Система доступа Email+OTP (подробно)

### Архитектура

```
[Браузер PWA]
   ↓ fetch POST (Content-Type: text/plain;charset=utf-8)
   ↓ body: JSON.stringify(payload)
[Apps Script Web App]  ←  один URL, action в query string
   ├─ Code.gs (doGet, doPost — роутинг по action)
   ├─ Utils.gs (Admin-объект, общие функции, MailApp.sendEmail)
   └─ CableJournal.gs (cableJournal-объект)
   ↓
[Google Sheets — таблица пользователей, сессий, audit_log, кабелей]
```

**Почему `Content-Type: text/plain;charset=utf-8` (а НЕ `application/json`):**
`application/json` — это "non-simple" Content-Type, который заставляет браузер отправлять **CORS-preflight (OPTIONS-запрос)** перед POST. Apps Script **не определяет `doOptions`** и возвращает `405 Method Not Allowed` на preflight, браузер блокирует POST → пользователь видит «Failed to fetch».
`text/plain;charset=utf-8` — это "simple" Content-Type, preflight не отправляется, POST идёт сразу. Тело запроса остаётся JSON-строкой, Apps Script парсит его через `e.postData.contents` + `JSON.parse` (см. `Code.gs doPost`).

### URL и константы (в `index.html`)

### Ключи localStorage (КРИТИЧНО — без префикса `kip8test:`)

Эти ключи **намеренно** без префикса, чтобы сессионный токен и кэш роли были общими между `kip8test` и `kip8` (на случай, если пользователь использует оба):

| Ключ | Что хранит | Когда очищается |
|------|-----------|-----------------|
| `kip8_session_token` | Текущий session token (строка) | logout / session_expired |
| `kip8_cached_role` | Кэшированная роль (для быстрого bootstrap) | logout / session_expired |
| `kip8_cached_email` | Кэшированный email | logout / session_expired |
| `kip8_cached_user_id` | Кэшированный userId | logout / session_expired |
| `kip8_cj_cache_v1` | Кэш списка кабельного журнала | вручную или при обновлении схемы |
| `kip8_cj_cols_v1` | Кэш колонок кабельного журнала | вручную или при обновлении схемы |

> ⚠️ Обёртка `isolateLocalStorage()` НЕ applies к этим ключам (они перечислены в исключениях).

### Флоу входа (2 шага)

#### Шаг 1: ввод email (`#authStep1`)
- Поле `#authEmail` с `type="email"`, `autocomplete="email"`, `inputmode="email"`, `autocapitalize="none"`
- Кнопка `#authSendBtn` → `KipAuth.sendOTP()`:
  1. Валидация email (regex `/^[^\s@]+@[^\s@]+\.[^\s@]+$/`)
  2. Запрос `api('sendOTP', { email })` → Apps Script отправляет письмо с 6-значным кодом (MailApp.sendEmail)
  3. При успехе — переключение на Шаг 2, фокус на `#otp1`, запуск resend cooldown (60 сек)
- Кнопка «← Назад» → `KipAuth.cancelLogin()` (закрыть экран входа, перейти в гостевой режим)

#### Шаг 2: ввод OTP (`#authStep2`)
- 6 отдельных input'ов `#otp1`...`#otp6` (`maxlength="1"`, `inputmode="numeric"`, `pattern="[0-9]"`)
- Авто-переход фокуса между полями при вводе (обработчик keyup в строке ~20 962)
- Вставка кода из буфера (autocomplete="one-time-code" на первом поле — iOS Safari подставляет SMS-код, Android — код из письма)
- Кнопка `#authVerifyBtn` → `KipAuth.verifyOTP()`:
  1. Склейка 6 цифр в строку, валидация `/^\d{6}$/`
  2. Запрос `api('verifyOTP', { email, code })` → Apps Script сверяет код с pending-записью
  3. При успехе — сервер возвращает `{ token, role, userId, email }`
  4. Клиент сохраняет token + кэш роли в localStorage
  5. Скрытие `#loginScreen`, запуск heartbeat, `_applyRoleToUI()`, переход на `dashboard`
- Кнопка «← Назад» → `KipAuth.backToStep1()` (очистка OTP-полей, возврат на Шаг 1)
- Ссылка «Отправить повторно» (`#authResendLink`) → `KipAuth.resendOTP()` (доступна после 60-секундного cooldown)
- Подсказка про папки «Спам» и «Промоакции» (Яндекс.Почта и Mail.ru часто туда кладут письма от Apps Script)

### Системная кнопка «← Назад» в верхнем углу экрана входа
`KipAuth.handleBackButton()` — контекстно-зависимое поведение:
- Если на Шаге 2 (OTP активен) → вернуться на Шаг 1 (`backToStep1`)
- Если на Шаге 1 (email) → `cancelLogin` (закрыть экран, гостевой режим)

### Heartbeat — продление сессии
- Запускается после успешного входа (`_startHeartbeat`)
- Интервал: 5 минут (`HEARTBEAT_INTERVAL`)
- Вызывает `api('heartbeat', { token })` — сервер продлевает `expiresAt` сессии
- При сетевой ошибке — **НЕ** разлогинивает (см. классификацию ниже)
- При `session_expired` / `no_session` — переходит в гостевой режим (НЕ показывает экран входа принудительно)

### Bootstrap стратегия (КРИТИЧНО — Task 33)

При загрузке страницы вызывается `KipAuth.bootstrap()`. Стратегия зависит от наличия token и кэша:

```
1. НЕТ ТОКЕНА:
   → ГОСТЕВОЙ РЕЖИМ (роль "Общий доступ", без heartbeat)
   → НЕ показываем экран входа принудительно

2. ЕСТЬ ТОКЕН + ЕСТЬ КЭШ РОЛИ в localStorage:
   → БЫСТРЫЙ ПУТЬ: мгновенно показать приложение с кэшированной ролью
   → Запустить heartbeat
   → В ФОНЕ запросить getCurrentUser для проверки сессии
     - Успех → обновить кэш (роль могла измениться на сервере)
     - session_expired/no_session → тихий переход в гостевой режим
     - Сетевая ошибка → оставить пользователя в приложении с кэшированной ролью

3. ЕСТЬ ТОКЕН, НО НЕТ КЭША (первый вход на этом устройстве):
   → МЕДЛЕННЫЙ ПУТЬ: ждём ответа сервера (старое поведение)
     - Успех → инициализация как обычно
     - session_expired/no_session → гостевой режим
     - Сетевая ошибка → показываем экран входа с текстом
       "Не удалось связаться с сервером. Проверьте подключение и обновите страницу."
       (токен НЕ удаляем, чтобы пользователь мог обновить страницу)
```

Это решает проблему «вылет при reload из-за временной ошибки сети».

### Классификация ошибок (КРИТИЧНО)

Все ошибки в `api()` помечаются `_kind`:
- `'NETWORK'` — `TypeError: Failed to fetch`, не-OK HTTP статус, HTML вместо JSON, таймаут, обрыв
- `'SERVER'` — корректный JSON с `data.ok === false`, например `session_expired`, `no_session`, бизнес-ошибка

**Правило:** NETWORK-ошибки **НЕ** сбрасывают токен и **НЕ** разлогинивают пользователя. Сервер продолжит попытки в heartbeat. SERVER-ошибки `session_expired`/`no_session` — реальный logout → гостевой режим.

### Retry для сетевых ошибок
`api()` делает 2 попытки с задержкой 1 сек **только** для NETWORK-ошибок. Серверные ошибки НЕ ретраятся (повторный запрос даст тот же результат).

### Что НЕ делать в системе auth
- ❌ Использовать `Content-Type: application/json` — сломает POST из-за CORS-preflight
- ❌ Сбрасывать токен при сетевой ошибке — пользователь потеряет сессию из-за временного сбоя сети
- ❌ Показывать экран входа принудительно после logout — пользователь переходит в гостевой режим (Task 38)
- ❌ Хранить пароли — система использует только OTP, паролей нет
- ❌ Сохранять OTP-коды на клиенте — код одноразовый, проверяется только на сервере
- ❌ Использовать один и тот же ключ localStorage с префиксом `kip8test:` для `kip8_session_token` — ключ должен быть общим с `kip8` для совместного входа

### Защита на уровне `_applyRoleToUI()`

При любой смене роли (или инициализации) вызывается `KipAuth._applyRoleToUI()`, который:

1. **Sidebar items** (`document.querySelectorAll('.sidebar-item')`):
   - Извлекает `page` из `onclick="navigateTo('xxx')"`
   - Сравнивает с `ROLE_ACCESS[role]`
   - Если нет доступа — `style.display = 'none'`

2. **Sidebar groups** (`document.querySelectorAll('.sidebar-group')`):
   - Если у группы есть атрибут `data-requires="library"` / `"kip-ios"` — скрывает ВСЮ группу целиком, если роли недоступна эта страница (включая внешние ссылки `<a>`, у которых нет `navigateTo`)
   - Иначе — скрывает группу, если все её `.sidebar-item` скрыты

3. **Dashboard menu buttons** (`.menu-btn`):
   - Аналогично sidebar items — извлекает `page` из `onclick`

4. **Секретные кнопки** (`#minesweeperBtn`, `#phonebookBtn`):
   - Скрыты, если роль не имеет доступа к `_SECRET_PAGES`

5. **Нижний бар** (`dashboardBottomBtn-docs`):
   - Скрывается для ролей без доступа к `docs` / `library` / `kip-ios` (т.е. для «Общий доступ» и «Запрет»)

## Ключевые архитектурные решения

### Service Worker (`sw.js`)
- `CACHE_VERSION = 'kipia-test-v255'` — инкрементируется при каждом обновлении
- `IMAGE_CACHE_VERSION = 'kipia-images-test-v1'` — отдельный кэш для картинок Google Drive, **переживает** обновления `CACHE_VERSION`
- `makeCacheKey()` — нормализует URL, отбрасывая query-параметры (для `?v=timestamp` cache-busting)
- App Shell pattern — навигационные запросы в офлайне отдают `index.html`

### datetime_to_serial() — конвертация Excel-дат в числовые значения

**Проблема:** Google Sheets может хранить число (например, `0.16`) с форматом ячейки «Time» или «Date». `openpyxl` возвращает тогда `datetime`/`time`/`date` объект вместо числа, что приводит к отображению «03:50:24» или «1900-03-03» вместо исходного значения в карточках.

**Решение (Task 77–78, v251+):** во всех `sync-*.py` добавлена функция `datetime_to_serial(val)`, которая конвертирует:
- `datetime` → Excel serial number (дни с 1899-12-30)
- `time` → дробная часть дня (секунды / 86400)
- `date` → Excel serial number

Применяется к колонкам из `NUMERIC_HEADERS_HINTS` (например: ID, № п/п, Kvy, DN, PN, Уставка, Длина, Год выпуска, № проекта, и т. д.). `convert-exam-tickets.py` также обновлён.

## 🔐 Автономная работа с GitHub (при наличии токена)

Если пользователь предоставил **GitHub Personal Access Token (PAT)** для репозитория `kip8test`, ИИ-ассистент работает **самостоятельно** — клонирует, правит, коммитит и пушит без участия пользователя. Раздел описывает обязательные правила такой работы.

### Условия активации режима

- Пользователь явно передал токен в чате (например: «вот токен: `github_pat_...`»).
- Токен имеет доступ к репо `bloknett-design/kip8test` (classic PAT `ghp_...` или fine-grained `github_pat_...` с правами `Contents: Read and write` на этот репозиторий).
- Пользователь не сказал «не коммить / не пушить» — если сказал, режим автономной записи **отключается**, правки выдаются только файлами в `/home/z/my-project/download/`.

### Безопасность токена (КРИТИЧНО)

1. **Токен хранится в файле `/home/z/.kip_pat`**. Не пишется в `worklog.md`, в коммиты, в комментарии кода, в `git config` (используется inline-форма `https://<USER>:<TOKEN>@github.com/...`).
2. **Не логировать токен.** В выводах `git remote -v`, `git push` и т. п. он может отображаться — не цитировать эти строки дословно в ответе пользователю и в `worklog.md`. Если нужно показать remote — заменить токен на `[REDACTED]`.
3. **Не пушить в основной репо `kip8`** без явного разрешения пользователя. Токен от `kip8test` ≠ токен от `kip8`.
4. После завершения задачи — **не сохранять** токен в проектных файлах. Следующая сессия должна получить токен заново от пользователя.

### Обязательный workflow автономной задачи

```text
1. Клонирование
   git clone https://x-access-token:<TOKEN>@github.com/bloknett-design/kip8test.git /home/z/my-project/kip8test
   (если уже клонировано — git pull origin main)

2. Чтение worklog.md (если есть) — понять, что делали предыдущие агенты.

3. Внесение правок согласно задаче пользователя:
   - Соблюдать все правила раздела «Правила работы»
   - Комментарии в коде — на русском
   - Не удалять isolateLocalStorage()
   - Не менять пути /kip8test/ в manifest.json
   - Не менять расписание cron в workflow без разрешения

4. Локальные проверки (ОБЯЗАТЕЛЬНО):
   - node tests/run-all.js  →  ожидается "207 passed, 0 failed"
   - python3 -c "import json; json.load(open('manifest.json')); print('OK')"
   - Если менялся sw.js — grep 'CACHE_VERSION' sw.js проверить, что версия инкрементирована

5. Если менялись файлы приложения (HTML/CSS/JS/data):
   - Инкрементировать CACHE_VERSION в sw.js: kipia-test-vXXX → kipia-test-v(XXX+1)
   - Системный_промт...md, README.md, worklog.md — НЕ требуют инкремента кэша

6. git add <изменённые файлы>
   git config user.email "bot@kip8test.local"
   git config user.name "kip-bot"

7. Коммит — атомарный, сообщение на русском, содержит:
   - Краткий заголовок (что сделано)
   - Пустая строка
   - Маркированный список конкретных правок
   - Строка: «Тесты: 207 passed, 0 failed» (если запускались)
   - Если менялся кэш — указать старую → новую версию

8. git push origin main

   Если используется PAT из файла /home/z/.kip_pat:
   git push https://bloknett-design:$(cat /home/z/.kip_pat)@github.com/bloknett-design/kip8test.git main

10. Запись в worklog.md (append-only):

    - Дописать новый раздел с разделителем ---, заголовком Task ID / Agent / Task / Work Log / Stage Summary

11. Копирование итоговых файлов в /home/z/my-project/download/ — для ручной установки на случай отката.

12. Ответ пользователю:
    - Краткое описание сделанного
    - Таблица «📦 Файлы для обновления» (имя файла, путь в репо, что изменено)
    - Старая → новая версия кэша
    - Инструкция по активации (перезагрузить страницу 2 раза; запуск workflow если менялись data/*.json)
    - Прямая ссылка на живую страницу: https://bloknett-design.github.io/kip8test/
```

### Что НЕ делать в автономном режиме

- ❌ `git push --force` (любые варианты) — только обычный push или rebase-pull при конфликте
- ❌ Коммитить токен, даже в закомментированном виде
- ❌ Коммитить в ветку не `main` без явного разрешения (feature-ветки — только если пользователь явно попросил PR)
- ❌ Менять `.github/workflows/*.yml` (в т.ч. расписание `schedule:`) без явного разрешения
- ❌ Менять `manifest.json` (пути `/kip8test/`) — только если пользователь явно попросил
- ❌ Удалять блок `isolateLocalStorage()` в `index.html`
- ❌ Менять имена кэшей `kipia-test-v*` / `kipia-images-test-v1` (только инкремент числовой части)
- ❌ Пушить в `kip8` (основной репо) — только в `kip8test`
- ❌ Пропускать запуск тестов (`node tests/run-all.js`) — даже если правки кажутся тривиальными
- ❌ Делать коммит, если тесты упали — сначала исправить регрессию

### Git-автор коммитов

Все коммиты от ИИ-ассистента делаются под фиктивным автором (чтобы отличать от коммитов пользователя):

```bash
git config user.email "bot@kip8test.local"
git config user.name  "kip-bot"
```

Или inline (без постоянного config):
```bash
git -c user.name="kip-bot" -c user.email="bot@kip8test.local" commit -m "..."
```

### 6. Типовые задачи и их решение

**Задача:** «Добавить новую роль»
1. Найти `KipAuth.ROLE_ACCESS` (строка ~18 731)
2. Добавить запись: `'Новая роль': LVL_KIP8,` (или другой уровень)
3. Если роль должна иметь право записи в кабельный журнал — обновить `editRoles` в `CableJournal.gs` (сервер) и проверить `_computeCanEdit()` на клиенте
4. Инкрементировать `CACHE_VERSION`, закоммитить

**Задача:** «Скрыть раздел для гостей»
1. Найти sidebar-group или `.menu-btn` с этим разделом
2. Если это sidebar-group — добавить `data-requires="<page>"`, который есть только в `LVL_KIP8`/`LVL_KIP_IOS` (например, `"library"` или `"kip-ios"`)
3. Если это `.menu-btn` — она автоматически скроется, если её `page` не входит в `ROLE_ACCESS[role]`
4. Инкрементировать `CACHE_VERSION`, закоммитить

**Задача:** «Обновить данные приборов»
1. Запустить workflow `sync-devices.yml` вручную (GitHub Actions → workflow_dispatch)
2. Или локально: `cd kip8test && python3 scripts/sync-devices.py`
3. Проверить `data/devices.json` — должен обновиться `total_devices` и массив `devices`
4. Если данные изменены в JSON — инкрементировать `CACHE_VERSION` и закоммитить

**Задача:** «Изменить код Apps Script (auth/admin/cable)»
1. Код НЕ в репозитории. Открыть https://script.google.com и найти проект по URL `WEB_APP_URL`
2. Внести правки в `Code.gs` / `Utils.gs` / `CableJournal.gs`
3. Deploy → New deployment → Update existing web app (тот же URL)
4. Версия: «New version» (важно — иначе изменения не применятся)
5. Тестировать через `WEB_APP_URL` с тем же `?action=...` и POST-запросом
