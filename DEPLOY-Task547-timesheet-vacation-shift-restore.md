# DEPLOY — Task 547: Табель учёта — смена периода отпуска (шахматка рабочих дней + подмены)

**Дата:** 2026-10-26
**Заявка:** «В разделе табель учёта, при изменении периода отпуска сменного
работника на несколько дней, шахматка его рабочих дней после первого
формирования данных шахматки на этот месяц остаётся пустой и заполняется
после повторного нажатия на кнопку формирования шахматки. Ранее подменные
дни распределённые другим сменным работникам остаются, хотя у отпускного
работника возвращаются его рабочие смены и отпуск смещается.»

## Корень (два дефекта, один триггер — смещение периода отпуска)

1. **СЕРВЕР** (`WorkSchedule.gs`, `generateMonth`): генерация читала записи
   ДО расчёта — на днях прежнего отпуска стояли авто-«ОТ»; шаг 3 видел
   «запись уже есть» и НЕ вставлял смену, сверка устаревших «ОТ» УДАЛЯЛА
   строку → ячейки рабочих дней ПУСТЕЛИ до ПОВТОРНОГО «Сформировать».
2. **Подмены**: авто-«д»/«н» замещения отпуска (Task 456/458) сохранены
   записями «руч» с ПУСТЫМ «замещает»; отпуск сместился — спрос дня исчез,
   записи остались (двойная расстановка: отпускник работает И подмена стоит).

## Что менялось

### 1. СЕРВЕР — `scripts/WorkSchedule.gs` (generateMonth)

| Изменение | Реализация |
|-----------|-----------|
| Рестор смен из-под «ОТ» | Сверка устаревших авто-«ОТ»: день со **плановой сменой** → смена **ВОССТАНОВИНА на месте** (`toUpdate`, как 4.6 для мероприятий); день без смены → удаление (как прежде). **Одно «Сформировать» сходится к актуальному плану.** Связка с мероприятием (бейдж, Task 303) сохраняется: `инструкция = coveredTr[id]` |
| Шаг 4.8 — устаревшие замещения | Ручные записи с `«замещает»=X`, где X работает СВОЮ плановую смену этого дня (отпуск сместился/удалился) — строка под удаление. Записи БЕЗ «замещает» серверу неотличимы от ручного ввода — **не трогаются** (их снимает клиентский свип); X отсутствует (ОТ/«Б»/мероприятие) / X без шаблона / таб X не из справочника — замещение живо |
| Счётчики | Ответ: `vacationRestored`, `substitutionsRemoved`; аудит-сводка: «возвращено смен из-под отпусков N», «снято устаревших замещений M» |

### 2. КЛИЕНТ — `index.html`

| Изменение | Реализация |
|-----------|-----------|
| `_autoDnStaleSweep()` | Свип устаревших авто-«д»/«н» по **реестру месяца** Task 458 (`ws_auto_dn_keys`, localStorage). Спрос дня = как `need` плана: отпускник (эффективная запись семейства отпусков ИЛИ план листа «Отпуска») со плановой сменой «Д»/«Н» этого типа. Спрос исчез → серверная запись «руч» под `__delete` + `__autoStale` («Сохранить» удалит, «Отменить» вернёт); несохранённая материализация (правка с `__autoDn`) снимается с меткой; спрос вернулся → свип-удаление откатывается. Статус ячейки — ПО СЕРВЕРУ (под `__delete` эффективное состояние пусто, запись жива) |
| Неприкосновенность | Правки пользователя поверх слоя (любой код, не удаление), пользовательское `__delete`, ручные «д»/«н» ВНЕ реестра — свип НЕ трогает. Явные замещения с «замещает» снимает сервер 4.8 |
| Интеграция | `_renderGrid`: свип между восстановлением реестра и материализацией нового плана (свободные ячейки план займёт заново) + тост «Авто: снято N устаревших «д»/«н» (замещение отпуска) — нажмите «Сохранить»» |
| Тосты «Сформировать» | Месяц: «возвращено смен из отпусков N», «снято замещений M»; год: суммы за 12 месяцев |
| Материализация | `_autoDnMaterialize` маркирует свои правки флагом `__autoDn` — свип отличает свою правку от пользовательской; `saveAll` поле не отправляет |

## Деплой

### КЛИЕНТ (kip8test — Pages; kip8 — Pages/Build)

Ничего вручную: push в репозиторий — CI разворачивает. Пользователям после
выката — **Ctrl+Shift+R** (SW v758 подхватится сам при следующем открытии;
без жёсткого обновления — при первом обновлении после активации новой
версии Service Worker).

### СЕРВЕР (Apps Script, проект AKfycbyt… — тот же, что Task 534/536/546)

`WorkSchedule.gs` МЕНЯЛСЯ — без редеплоя серверные части фикса не работают:

1. Открыть проект Apps Script (script.google.com) → заменить содержимое
   файла `WorkSchedule.gs` на `scripts/WorkSchedule.gs` из репозитория
   (изменения — только внутри `generateMonth` + комментарии).
2. **New version → Deploy** (тот же deployment, Web App).
3. Проверка (шахматка любого месяца, где есть отпуск):
   - сменить период отпуска сменного работника на несколько дней;
   - «Сформировать» → «Текущий месяц» (ОДНО нажатие);
   - тост содержит «возвращено смен из отпусков N» — дни, освобождённые от
     отпуска, показывают СМЕНЫ (Д/Н), а не пустые ячейки;
   - ячейки с явным «замещает»=отпускник на вернувшихся сменах — записи
     сняты сервером (тост «снято замещений M»);
   - авто-«д»/«н» подмены (замещает пусто) — ячейки ПУСТЫЕ сразу после
     генерации (клиентский свип запланировал удаление) → «Сохранить» →
     записи удалены на сервере.

**Без серверного деплоя:** клиентский свип подмен и тосты работают уже от
SW v758 (спрос считается по фактическим данным), но строка отпускника
заполнится только ПОВТОРНЫМ «Сформировать» (старый сервер удаляет «ОТ» без
рестора) — см. DEPLOY шаги выше.

### Откат

- Клиент: revert коммита + бамп SW (v758 → v759); SW-кэш самоочистится.
- Сервер: вернуть прежний `WorkSchedule.gs` в редакторе → New version →
  Deploy. Данные не мигрировали (правки — только логика генерации;
  «Сформировать» повторением сходится к любому состоянию листа «Отпуска»).
