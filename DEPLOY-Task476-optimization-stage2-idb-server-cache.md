# DEPLOY — Task 476: Этап 2 оптимизации — IndexedDB-кэш серверных данных

**Тип: КЛИЕНТ-ONLY (серверных шагов НЕТ).**

Заявка (продолжение этапа 1): «ранее подгруженные данные должны
сохраняться в памяти устройства для моментального доступа к ним» —
для СЕРВЕРНЫХ данных (Apps Script), которые Service Worker не
кэширует (bypass: авторизация/heartbeat всегда в сеть).

## Состав изменений

### index.html

1. **KipDB — новый модуль** (глобальный `var KipDB`, отдельный
   `<script>`): мини-обёртка IndexedDB (БД `kip8-cache-test-v1`,
   store `kv`, промисы get/set/del/keys/clear, тихие ошибки).
   Надёжный ёмкий слой локальных копий серверных данных — квота
   localStorage (~5 МБ, синхронный) больше не может ТИХО потерять
   копии разделов.

2. **WorkSchedule (табель, Task 314)**:
   - `_cacheWrite` пишет копию в ОБА слоя — KipDB + localStorage
     (прежний синхронный слой сохранён);
   - разбор объекта кэша вынесен в `_restoreFromObj` (общий для
     обоих слоёв, формат v1 не менялся);
   - `_idbRestoreView` — асинхронный добор из KipDB ДО похода в
     сеть (промах localStorage: квота/чистка) + миграция старой
     localStorage-копии в KipDB (одноразово, сама собой);
   - `init` и `loadGrid` зовут KipDB-ветку до сетевого пути;
     `force` («Обновить») кэш не читает — только сеть, как прежде.

3. **KipCableJournal (кабельный журнал)**: `_persistData` /
   `_persistColumns` — оба слоя (единый снапшот, одинаковое ts);
   `_idbRestore` — промах localStorage → KipDB (колонки + строки,
   рендер, затем фоновое обновление как обычно) + миграция.

4. **FlowmeterData (расходомеры)**: `_persistData` — оба слоя;
   `_idbRestore(silent)` по образцу `_restoreCache` + миграция.

5. **PlanEventsData (плановые мероприятия)**: локальная копия
   отметок **ВПЕРВЫЕ** — `_marksCacheKey 'kip8_pe_marks_v1'`,
   формат `{v:1, years:{'2026':{marks, ts}}}`;
   `_cacheMarks` после успешного `planEvents.list`;
   `_restoreMarksCache` ДО сетевого `loadMarks` (init) — раздел
   открывается с галочками/крестиками мгновенно при любой связи.

6. **KipAuth**:
   - `_requestPersistentStorage` — `navigator.storage.persist()`
     после входа (5 точек: verifyOTP, bootstrap быстрый/медленный,
     офлайн-повтор, фоновая проверка сессии); идемпотентно, отказ
     браузера — не ошибка;
   - `_wipeLocalServerData` при **logout** (ручной выход):
     LS-ключи копий (`kip8_ws_cache_v1`, `kip8_cj_cache_v1`,
     `kip8_cj_cols_v1`, `kip8_flow_cache_v1`) + KipDB.clear()
     целиком. Автоистечение сессии (handleSessionExpired) НЕ чистит
     — тот же пользователь вернётся после повторного входа.
     Статические публичные data/*.json (SW DATA-кэш) и настройки
     интерфейса (тема/закреплённые/избранное) НЕ трогаются.

## Поведение пользователя (что изменится)

- Табель/каб. журнал/расходомеры/отметки мероприятий открываются
  мгновенно при любой связи — даже если localStorage-копия не
  влезла в квоту (KipDB-слой надёжнее и ёмче).
- Отметки «Плановых мероприятий» переживают офлайн ВПЕРВЫЕ
  (раньше раздел без сети показывал только крестики-заглушку).
- Кнопка «Обновить» в разделах по-прежнему тянет ТОЛЬКО сеть.
- После ручного выхода (logout) локальные копии серверных данных
  стираются с устройства (граница приватности). Сессия, истёкшая
  сама, копии НЕ стирает.
- Браузеру отправляется запрос storage.persist() (закрепить
  хранилище от автоочистки) — тихо, без интерфейса.

## Откат

Вернуть `index.html`, `sw.js`, `tests/` из коммита, предшествующего
Task 476, и поднять CACHE_VERSION (клиент перекэширует App Shell).

безвредны (старый код их не читает); чистятся logout'ом или вручную
(DevTools → Application → IndexedDB).
