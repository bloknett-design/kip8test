# Task 413 — записи раздела инструктажей не добавлялись: автосоздание таблицы «Инструктажи» + архив записей

**Заявка:** «При добавлении инструктажа или проверки знаний в форме ввода в
приложении, они не добавляются, ещё я удалил таблицу Инструктажи в файле
табель_КИП_ИОС, когда мы начали заново работать над разделом проведения
инструктажей и проверки знаний. Где должны сохраняться вновь создаваемые записи
в этом разделе? Что нужно сделать чтобы был их архив?».

## Где сохраняются записи (ответ на вопрос заявки)

Все новые записи раздела «Инструктажи и проверка знаний» сохраняются в лист
**«Инструктажи»** файла табель_КИП_ИОС (столбцы A..H):

| Столбец | Поле | Примечание |
|---|---|---|
| A | id | сквозная нумерация (общая с листом «Мероприятия») |
| B | таб_номер | FK на «Сотрудники», текст (ведущие нули не теряются) |
| C | тип | инструктаж / проверка_знаний |
| D | тема | название пункта «Список_И_и_ПЗ» |
| E | дата_начала | Date |
| F | дата_окончания | Date (для И/ПЗ = дате проведения — однодневные) |
| G | длительность_дней | int (для И/ПЗ всегда 1) |
| H | комментарий | до 500 символов |

Мероприятия (обучение/прогул/примечание) живут в отдельном листе
«Мероприятия» (Task 405).

## Диагноз

Лист «Инструктажи» был удалён пользователем из файла вручную. Серверный
`addTraining` писал записи в этот лист и при его отсутствии возвращал
`sheet_not_found: Инструктажи` — форма показывала «Ошибка: sheet_not_found:
Инструктажи», записи не сохранялись. Для листа «Мероприятия» автосоздание уже
было (Task 405, `_ensureEventsSheet`), для «Инструктажей» — не было. Дополнительно
`listTrainings` при отсутствии листа падал ошибкой — вся загрузка сетки шла с
экраном/тостом ошибки.

## Что сделано

### Сервер (WorkSchedule.gs) — ⚠ требует обновления в Apps Script

- **`_ensureTrainingsSheet`** (новый, зеркально `_ensureEventsSheet` Task 405):
  создаёт лист «Инструктажи» с каноническими заголовками A..H, стилями шапки
  (жирный текст, фон #1F4E5F, закреплённая строка 1) и записью аудита
  WORKSCHEDULE_TRAININGS_SHEET_CREATED. Защита от гонки одновременных
  добавлений: `insertSheet` бросил исключение, но лист уже создан другим
  вызовом — берётся существующий.
- **`addTraining`**: при отсутствии ЛЮБОГО листа («Инструктажи» или
  «Мероприятия») вызывает соответствующий ensure. **Архив записей
  восстанавливается первым же добавлением**: заголовки + первая строка данных.
- **`listTrainings`**: мягкая деградация без листа «Инструктажи» — ok:true,
  trainings/instrAll — пустые срезы, «Мероприятия» (eventsAll) и
  «Список_И_и_ПЗ» (instrList) читаются независимо. Загрузка сетки больше не
  падает.
- Док-блоки шапки и структуры листа обновлены.

### Клиент (index.html) — защита до обновления Apps Script

- **`_apiErrText`**: код `sheet_not_found: X` показывается понятным текстом —
  «таблица «X» отсутствует в файле табель_КИП_ИОС — обновите WorkSchedule.gs в
  Apps Script: она будет создана автоматически при первом добавлении записи».
- Тосты/экран ошибки `submitTrainingForm` (новая запись), `_doDeleteTraining`,
  `loadGrid` — через `_apiErrText` (раньше сырой `err.message`).

## ⚠ Серверный шаг пользователя (обязателен для сохранения записей)

1. Открыть Apps Script проекта табель_КИП_ИОС → заменить содержимое
   WorkSchedule.gs на версию из репо (файл scripts/WorkSchedule.gs, коммит
   aeec428).
2. **Создать новое развёртывание** (Deploy → Manage deployments → Edit →
   New version / New deployment) — без этого Apps Script продолжает отдавать
   старый код.
3. Готово: при первом добавлении инструктажа/проверки знаний лист
   «Инструктажи» создастся автоматически с заголовками; все последующие
   записи будут накапливаться там. Годовые архивы в карточках (Task 408) читают
   именно этот лист.
4. Шаги Task 409 (instrListInit) остаются актуальными для наполнения
   «Список_И_и_ПЗ» живыми данными — до этого клиент работает на встроенном
   эталоне (Task 412).

## Что проверять после серверного шага

- В файле табель_КИП_ИОС после первого добавления появляется лист
  «Инструктажи» с шапкой id/таб_номер/тип/тема/дата_начала/дата_окончания/
  длительность_дней/комментарий и первой записью.
- Записи отображаются в карточке работника (группы канона), бейджах И/ПЗ
  шахматки, годовых архивах ‹год›.
